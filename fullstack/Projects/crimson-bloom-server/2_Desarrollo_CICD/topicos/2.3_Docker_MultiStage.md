# Tópico 2.3: Compilaciones Docker Multi-stage y Hardening de Imágenes

## 🎯 Objetivo de Aprendizaje
Escribir archivos de empaquetado `Dockerfile` altamente optimizados empleando compilaciones multi-fase y robustecer la seguridad interna restringiendo privilegios de ejecución.

## 📋 Checklist de Conceptos a Dominar
- [ ] ¿Por qué una imagen final de producción no debe contener herramientas como `git`, `npm`, o compiladores de lenguaje?
- [ ] Explicar la mecánica de funcionamiento de las fases `builder` y `runtime` en un `Dockerfile`.
- [ ] Conocer las ventajas en tamaño y seguridad de las imágenes base Alpine y Distroless de Google.
- [ ] Entender las vulnerabilidades de ejecutar procesos internos de contenedores bajo privilegios `root` del host Debian.
- [ ] Conocer cómo caching de capas (Layers Cache) en Docker acelera los tiempos de compilación de imágenes.

## 📚 Conceptos Mínimos a Estudiar
*   **Capas de Docker e Inmutabilidad:** Cada instrucción en un `Dockerfile` (`RUN`, `COPY`, `ADD`) genera una capa de solo lectura. Ordenar las instrucciones de las dependencias que cambian poco (ej: `package.json` o `go.mod`) antes que el código fuente optimiza la reutilización de caché.
*   **Docker Multi-stage Builds:** Técnica que utiliza múltiples directivas `FROM`. La primera fase compila y genera los artefactos binarios usando imágenes pesadas. La segunda fase usa una base limpia y copia solo los binarios compilados de la fase anterior, descartando el resto.
*   **Hardening No-root:** Por defecto, los procesos dentro de Docker corren como `root` (UID 0), lo que permite a atacantes que exploten un desbordamiento de búfer del contenedor acceder al kernel del host como root. Configurar un usuario sin privilegios (`USER appuser` en UID > 10000) detiene esto de raíz.

## 🔍 Comandos de Diagnóstico Útiles
*   `docker build -t test-image .`: Compila la imagen local a partir del Dockerfile del directorio actual.
*   `docker images`: Muestra una lista de todas las imágenes locales detallando su tamaño físico.
*   `docker run -it --entrypoint sh <image_id>`: Permite inspeccionar el sistema de archivos interno de la imagen final para verificar que no queden rastros del código fuente o herramientas de build.
*   `docker exec -it <container_name> whoami`: Comprueba el nombre del usuario bajo el que se ejecuta el proceso del contenedor.
