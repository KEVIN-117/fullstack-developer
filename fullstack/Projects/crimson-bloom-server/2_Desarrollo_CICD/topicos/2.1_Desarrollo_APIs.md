# Tópico 2.1: Desarrollo de APIs REST (Go o NestJS)

## 🎯 Objetivo de Aprendizaje
Desarrollar una API RESTful funcional, robusta y concurrente (en Go o NestJS) siguiendo principios limpios de desacoplamiento de capas y buenas prácticas de respuestas HTTP.

## 📋 Checklist de Conceptos a Dominar
- [ ] Explicar cómo funciona el modelo de concurrencia CSP (Communicating Sequential Processes) de Go (Goroutines y Channels) o el Event Loop asíncrono de Node.js.
- [ ] Conocer las diferencias entre verbos HTTP (GET, POST, PUT, DELETE) y la semántica de códigos de respuesta (2xx, 3xx, 4xx, 5xx).
- [ ] Estructura limpia de proyectos: Diferencia entre Controladores (entrada/salida HTTP) y Servicios (lógica de negocio).
- [ ] ¿Qué es y para qué sirve un endpoint de salud (`/health`) en entornos contenerizados?
- [ ] Entender el uso de Middlewares para el manejo global de errores y CORS.

## 📚 Conceptos Mínimos a Estudiar
*   **Concurrencia en Go (Goroutines/Channels):** Las Goroutines son hilos ligeros multiplexados en un número menor de hilos del sistema operativo. Los canales (`channels`) proveen una forma segura para que las Goroutines compartan datos y eviten condiciones de carrera de memoria (Race Conditions).
*   **NestJS (Dependency Injection / Modules):** Entender cómo opera la inyección de dependencias (DI) para desacoplar clases, y cómo modularizar la API utilizando decoradores `@Module`, `@Controller`, y `@Injectable`.
*   **Semántica HTTP:**
    *   `200 OK` (Petición exitosa), `201 Created` (Elemento creado con éxito).
    *   `400 Bad Request` (Entrada inválida), `401 Unauthorized` (Falta autenticación), `403 Forbidden` (Acceso denegado).
    *   `404 Not Found` (Recurso inexistente).
    *   `500 Internal Server Error` (Fallo no controlado en backend).

## 🚀 Actividades Prácticas Realizadas
1. Inicializado el proyecto en la carpeta `/src/backend`.
2. Programada la estructura básica con un router HTTP.
3. Creado el endpoint `/health` que devuelva el estado del servidor.
4. Desarrollada una estructura de datos en memoria para servir información estructurada en el endpoint `/api/data`.
5. Escritas pruebas unitarias para validar las respuestas del controlador.

## 🔍 Comandos de Diagnóstico Útiles
*   `go run main.go` o `npm run start:dev`: Arranca el servidor backend en caliente para desarrollo local.
*   `go test ./...` o `npm run test`: Ejecuta la suite de pruebas unitarias configurada en el proyecto.
*   `curl -iv http://localhost:3000/health`: Realiza un chequeo rápido del estado de salud del backend local.
