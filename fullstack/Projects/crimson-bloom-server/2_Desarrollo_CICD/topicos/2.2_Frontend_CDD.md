# Tópico 2.2: Frontend Modular con CDD (React + Vite)

## 🎯 Objetivo de Aprendizaje
Construir una SPA (Single Page Application) modular y dinámica empleando el enfoque Component Driven Development (CDD) con React y Vite.

## 📋 Checklist de Conceptos a Dominar
- [ ] Comprender qué es Component Driven Development (CDD) y cómo facilita el desarrollo Bottom-Up.
- [ ] Explicar la diferencia de flujo entre "Smart Components" (manejo de estado/llamadas API) y "Dumb Components" (puramente visuales).
- [ ] Conocer las ventajas de usar CSS Modules o Styled Components para aislar estilos en la UI.
- [ ] ¿Cómo gestionar variables de entorno en Vite (`import.meta.env`) para cambiar la URL del backend según el entorno?
- [ ] Entender el concepto de diseño de UI atómico (Atomic Design: Átomos, Moléculas, Organismos).

## 📚 Conceptos Mínimos a Estudiar
*   **Component Driven Development (CDD):** Metodología que ancla el desarrollo de interfaces en la creación de componentes visuales individuales, desacoplados y probados de manera independiente.
*   **Aislamiento de Estilos (CSS Modules):** Genera nombres de clases CSS dinámicos únicos al compilar para evitar el acoplamiento global y colisiones de clases en el DOM (ej. `.table_container` se convierte en `.table_container__aB8d`).
*   **Componentes Contenedores vs Presentacionales:**
    *   *Smart (Contenedores):* Tienen estado, interactúan con almacenes de datos (Context, Redux) y realizan llamadas `fetch`/`axios` de red.
    *   *Dumb (Presentación):* No tienen lógica de red. Reciben datos y funciones por `props` y los muestran visualmente. Son altamente reutilizables.

## 🚀 Actividades Prácticas Realizadas
1. Inicializada la aplicación React en `/src/frontend` utilizando el andamiaje rápido de Vite.
2. Creados componentes puros (como la tabla de transacciones `TransactionTable`) aislados de llamadas de red.
3. Consumidos los datos de la API backend de forma segura mediante un cliente HTTP (`fetch` o `axios`) en el componente principal.
4. Diseñados los componentes bajo la metodología BEM o usando CSS Modules para evitar colisiones de estilos.

## 🔍 Comandos de Diagnóstico Útiles
*   `npm run dev`: Inicializa el servidor de desarrollo local de Vite de respuesta rápida con recarga en caliente (HMR).
*   `npm run build`: Compila y minifica el proyecto generando los archivos finales listos para producción en la carpeta `/dist`.
*   `npm run preview`: Sirve localmente los archivos compilados de `/dist` para comprobar el resultado final antes de subir a producción.
