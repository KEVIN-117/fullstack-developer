# Tópico 5.1: Recolección y Almacenamiento de Métricas (Prometheus)

## 🎯 Objetivo de Aprendizaje
Configurar Prometheus para el almacenamiento de series temporales de telemetría y desplegar agentes para capturar el rendimiento del hardware y de los contenedores Docker en ejecución.

## 📋 Checklist de Conceptos a Dominar
- [ ] Entender el modelo de base de datos de series temporales (TSDB) de Prometheus.
- [ ] Explicar el modelo de recolección de métricas por extracción (Scraping/Pull) y su diferencia con el modelo push.
- [ ] Conocer las funciones de los agentes recolectores: Node Exporter (sistema de archivos y CPU del Host Debian) y cAdvisor (monitoreo de recursos consumidos por contenedores).
- [ ] Entender las métricas básicas expuestas en el formato estándar de Prometheus en el endpoint `/metrics`.
- [ ] Diferenciar entre los 4 tipos de métricas de Prometheus: Counter, Gauge, Histogram y Summary.

## 📚 Conceptos Mínimos a Estudiar
*   **Time Series Database (TSDB):** Base de datos optimizada para almacenar valores numéricos que varían a lo largo del tiempo. Las muestras se indexan por marca de tiempo (timestamp) y etiquetas dimensionales en formato llave-valor.
*   **Tipos de Métricas:**
    *   *Counter:* Contador acumulativo que solo se incrementa o resetea a cero al reiniciar (ej. peticiones totales HTTP).
    *   *Gauge:* Métrica que puede subir y bajar a discreción (ej. uso actual de memoria RAM).
    *   *Histogram:* Muestrea las observaciones (habitualmente latencias o tamaños de archivos) y las cuenta en rangos (buckets) definidos.
*   **cAdvisor vs Node Exporter:**
    *   *Node Exporter:* Mide el rendimiento físico del hardware del host anfitrión (Debian).
    *   *cAdvisor:* Analiza los namespaces y cgroups del kernel para reportar el consumo de recursos de forma aislada por cada contenedor Docker activo.

## 🚀 Actividades Prácticas Realizadas
1. Desplegados Prometheus, Node Exporter y cAdvisor a través de un archivo `docker-compose-monitor.yml`.
2. Escrito el archivo `prometheus.yml` detallando las tareas de scraping de hardware y contenedores.
3. Montados de forma segura directorios del kernel y cgroups del host Debian en cAdvisor para lectura de telemetría.
4. Integradas librerías de cliente en tu API del Módulo 2 para exponer métricas en el endpoint `/metrics`.

## 🔍 Comandos de Diagnóstico Útiles
*   `curl http://localhost:9090/-/healthy`: Comprueba si el servidor de Prometheus se encuentra activo y saludable.
*   `docker compose -f docker-compose-monitor.yml logs prometheus`: Revisa los logs de Prometheus para verificar fallos de conexión hacia los agentes de scraping.
