# Tópico 1.3: Gateway de Entrada y Proxy Inverso con Nginx

## 🎯 Objetivo de Aprendizaje
Implementar un Proxy Inverso (Nginx) como gateway unificado para enrutar el tráfico entrante de red hacia los contenedores internos aislados.

## 📋 Checklist de Conceptos a Dominar
- [ ] Explicar la diferencia entre un Servidor Web clásico y un Proxy Inverso (Reverse Proxy).
- [ ] ¿Cómo funciona la directiva `proxy_pass` para reenviar peticiones dentro de redes de Docker?
- [ ] Conocer la importancia de reescribir cabeceras HTTP como `Host`, `X-Real-IP` y `X-Forwarded-For`.
- [ ] Entender las fases del procesamiento de peticiones en Nginx (bloques `server`, `location` y `upstream`).
- [ ] Conocer la directiva `try_files` para servir archivos de aplicaciones Single Page Applications (SPA).

## 📚 Conceptos Mínimos a Estudiar
*   **Proxy Inverso:** Actúa como intermediario del servidor web físico. Oculta los puertos internos de los microservicios en Docker y expone únicamente el puerto 80/443 para todo el tráfico, mejorando la seguridad perimetral.
*   **Cabeceras de Proxy (Headers):** Cuando Nginx pasa una solicitud a un backend (`api-backend:3000`), el backend ve que la IP del remitente es la del proxy Nginx, no la del cliente real. Es indispensable inyectar cabeceras como `X-Real-IP` y `X-Forwarded-For` para mantener la auditoría del tráfico de red.
*   **Upstreams:** Permiten definir grupos de servidores backend a los que enrutar el tráfico, habilitando balanceo de carga interno (Round-Robin, Least Connections) nativo y transparente.

## 🚀 Actividades Prácticas Realizadas
1. Creado el archivo de configuración `nginx.conf` en el host Debian.
2. Desplegado Nginx como servicio principal expuesto a los puertos 80 y 443 físicos del servidor.
3. Mapeado el ruteo básico de la raíz `/` hacia el contenedor web estático (`web-static`).
4. Realizadas pruebas de recarga en caliente de configuraciones (`nginx -s reload`) sin detener los contenedores.

## 🔍 Comandos de Diagnóstico Útiles
*   `nginx -t`: Valida la sintaxis del archivo de configuración de Nginx (dentro o fuera del contenedor).
*   `docker compose exec nginx-proxy nginx -s reload`: Recarga la configuración del proxy inverso Nginx en caliente sin causar caídas de tráfico.
*   `curl -I http://localhost`: Realiza una petición HTTP simple y devuelve únicamente las cabeceras de respuesta para auditar el ruteo.
*   `ss -tulpn | grep -E "80|443"`: Comprueba si Nginx está escuchando correctamente en los puertos del Host Debian.
