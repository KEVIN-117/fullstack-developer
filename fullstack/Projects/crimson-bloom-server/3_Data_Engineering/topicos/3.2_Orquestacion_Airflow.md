# Tópico 3.2: Orquestación con Apache Airflow

## 🎯 Objetivo de Aprendizaje
Desplegar, configurar y administrar Apache Airflow para estructurar, monitorear y calendarizar tareas de procesamiento de datos mediante grafos acíclicos dirigidos.

## 📋 Checklist de Conceptos a Dominar
- [ ] Explicar el concepto de Grafo Acíclico Dirigido (DAG) en el ámbito del procesamiento de datos en lote.
- [ ] Conocer las diferencias funcionales de los componentes de Airflow: Scheduler, Webserver, MetaDB, y Executor.
- [ ] ¿Cómo funciona el paso de datos contextuales entre tareas mediante XComs y qué limitaciones tiene?
- [ ] Diferencia entre un Operador (`PythonOperator`, `BashOperator`, `SqlOperator`) y un Sensor.
- [ ] Entender las políticas de reintentos (`retries`, `retry_delay`) ante fallos de tareas.

## 📚 Conceptos Mínimos a Estudiar
*   **Grafos Acíclicos Dirigidos (DAGs):** Colección de tareas organizadas de forma secuencial sin bucles (ciclos). Define el orden lógico de ejecución de tareas de datos con dependencias explícitas (`tarea_A >> tarea_B`).
*   **Airflow Components:**
    *   *Scheduler:* Cerebro del sistema. Monitorea y calendariza los DAGs lanzando los trabajos a ejecutar.
    *   *Webserver:* Interfaz de usuario para inspeccionar el estado de los DAGs, pausarlos o forzar su ejecución.
    *   *Executor:* Define cómo se corren las tareas físicas (hilos locales con `LocalExecutor` o colas de Redis con `CeleryExecutor`).
*   **XComs (Cross-Communications):** Mecanismo para intercambiar pequeños metadatos (como variables o estados) entre tareas. No debe usarse para mover datasets voluminosos (para esto se usa almacenamiento físico).

## 🔍 Comandos de Diagnóstico Útiles
*   `docker compose -f docker-compose-airflow.yml ps`: Comprueba el estado de la infraestructura del orquestador.
*   `docker compose -f docker-compose-airflow.yml logs airflow-scheduler`: Muestra los logs del scheduler de Airflow para verificar que detecte nuevos archivos de DAGs.
*   `airflow tasks test <dag_id> <task_id> <execution_date>`: Ejecuta y testea una tarea individual de un DAG de forma aislada en la terminal sin programar la corrida completa.
