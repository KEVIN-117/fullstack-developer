# Tópico 3.3: Diseño de Pipelines ETL Idempotentes

## 🎯 Objetivo de Aprendizaje
Programar pipelines de datos en Python que extraigan, transformen, dedupliquen con Redis y carguen información de facturas en PostgreSQL de forma robusta e idempotente.

## 📋 Checklist de Conceptos a Dominar
- [ ] Explicar la importancia de la idempotencia y el diseño libre de efectos secundarios en ingeniería de datos.
- [ ] ¿Cómo gestionar y depurar fallos intermedios en el pipeline sin dejar la base de datos en un estado inconsistente?
- [ ] Entender el uso de sentencias `ON CONFLICT` en SQL (Upsert) para el control de duplicaciones a nivel de base de datos física.
- [ ] ¿Cómo estructurar validaciones de negocio en Python (por ejemplo, validando tipos de datos o formatos)?
- [ ] Conocer cómo programar e implementar ejecuciones retroactivas de procesamiento (Backfilling).

## 📚 Conceptos Mínimos a Estudiar
*   **Idempotencia de Pipeline:** Garantizar que si un DAG de Airflow corre 5 veces consecutivas con el mismo conjunto de datos de entrada, el estado de las tablas de PostgreSQL sea idéntico y no se multipliquen los registros ni se dupliquen las sumas analíticas.
*   **Manejo de Conflictos (Upsert):** La directiva `ON CONFLICT (columna_unica) DO UPDATE / DO NOTHING` permite a la base de datos interceptar la inserción de registros existentes y actualizarlos en lugar de lanzar una excepción fatal que detenga el pipeline.
*   **Backfilling:** Ejecución de tareas de datos orientadas al pasado. Permite correr el pipeline con fechas históricas para reprocesar o recuperar el historial de datos sin alterar las particiones de datos del presente.
