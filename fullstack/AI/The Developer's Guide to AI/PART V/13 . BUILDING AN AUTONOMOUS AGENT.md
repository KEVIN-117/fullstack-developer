### **Setting Up Your Agent Development Environment**

Imagine you’re an investor wanting to know how much money the companies you care about made at the end of Q4 2024. It sounds easy, but to find that number, you’d have to take these steps:

1. Go online and search for each company’s earnings report.
2. Find the correct link for the Q4 2024 report.
3. Download that report (which can be a long document).
4. Open the report and look through it to find the specific section with the revenue information you need.

This multi-step process takes time and effort for each company.

In these kinds of tasks, where the steps aren’t always the same, AI agents really shine. The process isn’t just about finding the report itself, because even reading the report and locating the specific revenue figure can be different for each company. The way Amazon presents its earnings might be different from the way Apple or Google does it. This makes it challenging to create a single, fixed set of instructions that would work for every company’s report.

Let’s build our first agent. The following code was built and tested on Python 3.13.7 and Hugging Face smolagents 1.22.0.

It’s good practice to start by setting up a new Python environment. This helps manage project dependencies and avoids conflicts with other projects on your system, keeping your project clean and isolated. You can typically do this using tools like venv (built into Python) or Conda.

We’ll be using the Hugging Face smolagents library, which leverages tools like LiteLLM to connect to various LLMs, including Google’s models. Since our examples will use a Google Gemini Flash model, we need to install smolagents with the litellm integration. Open your terminal or command prompt within your new environment and run the following command:

pip install smolagents==1.22.0 "smolagents[litellm]" "smolagents[toolkit]"

To allow smolagents and LiteLLM to access the Google Gemini model API, you will need an API key. Obtain your GEMINI_API_KEY from Google AI Studio or Google Cloud Platform. Once you have your key, it must be made available to your Python environment by setting it as an environment variable named GEMINI_API_KEY. For example, in your terminal (for the current session), you might use the following:

// On Linux/macOS
export GEMINI_API_KEY=your_api_key_here
// On Windows
set GEMINI_API_KEY=your_api_key_here

Replace your_api_key_here with your actual key. For a more permanent solution across different terminal sessions, consider adding this line to your shell’s startup file (like _/.bashrc_, _/.zshrc_, or _/.profile_) or using a _.env_ file loaded by a library like python-dotenv.

### **Building Your First Agent**

With your environment set up, necessary libraries installed, and your API key configured, you’re ready to write the code for your first simple AI agent using smolagents. This initial agent will be equipped with built-in capabilities to begin tackling tasks:

from smolagents import CodeAgent, LiteLLMModel

model_id = "gemini/gemini-2.0-flash"

model = LiteLLMModel(
  model_id=model_id,
  provider="google",
)

tools = []

agent = CodeAgent(
  tools=tools,
  model=model,
  add_base_tools=True,
  verbosity_level=1,
  max_steps=5
)

message = "Based on Amazon's Q4 2024 earnings report,
            what is the revenue for the quarter?"
agent.run(message)

Let’s examine what the CodeAgent block does. The tools=tools parameter assigns a set of tools to the agent. These tools are the specific functions or capabilities the agent can use to accomplish its tasks. In our case, we are not assigning any tools. We will use this parameter later.

The underlying LLM that the agent will use for its reasoning and code generation is set using model=model. When we set add_base_tools=True, this automatically includes a standard set of essential tools. The smolagents library has a set of default tools that includes the DuckDuckGo web search capability and a Python code interpreter. The verbosity_level=1 setting controls the amount of information the agent prints out while it’s working. And finally, max_steps=5 sets a limit on the number of steps the agent can take to complete its task. In this case, the agent will stop its process after a maximum of five steps, whether it has finished the task or not. This is a safety measure to prevent the agent from running indefinitely.

When you run this code, it should give the answer as $187.8 billion or an answer containing that result.

Let’s look at what’s happening under the hood. We instructed the AI agent to find Amazon’s revenue for the fourth quarter of 2024. It’s important to recognize that an LLM, in its foundational state, does not possess real-time knowledge of such specific, external data. To find the answer, the agent needs to go and look for it, just as we would!

The agent requires the capability to search and retrieve the data from the internet. As part of our initial setup, we equipped the agent with this functionality by including the parameter add_base_tools=True. This enabled the agent with a set of default utilities, one of which is a web search tool powered by the DuckDuckGo search engine. This allowed the agent to perform a web query to find the requested financial data.

Now, as an exercise, let’s modify our approach. Try removing the add _base_tools=True parameter from your code and execute the program again. Observe the resulting behavior when the agent is tasked with finding Amazon’s Q4 2024 revenue without the explicit provision of a web search capability. This will illustrate the agent’s reliance on external tools to access information beyond its inherent knowledge base.

### **Agents and Prompt Engineering**

Building an agent to effectively execute desired operations involves more than simply choosing a capable reasoning model. The art and science of prompt engineering cannot be ignored. The way we instruct and guide the agent, or setting the context, through well-crafted prompts plays an equally crucial role in achieving the desired outcome.

Let’s take the earlier example and extend it for generating the revenue of Amazon, Google, and Apple. If we update the instruction to “Show me the Q4 2024 revenue for Amazon, Google, and Apple” and run the agent, you would get a response like the following:

Amazon Q4 2024 Revenue: $187.8 billion,
Google Q4 2024 Revenue: $96.5 billion,
Apple Q4 2024 Revenue: $94.9 billion

But presenting the information in a structured table would significantly enhance its readability and facilitate easier comparison, so let’s change the instruction and ask for a table:

Show me the Q4 2024 revenue for Amazon,
Google and Apple and compare them in a table

This gives us the following result:

|**Company**|**Q4 2024 Revenue (USD)**|
|---|---|
|Amazon|$187.8 billion|
|Google (Alphabet)|$96.5 billion|
|Apple|$94.9 billion|

This revised instruction explicitly requests a structured output, making it much more convenient for analysis and comparison of the financial results.
