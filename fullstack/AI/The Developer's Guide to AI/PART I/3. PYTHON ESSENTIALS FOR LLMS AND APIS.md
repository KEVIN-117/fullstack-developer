### **Llamando a un LLM mediante una API**

Ahora vas a recrear el servicio REST del [Capítulo 2](https://learning.oreilly.com/library/view/the-developers-guide/0642572230333/xhtml/ch2.xhtml#ch2). Cuando se llama, el servicio utilizará FastAPI y el SDK de Ollama para transmitir de vuelta una finalización del LLM. Ya has aprendido los conceptos a través de los ejemplos de JavaScript del capítulo anterior, así que puedes lanzarte directamente al código en Python.

#### _**Crear el servidor FastAPI**_

Crea un nuevo directorio para tu proyecto llamado _getting_started_python_. Dentro del directorio de tu proyecto, crea un archivo llamado _main.py_. Abre este archivo en un editor de texto o en tu IDE favorito (como VS Code).

Vamos a repasar los detalles en breve, pero primero añadiremos las siguientes líneas de código al _archivo main.py_:

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from fastapi.middleware.cors import CORSMiddleware
from ollama import Client
from pydantic import BaseModel

app = FastAPI()

app.add_middleware(
  CORSMiddleware,
  allow_origins=["*"],
  allow_credentials=True,
  allow_methods=["*"],
  allow_headers=["*"],
)

client = Client()

class ChatRequest(BaseModel):
  question: str

def generate_stream(question: str):
  result = client.generate(stream=True, model="llama3.2", prompt=question)

  for chunk in result:
    if chunk.response:
      yield chunk.response
  
@app.post("/")
def chat(chatRequest: ChatRequest):
  return StreamingResponse(
    generate_stream(chatRequest.question), media_type="text/plain")
```

Este es un servidor FastAPI sencillo. Escuchará en el puerto 8000 (el puerto predeterminado de FastAPI) cualquier solicitud HTTP POST. Ahora vamos a repasar el código.

Las primeras cuatro líneas son importaciones de las librerías de Python que instalaste ➊. Estas importaciones definen las clases que vas a usar de cada biblioteca:

- FastAPI La clase principal utilizada para crear y gestionar una aplicación web FastAPI. Sirve como punto central para definir los endpoints de la API, gestionar solicitudes y configurar el comportamiento de la aplicación.
- StreamingResponse Una utilidad FastAPI diseñada para enviar grandes cantidades de datos a un cliente en fragmentos en lugar de todos de golpe. Esto facilita que podamos transmitir respuestas de los LLM.
- CORSMiddleware Como en nuestro ejemplo Node.js, FastAPI proporciona middleware que gestiona automáticamente los requisitos de CORS.
- Cliente El cliente para comunicarse con modelos LLM alojados en tu instancia local de Olama.

Empiezas construyendo una instancia de servidor FastAPI ➋. La variable de la app se inicializa con una referencia al servidor para que puedas configurarlo y configurar tu API de servicio.

Como en el ejemplo anterior, estás configurando middleware para gestionar los requisitos de CORS por ti (véase [el Capítulo 2](https://learning.oreilly.com/library/view/the-developers-guide/0642572230333/xhtml/ch2.xhtml#ch2) para más información sobre CORS). Llamas al método app.add_middleware para añadir el componente CORSMiddleware que has importado ➌. Esto permite que tu cliente de navegador haga peticiones a tu servidor.

Fíjate en que proporcionas la clase CORSMiddleware junto con algunos parámetros de configuración. Estos parámetros se definen por nombre (por ejemplo, allow_origins=["*"]). Este es un patrón común que verás, especialmente para parámetros opcionales de funciones y métodos en Python. Esta configuración básicamente abre tu servidor a todos los clientes del navegador.

Ahora se crea una instancia cliente Ollama ➍. No estás cambiando ninguna opción de configuración porque los valores predeterminados son apropiados para este ejemplo.

#### _**Configurar el servidor FastAPI**_

Ahora que tienes los componentes necesarios, puedes definir tu API REST:

```python
   --snip--

➊ from pydantic import BaseModel

➋ class ChatRequest(BaseModel):
     question: str

➌ @app.post("/")
➍ def chat(chatRequest: ChatRequest):

```

Fíjate en que estás importando una clase BaseModel adicional desde el módulo pydántico ➊. No tenías que instalar la biblioteca Pydantic porque viene incluida con FastAPI. Verás que se usa Pydantic a lo largo del libro.

Pydantic facilita la creación de clases (conocidas como _modelos_) que definen el cuerpo JSON en la solicitud y respuesta de una API REST. La clase ChatRequest define cómo queremos que sea nuestro cuerpo de solicitud JSON ➋. La clase hereda del Modelo Base Pydántico (los paréntesis son la sintaxis de la herencia en Python). La clase tiene un único atributo llamado pregunta que se define como una cadena (fuerza).

La clase Pydantic BaseModel añade métodos a la clase ChatRequest que facilitan la validación y conversión del siguiente JSON a una instancia de la clase:

```json
{
  "question": "Tell me about the Beatles."
}
```

Ahora echa un vistazo a la función de chat firma ➍. La palabra clave def se utiliza para iniciar la definición de un método o función en Python. La anotación @app.post("/") sobre tu función configura la función de chat para gestionar las solicitudes REST API ➌. Esta anotación es un elemento de configuración que indica a FastAPI que tu función de chat responderá a peticiones HTTP POST que se presentan así:

```http
POST https://localhost:8000/

{
  "question": "Who are the Beatles?"
}
```

Puede parecer un poco mágico, pero verás anotaciones en los ejemplos de código a lo largo del libro. En Python, ofrecen una forma sencilla de integrar tu código con una biblioteca o framework mediante _configuración en línea_.

FastAPI entiende que cualquier petición POST a "/", la URL base del puerto que se está escuchando, debe llamar a tu función de chat. También analiza el parámetro chatRequest y utiliza nuestro modelo Pydantic para entender cómo debería ser el cuerpo del JSON.

FastAPI validará el JSON en cualquier solicitud basada en nuestra definición de modelo ChatRequest y enviará automáticamente una respuesta de error si esa validación falla. En [el capítulo 6](https://learning.oreilly.com/library/view/the-developers-guide/0642572230333/xhtml/ch6.xhtml#ch6), aprenderás más sobre cómo funciona esto cuando usamos esquemas Pydantic para estructurar la salida de un LLM.

#### _**Envía un prompt al LLM local**_

```python
--snip--

```

Esta función comienza llamando al método generate en tu cliente Ollama ➊. Este método llamará a Ollama para generar una respuesta LLM para el prompt dado. Fíjate que se han usado parámetros nombrados de nuevo para especificar tu modelo descargado (model="llama3.2") y que quieres que la respuesta se transmita (stream=True).

El resultado que obtienes es un flujo iterable. Un bucle para itera a través de los chunks a medida que se generan ➋. Luego compruebas que tienes datos de respuesta antes de entregar el texto ➌.

La palabra clave yield en Python transforma una función regular en una _función_ generadora ➍. Cuando se llama, una función generador no se ejecuta inmediatamente. En su lugar, devuelve un objeto generador, que es un iterador. Esto es perfecto para el escenario de streaming, ya que estás esperando fragmentos del cliente Ollama.

Ahora puedes organizar toda tu función de chat y retransmitir la respuesta:

```python
--snip--

def generate_stream(question: str):
  result = client.generate(stream=True, model="llama3.2", prompt=question)

  for chunk in result:
    if chunk.response:
      yield chunk.response

@app.post("/")
def chat(chatRequest: ChatRequest):
➊ return StreamingResponse(
     generate_stream(chatRequest.question), media_type="text/plain")
```

Fíjate en que estás usando el componente FastAPI StreamingReponse que importaste anteriormente, lo que hace que el streaming sea sencillo ➊. Simplemente construyes una instancia con el generador que da la función generate_stream y le dices el media_type que estás enviando de vuelta. En este caso, estás devolviendo el texto plano que genera el LLM.

> _Si vienes de lenguajes como JavaScript, Java o C#, presta mucha atención a la indentación en Python.
