#### _**Crear el archivo del servidor**_

Crea un archivo llamado _server.mjs_ en el directorio de tu proyecto. Abre este archivo en un editor de texto o en tu entorno de desarrollo integrado (IDE) favorito, como Visual Studio Code (VS Code), y añade las siguientes líneas de código:

```python
➊ import express from "express";
   import { Ollama } from "ollama";

➋ const app = express();

➌ const ollama = new Ollama();

➍ app.get('/', async (request, response) => {
  ➎ response.type('text/plain');

  ➏ const modelResponse = await ollama.generate({
       model: 'llama3.2',
       prompt: "Can you simply say 'test'?"
     });

     response.send(modelResponse.response);
   });

➐ app.listen(8000, () => {
    console.log(`Server is running on port 8000`);
   });
```

Este es un servidor Express sencillo que escucha en el puerto 8000 cualquier petición HTTP GET ➐. GET es la solicitud HTTP más básica. Cuando cargas un sitio web desde una URL, el navegador envía una solicitud GET para iniciar la carga de la página.

El ejemplo comienza importando lo siguiente de los paquetes de Node.js que instalaste ➊:

- Express La función de nivel superior exportada por el módulo exprés. Es esencialmente el constructor de una instancia de aplicación Express, y proporciona una forma de gestionar rutas, gestionar solicitudes y respuestas HTTP y usar middleware.
- Ollama La clase de biblioteca ollama-js que facilita la interacción con la API de Ollama. Esta clase facilita la integración y el uso de modelos alojados en Ollama dentro de tus aplicaciones JavaScript.

La función express se utiliza entonces para inicializar tu aplicación, y la constante de la app se establece con el resultado ➋. Se crea una instancia de Ollama y se establece a la constante de ollama para su uso en nuestro servicio ➌.

El método get en la instancia de la app se utiliza entonces para configurar la función _de manejador de ruta_ que quieres llamar cuando se recibe cualquier solicitud GET en la URL raíz ('/') ➍. Observa que la función de manejador de rutas recibe parámetros de solicitud y respuesta:

- Solicitud Un objeto que representa la solicitud HTTP entrante del cliente. Este objeto contiene propiedades y métodos que proporcionan información sobre la solicitud (como cabeceras, parámetros y cuerpo).
- Respuesta Un objeto que representa la respuesta HTTP que el servidor enviará de vuelta al cliente. Este objeto contiene métodos para enviar datos, establecer encabezados y gestionar el proceso de respuesta.

Dentro de la función de manejador de rutas, empiezas indicando al cliente el tipo de datos que vas a enviar de vuelta. En este caso, estarás enviando texto plano ➎. El método response.type proporciona una forma conveniente de establecer el encabezado Content-Type en texto/plano en la respuesta.

El encabezado Content-Type es importante tanto para el cliente como para el servidor. Este encabezado especial indica el tipo de datos que se envían en una solicitud o respuesta (conocido como tipo de medio o tipo MIME) para que pueda procesar esos datos correctamente. Los datos pueden ser texto plano, HTML, XML, JSON y más. En el ejemplo, estás ayudando a un navegador a optimizar su renderizado diciéndole que espere texto plano. No hace falta interpretar HTML.

Ahora puedes llamar al método generate en la instancia ollama con el modelo que estás usando ➏ (en este caso, llama3.2) y un simple prompt, ¿puedes simplemente decir 'test'? El método generate se ejecuta de forma asincrónica, así que esperas la respuesta del LLM. Una vez generada la respuesta completa, se envía de vuelta al llamante con el método response.send.

### **Transmitiendo tus respuestas a un LLM en streaming**

El efecto de tipado chulo que ves en las respuestas de ChatGPT hace que se sienta responsivo. Sin él, la interfaz se sentiría lenta y a menudo insoportable.

OpenAI transformó ingeniosamente una desventaja de los LLM, su velocidad de generación de texto, en un efecto de interfaz cautivador. Alcanzar un nivel similar de respuesta es posible empleando el streaming de respuesta de LLM.

Recuerda que cuando solicitas un LLM, genera un token de respuesta por token. El streaming captura estos tokens a medida que se generan y los envía de vuelta al llamante en fragmentos. El tamaño de los chunks variará según el LLM, pero este enfoque permite enviar el texto generado de vuelta al usuario cuando esté listo. A medida que tus prompts y cadenas de llamadas crecen en tamaño y complejidad, el streaming puede ser crucial para el rendimiento (véase [la Figura 2-3](https://learning.oreilly.com/library/view/the-developers-guide/0642572230333/xhtml/ch2.xhtml#fig2_3)).

!["¿Quiénes son los Beatles?" aparece en un Gran Modelo de Lenguaje, que produce tres fragmentos de respuesta: "Los Beatles son", "un inglés", "una banda de rock que."](https://learning.oreilly.com/api/v2/epubs/urn:orm:book:0642572230333/files/images/annot_page57_1.jpg)

_Figura 2-3: Un LLM generando una respuesta en bloques para mejorar la latencia percibida_

#### _**Escucha una respuesta de LLM con Ollama**_

La biblioteca JavaScript de Ollama ofrece la capacidad de transmitir cualquier respuesta. El siguiente fragmento muestra cómo especificar que una respuesta debe transmitirse tal y como se genera el modelo:

```python
   import { Ollama } from "ollama";

   const ollama = new Ollama();

   const streamIterator = await ollama.generate({
     model: 'llama3.2',
     prompt: "Can you tell me about the Beatles in 500 words or less?",
  ➊ stream: true
   });

   --snip--
```

Configurar la opción de flujo en verdadero al llamar al método generate te permite recibir la respuesta del LLM en bloques ➊. Ahora necesitas una forma de enviar estos fragmentos de vuelta al cliente a medida que se reciben.

#### _**Transmite una respuesta REST con Express**_

El objeto Express Response proporciona el método de escritura. Este método te permite enviar una respuesta al cliente a medida que se genera. Esto es exactamente lo que necesitas. El siguiente fragmento muestra cómo esta API podría usarse para enviar un fragmento de respuesta al cliente tal como se genera mediante el método de stream:

```python
   --snip--

   const ollama = new Ollama();

   app.post('/', async (request, response) => {
     response.type('text/plain');

➊ const streamIterator = await ollama.generate({
     model: 'llama3.2',
     prompt: "Can you tell me about the Beatles in 500 words or less?",
     stream: true
   });

➋ for await (const chunk of streamIterator) {
  ➌ response.write(chunk.response);
   }

   response.end();
 });
```

Estás haciendo lo mismo que antes, pero el método generate ➊ ahora proporciona un _iterador_ sobre el que puedes hacer loop para recibir los chunks ➋. Usar await en streamIterator hace que la lógica del bucle for se ejecute cada vez que el LLM genera un chunk.

Dentro del bucle for ➌, el método de escritura del objeto Express Response se utiliza para enviar la cadena de respuesta de cada fragmento de vuelta al cliente tan pronto como está lista. El bucle continúa y los chunks se transmiten de vuelta al cliente hasta que se complete toda la respuesta del modelo.

Fíjate que ahora estás aceptando una solicitud HTTP POST. En un momento veremos cómo esto permite a un cliente enviar cualquier pregunta en el cuerpo de la solicitud para que podamos generar una respuesta desde el LLM.

#### _**Crear el archivo completo del servidor con Express**_

Si sigues el código, sustituye tu archivo _server.mjs_ por lo siguiente para transmitir la respuesta del LLM a un cliente:

  ```python
   import express from "express";
   import { Ollama } from "ollama";
   import cors from "cors";

   const app = express();

➊ app.use(cors());
   app.use(express.json());

   const ollama = new Ollama();

   app.post('/', async (request, response) => {
     response.type('text/plain');

  ➋ const body = request.body;

     const streamIterator = await ollama.generate({
       model: 'llama3.2',
    ➌ prompt: body.question,
       stream: true
     });

     for await (const chunk of streamIterator) {
       response.write(chunk.response);
     }

     response.end();
   });

   app.listen(8000, () => {
     console.log(`Server is running on port 8000`);
   });
  ```

Empiezas configurando el middleware Express necesario ➊. El middleware Express proporciona una forma sencilla de añadir lógica que realiza cambios en una petición y respuesta antes y/o después de que tu código se ejecute. Por ejemplo, el middleware de Cors añadirá automáticamente los encabezados de solicitud y respuesta necesarios para gestionar CORS.

El middleware express.json analiza automáticamente el JSON de las solicitudes entrantes. Le estás diciendo a Express que espere JSON en el cuerpo de la solicitud. Los datos analizados están disponibles en el atributo request.body ➋. Por ejemplo, el siguiente JSON podría enviarse como cuerpo de la solicitud al servidor:

```json
{
  "question": "Can you tell me about the Beatles in 500 words or less?"
}
```

El middleware express.json analiza esto para que puedas recuperar directamente el valor del atributo body.question y enviar la pregunta como el prompt ➌.
