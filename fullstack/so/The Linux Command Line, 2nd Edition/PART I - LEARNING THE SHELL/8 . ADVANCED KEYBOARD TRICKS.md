A menudo describo en broma a Unix como "el sistema operativo para la gente a la que le gusta escribir". Por supuesto, el hecho de que tenga una línea de comandos es testimonio de ello; sin embargo, a los usuarios de la línea de comandos no les gusta escribir *tanto*. ¿Por qué si no tantos comandos tendrían nombres tan cortos como **cp**, **ls**, **mv** y **rm**? De hecho, uno de los objetivos más preciados de la línea de comandos es la pereza: hacer el máximo trabajo con el menor número de pulsaciones de teclas. Otro objetivo es no tener que levantar nunca los dedos del teclado para alcanzar el ratón. En este capítulo, veremos las características de **bash** que hacen que el uso del teclado sea más rápido y eficiente.

Los siguientes comandos harán su aparición:

**clear** - Limpia la pantalla de la terminal.

**history** - Muestra o manipula la lista del historial.

### **Edición de la Línea de Comandos**

**bash** utiliza una biblioteca (una colección compartida de rutinas que diferentes programas pueden utilizar) llamada *Readline* para implementar la edición de la línea de comandos. Ya hemos visto algo de esto. Sabemos, por ejemplo, que las teclas de flecha mueven el cursor, pero hay muchas más características. Piensa en ellas como herramientas adicionales que podemos emplear en nuestro trabajo. No es importante aprenderlas todas, pero muchas de ellas son muy útiles. Elige las que desees.

> [!NOTE]
> _Algunas de las secuencias de teclas tratadas en este capítulo (particularmente las que usan la tecla **ALT**) pueden ser interceptadas por la interfaz gráfica (GUI) para otras funciones. Todas las secuencias de teclas deberían funcionar correctamente cuando se utiliza una consola virtual._

Debido a que es posible que cometamos un error al componer los comandos, necesitamos una forma de corregirlos eficientemente. La Tabla 8-2 describe los comandos de teclado que se utilizan para editar caracteres en la línea de comandos.

| --- | --- |

**Tabla 8-3:** Comandos de Cortar y Pegar

**LA TECLA META**

Si te aventuras en la documentación de Readline, que se puede encontrar en la sección "READLINE" de la página man de **bash**, encontrarás el término *meta key* (tecla meta). En los teclados modernos, esta se asigna a la tecla **ALT**; sin embargo, esto no siempre fue así.

En los tiempos oscuros (antes de los PCs pero después de Unix), no todo el mundo tenía su propio ordenador. Lo que podían tener era un dispositivo llamado *terminal*. Una terminal era un dispositivo de comunicación que contaba con una pantalla de visualización de texto y un teclado, y solo la electrónica suficiente en su interior para mostrar caracteres de texto y mover el cursor. Estaba conectada (normalmente por cable serie) a un ordenador más grande o a la red de comunicación de un ordenador más grande. Había muchas marcas diferentes de terminales, y todas tenían teclados y conjuntos de características de visualización diferentes. Debido a que todas tendían a entender al menos ASCII, los desarrolladores de software que querían aplicaciones portátiles escribían para el mínimo común denominador. Los sistemas Unix tienen una forma elaborada de tratar con las terminales y sus diferentes características de visualización. Debido a que los desarrolladores de Readline no podían estar seguros de la presencia de una tecla de control extra dedicada, inventaron una y la llamaron *meta*. Aunque la tecla **ALT** sirve como tecla meta en los teclados modernos, también puedes presionar y soltar la tecla **ESC** para obtener el mismo efecto que mantener pulsada la tecla **ALT** si todavía estás usando una terminal (¡lo cual todavía puedes hacer en Linux!).

### **Autocompletado**

Otra forma en que el shell puede ayudarte es a través de un mecanismo llamado *autocompletado*. El autocompletado ocurre cuando presionas la tecla **TAB** mientras escribes un comando. Veamos cómo funciona. Dado un directorio personal que se ve así:

```bash
[me@linuxbox ~]$ ls  
Desktop    ls-output.txt  Pictures  Templates      Videos  
Documents  Music          Public
```

intenta escribir lo siguiente, pero *no presiones* **ENTER**:

```bash
[me@linuxbox ~]$ ls l
```

Ahora presiona **TAB**.

```bash
[me@linuxbox ~]$ ls ls-output.txt
```

¿Ves cómo el shell completó la línea por ti? Intentemos con otro. De nuevo, no presiones **ENTER**.

```bash
[me@linuxbox ~]$ ls D
```

Presiona **TAB**.

```bash
[me@linuxbox ~]$ ls D
```

No hay autocompletado, simplemente nada. Esto ocurrió porque `D` coincide con más de una entrada en el directorio. Para que el autocompletado tenga éxito, la "pista" que le das tiene que ser inequívoca. Si vamos más allá, como con lo siguiente:

```bash
[me@linuxbox ~]$ ls Do
```

y luego presionas **TAB**:

```bash
[me@linuxbox ~]$ ls Documents
```

el autocompletado tiene éxito.

Si bien este ejemplo muestra el autocompletado de nombres de ruta, que es su uso más común, el autocompletado también funcionará en variables (si el principio de la palabra es un `$`), nombres de usuario (si la palabra comienza con `~`), comandos (si la palabra es la primera de la línea) y nombres de host (si el principio de la palabra es `@`). El autocompletado de nombres de host solo funciona para los nombres de host listados en */etc/hosts*.

Varias secuencias de teclas de control y meta están asociadas con el autocompletado, como se indica en la Tabla 8-4.

**Tabla 8-4:** Comandos de Autocompletado

| **Tecla** | **Acción** |
| --- | --- |
| **ALT-?** | Mostrar una lista de posibles terminaciones. En la mayoría de los sistemas, también puedes hacerlo presionando la tecla **TAB** por segunda vez, lo cual es mucho más fácil. |
| **ALT-*** | Insertar todas las posibles terminaciones. Esto es útil cuando quieres usar más de una coincidencia posible. |

Hay bastantes más que son bastante oscuras. Aparece una lista en la página man de **bash** bajo "READLINE".

**AUTOCOMPLETADO PROGRAMABLE**

Las versiones recientes de **bash** tienen una facilidad llamada *autocompletado programable*. El autocompletado programable te permite a ti (o más probablemente, a tu proveedor de distribución) añadir más reglas de autocompletado. Normalmente, esto se hace para añadir soporte para aplicaciones específicas. Por ejemplo, es posible añadir autocompletados para la lista de opciones de un comando o hacer coincidir tipos de archivos particulares que una aplicación admite. Ubuntu tiene un conjunto bastante grande definido por defecto. El autocompletado programable se implementa mediante funciones del shell, una especie de mini script de shell que cubriremos en capítulos posteriores. Si tienes curiosidad, intenta lo siguiente:

`set | less`

Ahora mira si puedes encontrarlos. No todas las distribuciones los incluyen por defecto.

### **Usando el Historial**

Como descubrimos en el Capítulo 1, **bash** mantiene un historial de los comandos que se han introducido. Esta lista de comandos se guarda en tu directorio personal en un archivo llamado *.bash_history*. La facilidad del historial es un recurso útil para reducir la cantidad de escritura que tienes que hacer, especialmente cuando se combina con la edición de la línea de comandos.

#### **_Buscando en el Historial_**

En cualquier momento, podemos ver el contenido de la lista del historial de comandos haciendo lo siguiente:

```bash
[me@linuxbox ~]$ history | less
```

Por defecto, **bash** almacena los últimos 500 comandos que hemos introducido, aunque la mayoría de las distribuciones modernas establecen este valor en 1.000. Veremos cómo ajustar este valor en el Capítulo 11. Digamos que queremos encontrar los comandos que usamos para listar */usr/bin*. Esta es una forma en que podríamos hacerlo:

```bash
[me@linuxbox ~]$ history | grep /usr/bin
```

Y digamos que entre nuestros resultados obtuvimos una línea que contiene un comando interesante como este:

```bash
   88  ls -l /usr/bin > ls-output.txt
```

El `88` es el número de línea del comando en la lista del historial. Podríamos usar esto inmediatamente usando otro tipo de expansión llamada *expansión del historial*. Para usar nuestra línea descubierta, podríamos hacer esto:

```bash
[me@linuxbox ~]$ !88
```

**bash** expandirá `!88` en el contenido de la línea 88 de la lista del historial. Hay otras formas de expansión del historial que cubriremos en la siguiente sección.

**bash** también proporciona la capacidad de buscar en la lista del historial de forma incremental. Esto significa que podemos decirle a **bash** que busque en la lista del historial a medida que introducimos caracteres, y cada carácter adicional refina aún más nuestra búsqueda. Para iniciar la búsqueda incremental, presiona **CTRL-R** seguido del texto que estás buscando. Cuando lo encuentres, puedes presionar **ENTER** para ejecutar el comando o presionar **CTRL-J** para copiar la línea de la lista del historial a la línea de comandos actual. Para encontrar la siguiente aparición del texto (moviéndose "hacia arriba" en la lista del historial), presiona **CTRL-R** de nuevo. Para salir de la búsqueda, presiona **CTRL-G** o **CTRL-C**. Aquí lo vemos en acción:

```bash
[me@linuxbox ~]$
```

Primero presiona **CTRL-R**.

```bash
(reverse-i-search)`':
```

El prompt cambia para indicar que estamos realizando una búsqueda incremental inversa. Es "inversa" porque estamos buscando desde el "ahora" hacia algún momento en el pasado. A continuación, empezamos a escribir nuestro texto de búsqueda. En este ejemplo, estamos buscando `/usr/bin`:

```bash
(reverse-i-search)`/usr/bin': ls -l /usr/bin > ls-output.txt
```

Inmediatamente, la búsqueda devuelve nuestro resultado. Con nuestro resultado, podemos ejecutar el comando presionando **ENTER**, o podemos copiar el comando a nuestra línea de comandos actual para seguir editándolo presionando **CTRL-J**. Copiémoslo. Presiona **CTRL-J**.

```bash
[me@linuxbox ~]$ ls -l /usr/bin > ls-output.txt
```

¡Nuestro indicador del shell regresa, y nuestra línea de comandos está cargada y lista para la acción!

La Tabla 8-5 enumera algunas de las pulsaciones de teclas utilizadas para manipular la lista del historial.

**Tabla 8-5:** Comandos del Historial

| **Tecla** | **Acción** |
| --- | --- |
| **CTRL-P** | Moverse a la entrada anterior del historial. Esta es la misma acción que la flecha arriba. |
| **CTRL-N** | Moverse a la siguiente entrada del historial. Esta es la misma acción que la flecha abajo. |
| **ALT-<** | Moverse al principio (arriba) de la lista del historial. |
| **ALT->** | Moverse al final (abajo) de la lista del historial, es decir, a la línea de comandos actual. |
| **CTRL-R** | Búsqueda incremental inversa. Busca de forma incremental desde la línea de comandos actual hacia arriba en la lista del historial. |
| **ALT-P** | Búsqueda inversa, no incremental. Con esta tecla, escribe la cadena de búsqueda y presiona **ENTER** antes de que se realice la búsqueda. |
| **ALT-N** | Búsqueda hacia adelante, no incremental. |
| **CTRL-O** | Ejecutar el elemento actual de la lista del historial y avanzar al siguiente. Esto es práctico si estás intentando volver a ejecutar una secuencia de comandos de la lista del historial. |

#### **_Expansión del Historial_**

El shell ofrece un tipo especializado de expansión para los elementos de la lista del historial mediante el uso del carácter `!`. Ya hemos visto cómo el signo de exclamación puede ir seguido de un número para insertar una entrada de la lista del historial. Hay otras características de expansión, como se describe en la Tabla 8-6.

**Tabla 8-6:** Comandos de Expansión del Historial

| **Secuencia** | **Acción** |
| --- | --- |
| **!!** | Repetir el último comando. Probablemente sea más fácil presionar la flecha arriba y **ENTER**. |
| **!número** | Repetir el elemento *número* de la lista del historial. |
| **!cadena** | Repetir el último elemento de la lista del historial que comience con *cadena*. |
| **!?cadena** | Repetir el último elemento de la lista del historial que contenga *cadena*. |

Advierto contra el uso de las formas `!cadena` y `!?cadena` a menos que estés absolutamente seguro del contenido de los elementos de la lista del historial.

Hay muchos más elementos disponibles en el mecanismo de expansión del historial, pero este tema ya es demasiado arcano, y nuestras cabezas podrían explotar si continuamos. La sección "HISTORY EXPANSION" de la página man de **bash** entra en todos los detalles escabrosos. ¡Siéntete libre de explorar!

**SCRIPT**

Además de la función de historial de comandos en **bash**, la mayoría de las distribuciones de Linux incluyen un programa llamado **script** que puede utilizarse para grabar una sesión completa del shell y guardarla en un archivo. La sintaxis básica del comando es la siguiente:

```bash
script archivo
```

donde *archivo* es el nombre del archivo utilizado para guardar la grabación. Si no se especifica ningún archivo, se utiliza el archivo *typescript*. Consulta la página man de **script** para obtener una lista completa de las opciones y características del programa.
