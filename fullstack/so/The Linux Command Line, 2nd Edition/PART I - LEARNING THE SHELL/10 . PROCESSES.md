Los sistemas operativos modernos suelen ser *multitarea*, lo que significa que crean la ilusión de hacer más de una cosa a la vez cambiando rápidamente de un programa en ejecución a otro. El núcleo gestiona esto mediante el uso de *procesos*. Los procesos son la forma en que Linux organiza los diferentes programas que esperan su turno en la CPU.

A veces un ordenador se vuelve lento o una aplicación deja de responder. En este capítulo, veremos algunas de las herramientas disponibles en la línea de comandos que nos permiten examinar qué están haciendo los programas y cómo terminar los procesos que se están portando mal.

Este capítulo presentará los siguientes comandos:

**ps** - Informa de una instantánea de los procesos actuales.

**top** - Muestra las tareas del sistema.

**jobs** - Lista los trabajos activos.

**bg** - Coloca un trabajo en segundo plano (*background*).

**fg** - Coloca un trabajo en primer plano (*foreground*).

**kill** - Envía una señal a un proceso.

**killall** - Mata procesos por su nombre.

**shutdown** - Apaga o reinicia el sistema.

### **Cómo funciona un proceso**

Cuando un sistema se pone en marcha, el núcleo inicia algunas de sus propias actividades como procesos y lanza un programa llamado **init**. **init**, a su vez, ejecuta una serie de scripts de shell (ubicados en */etc*) llamados *scripts de inicio* (*init scripts*), que inician todos los servicios del sistema. Muchos de estos servicios se implementan como *programas demonio* (*daemon programs*), programas que simplemente se quedan en segundo plano y hacen lo suyo sin tener ninguna interfaz de usuario. Así que, aunque no hayamos iniciado sesión, el sistema está al menos un poco ocupado realizando tareas rutinarias.

El hecho de que un programa pueda lanzar otros programas se expresa en el esquema de procesos como un *proceso padre* (*parent process*) que produce un *proceso hijo* (*child process*).

El núcleo mantiene información sobre cada proceso para ayudar a mantener las cosas organizadas. Por ejemplo, a cada proceso se le asigna un número llamado *ID de proceso* (*PID*). Los PID se asignan en orden ascendente, siendo **init** el que siempre obtiene el PID 1. El núcleo también lleva la cuenta de la memoria asignada a cada proceso, así como de la disposición de los procesos para reanudar la ejecución. Al igual que los archivos, los procesos también tienen propietarios e IDs de usuario, IDs de usuario efectivos, etc.

### **Visualización de Procesos**

El comando más utilizado para ver los procesos (hay varios) es **ps**. El programa **ps** tiene muchas opciones, pero en su forma más simple se utiliza así:

```bash
[me@linuxbox ~]$ ps  
  PID TTY          TIME CMD  
 5198 pts/1    00:00:00 bash  
10129 pts/1    00:00:00 ps
```

El resultado en este ejemplo enumera dos procesos, el proceso 5198 y el proceso 10129, que son **bash** y **ps**, respectivamente. Como podemos ver, por defecto, **ps** no nos muestra mucho, solo los procesos asociados con la sesión de terminal actual. Para ver más, necesitamos añadir algunas opciones; sin embargo, antes de hacerlo, miremos los otros campos producidos por **ps**. TTY es la abreviatura de "teletipo" y se refiere a la *terminal de control* del proceso. Unix está mostrando su edad aquí. El campo TIME es la cantidad de tiempo de CPU consumido por el proceso. Como podemos ver, ninguno de los procesos hace que el ordenador trabaje muy duro.

Si añadimos una opción, podemos obtener una imagen más amplia de lo que está haciendo el sistema.


Añadir la opción `x` (observa que no lleva guion inicial) le dice a **ps** que muestre todos nuestros procesos, independientemente de la terminal (si la hay) por la que estén controlados. La presencia de un `?` en la columna TTY indica que no hay terminal de control. Usando esta opción, vemos una lista de cada proceso que nos pertenece.

Debido a que el sistema está ejecutando muchos procesos, **ps** produce una lista larga. A menudo es útil canalizar (*pipe*) la salida de **ps** a **less** para facilitar la visualización. #### **_Visualización Dinámica de Procesos con top_**

```bash
[me@linuxbox ~]$ top
```

### **Control de Procesos**

Ahora que podemos ver y monitorizar los procesos, vamos a ganar algo de control sobre ellos. Para nuestros experimentos, utilizaremos un pequeño programa llamado **xlogo** como conejillo de indias. El programa **xlogo** es un programa de ejemplo suministrado con el X Window System (el motor subyacente que hace funcionar los gráficos en nuestra pantalla), que simplemente muestra una ventana redimensionable que contiene el logotipo de X. Primero, conoceremos a nuestro sujeto de pruebas.

```bash
[me@linuxbox ~]$ xlogo
```

Después de introducir el comando, debería aparecer en algún lugar de la pantalla una pequeña ventana con el logotipo. En algunos sistemas, **xlogo** podría imprimir un mensaje de advertencia, pero puede ignorarse con seguridad.

**NOTA**

_Si tu sistema no incluye el programa **xlogo**, intenta usar **gedit** o **kwrite** en su lugar._

Podemos verificar que **xlogo** se está ejecutando redimensionando su ventana. Si el logotipo se redibuja con el nuevo tamaño, el programa se está ejecutando.

¿Observas cómo no ha vuelto el prompt del shell? Esto se debe a que el shell está esperando a que el programa termine, al igual que todos los demás programas que hemos utilizado hasta ahora. Si cerramos la ventana de **xlogo** (ver Figura 10-1), el prompt regresa.

#### **_Interrumpiendo un Proceso_**

Observemos lo que sucede cuando ejecutamos **xlogo** de nuevo. Primero, introduce el comando **xlogo** y verifica que el programa se está ejecutando. A continuación, vuelve a la ventana de la terminal y presiona **CTRL-C**.

```bash
[me@linuxbox ~]$ xlogo  
[me@linuxbox ~]$
```

En una terminal, presionar **CTRL-C** *interrumpe* un programa. Esto significa que estamos pidiendo amablemente al programa que termine. Después de presionar **CTRL-C**, la ventana de **xlogo** se cerró y el prompt del shell regresó.

Muchos programas de línea de comandos (pero no todos) pueden interrumpirse utilizando esta técnica.

#### **_Colocando un Proceso en Segundo Plano_**

Supongamos que queremos recuperar el prompt del shell sin terminar el programa **xlogo**. Podemos hacerlo colocando el programa en segundo plano (*background*). Piensa en la terminal como si tuviera un *primer plano* (*foreground*, con cosas visibles en la superficie como el prompt del shell) y un *segundo plano* (con cosas ocultas tras la superficie). Para lanzar un programa de modo que se coloque inmediatamente en segundo plano, añadimos al comando el carácter ampersand (`&`).

```bash
[me@linuxbox ~]$ xlogo &  
[1] 28236  
[me@linuxbox ~]$
```

Tras introducir el comando, apareció la ventana de **xlogo** y regresó el prompt del shell, pero también se imprimieron unos números curiosos. Este mensaje forma parte de una característica del shell llamada *control de trabajos* (*job control*). Con este mensaje, el shell nos dice que hemos iniciado el trabajo número 1 (`[1]`) y que tiene el PID 28236. Si ejecutamos **ps**, podemos ver nuestro proceso.

```bash
[me@linuxbox ~]$ ps  
  PID TTY          TIME CMD  
10603 pts/1    00:00:00 bash  
28236 pts/1    00:00:00 xlogo  
28239 pts/1    00:00:00 ps
```

La facilidad de control de trabajos del shell también nos ofrece una forma de listar los trabajos que se han lanzado desde nuestra terminal. Utilizando el comando **jobs**, podemos ver esta lista:

```bash
[me@linuxbox ~]$ jobs  
[1]+  Running                 xlogo &
```

Los resultados muestran que tenemos un trabajo, numerado como 1; que se está ejecutando; y que el comando fue `xlogo &`.

#### **_Devolviendo un Proceso al Primer Plano_**

Un proceso en segundo plano es inmune a la entrada del teclado de la terminal, incluyendo cualquier intento de interrumpirlo con **CTRL-C**. Para devolver un proceso al primer plano, utiliza el comando **fg** de esta manera:

```bash
[me@linuxbox ~]$ jobs  
[1]+  Running                 xlogo &  
[me@linuxbox ~]$ fg %1  
xlogo
```

El comando **fg** seguido de un signo de porcentaje y el número de trabajo (llamado *jobspec*) hace el truco. Si solo tenemos un trabajo en segundo plano, el jobspec es opcional. Para terminar **xlogo**, presiona **CTRL-C**.

#### **_Deteniendo (Pausando) un Proceso_**

A veces querremos detener un proceso sin terminarlo. Esto se hace a menudo para permitir que un proceso en primer plano se mueva al segundo plano. Para detener un proceso en primer plano y colocarlo en el segundo plano, presiona **CTRL-Z**. Probémoslo. En el símbolo del sistema, escribe **xlogo**, presiona **ENTER** y luego presiona **CTRL-Z**.

```bash
[me@linuxbox ~]$ xlogo  
[1]+  Stopped                 xlogo  
[me@linuxbox ~]$
```

Después de detener **xlogo**, podemos verificar que el programa se ha detenido intentando redimensionar la ventana de **xlogo**. Veremos que parece estar totalmente muerta. Podemos continuar la ejecución del programa en primer plano, utilizando el comando **fg**, o reanudar la ejecución del programa en segundo plano con el comando **bg**.

```bash
[me@linuxbox ~]$ bg %1  
[1]+ xlogo &  
[me@linuxbox ~]$
```

Al igual que con el comando **fg**, el jobspec es opcional si solo hay un trabajo.

Mover un proceso del primer plano al segundo plano es útil si lanzamos un programa gráfico desde la línea de comandos pero olvidamos colocarlo en segundo plano añadiendo el `&` final.

¿Por qué querríamos lanzar un programa gráfico desde la línea de comandos? Hay dos razones:

- Puede que el programa que quieras ejecutar no figure en los menús del gestor de ventanas (como **xlogo**).
- Al lanzar un programa desde la línea de comandos, es posible que puedas ver mensajes de error que, de otro modo, serían invisibles si el programa se lanzara gráficamente. A veces, un programa no se inicia cuando se lanza desde el menú gráfico. Al lanzarlo desde la línea de comandos en su lugar, podemos ver un mensaje de error que revelará el problema. Además, algunos programas gráficos tienen opciones de línea de comandos interesantes y útiles.

### **Señales**

El comando **kill** se utiliza para "matar" procesos. Esto nos permite terminar programas que necesitan ser eliminados (es decir, algún tipo de pausa o terminación). He aquí un ejemplo:

```bash
[me@linuxbox ~]$ xlogo &  
[1] 28401  
[me@linuxbox ~]$ kill 28401  
[1]+  Terminated              xlogo
```

Primero lanzamos **xlogo** en segundo plano. El shell imprime el jobspec y el PID del proceso en segundo plano. A continuación, utilizamos el comando **kill** y especificamos el PID del proceso que queremos terminar. También podríamos haber especificado el proceso utilizando un jobspec (por ejemplo, `%1`) en lugar de un PID.

Si bien todo esto es muy sencillo, hay algo más que eso. El comando **kill** no "mata" exactamente los procesos; más bien, les envía *señales* (*signals*). Las señales son una de las varias formas en que el sistema operativo se comunica con los programas. Ya hemos visto señales en acción con el uso de **CTRL-C** y **CTRL-Z**. Cuando la terminal recibe una de estas pulsaciones, envía una señal al programa que está en primer plano. En el caso de **CTRL-C**, se envía una señal llamada **INT** (*interrupt*, interrupción); con **CTRL-Z**, se envía una señal llamada **TSTP** (*terminal stop*, detención de terminal). Los programas, a su vez, "escuchan" las señales y pueden actuar sobre ellas a medida que las reciben. El hecho de que un programa pueda escuchar y actuar sobre las señales permite que un programa haga cosas como guardar el trabajo en curso cuando recibe una señal de terminación.

#### **_Enviando Señales a Procesos con kill_**

El comando **kill** se utiliza para enviar señales a los programas. Su sintaxis más común es la siguiente:

`kill [-señal] PID...`

Si no se especifica ninguna señal en la línea de comandos, se envía por defecto la señal **TERM** (*terminate*, terminar). El comando **kill** se utiliza con más frecuencia para enviar las señales enumeradas en la Tabla 10-4.

**Tabla 10-4:** Señales Comunes

| **Número** | **Nombre** | **Significado** |
| --- | --- | --- |
| 1 | HUP | *Hang up* (colgar). Es un vestigio de los viejos tiempos en los que las terminales estaban conectadas a ordenadores remotos mediante líneas telefónicas y módems. La señal se utiliza para indicar a los programas que la terminal de control se ha "colgado". El efecto de esta señal puede demostrarse cerrando una sesión de terminal. El programa que se esté ejecutando en primer plano en la terminal recibirá la señal y terminará.<br><br>Esta señal también es utilizada por muchos programas demonio para provocar una reinicialización. Esto significa que cuando un demonio recibe esta señal, se reiniciará y volverá a leer su archivo de configuración. El servidor web Apache es un ejemplo de demonio que utiliza la señal **HUP** de esta manera. |
| 2 | INT | *Interrupt* (interrumpir). Realiza la misma función que **CTRL-C** enviado desde la terminal. Normalmente terminará un programa. |
| 9 | KILL | *Kill* (matar). Esta señal es especial. Mientras que los programas pueden optar por manejar las señales que se les envían de diferentes maneras, incluyendo ignorarlas por completo, la señal **KILL** nunca se envía realmente al programa de destino. En su lugar, el núcleo termina inmediatamente el proceso. Cuando un proceso termina de esta manera, no se le da oportunidad de "limpiar" después de sí mismo o guardar su trabajo. Por esta razón, la señal **KILL** debe utilizarse solo como último recurso cuando fallen otras señales de terminación. |
| 15 | TERM | *Terminate* (terminar). Esta es la señal por defecto enviada por el comando **kill**. Si un programa está todavía lo suficientemente "vivo" para recibir señales, terminará. |
| 18 | CONT | *Continue* (continuar). Restaurará un proceso después de una señal **STOP** o **TSTP**. Esta señal es enviada por los comandos **bg** y **fg**. |
| 19 | STOP | *Stop* (detener). Esta señal hace que un proceso se detenga sin terminar. Al igual que la señal **KILL**, no se envía al proceso de destino y, por tanto, no puede ignorarse. |
| 20 | TSTP | *Terminal stop* (detención de terminal). Esta es la señal enviada por la terminal cuando se presiona **CTRL-Z**. A diferencia de la señal **STOP**, la señal **TSTP** es recibida por el programa, pero este puede optar por ignorarla. |

Probemos el comando **kill**.

```bash
[me@linuxbox ~]$ xlogo &  
[1] 13546  
[me@linuxbox ~]$ kill -1 13546  
[1]+  Hangup                  xlogo
```

En este ejemplo, iniciamos el programa **xlogo** en segundo plano y luego le enviamos una señal **HUP** con **kill**. El programa **xlogo** termina y el shell indica que el proceso en segundo plano ha recibido una señal de colgado. Es posible que tengamos que pulsar **ENTER** un par de veces antes de que aparezca el mensaje. Ten en cuenta que las señales pueden especificarse por número o por nombre, incluyendo el nombre precedido por las letras *SIG*.

```bash
[me@linuxbox ~]$ xlogo &  
[1] 13601  
[me@linuxbox ~]$ kill -INT 13601  
[1]+  Interrupt               xlogo  
[me@linuxbox ~]$ xlogo &  
[1] 13608  
[me@linuxbox ~]$ kill -SIGINT 13608  
[1]+  Interrupt               xlogo
```

Repite el ejemplo anterior y prueba las otras señales. Recuerda que también podemos usar jobspecs en lugar de PIDs.

Los procesos, al igual que los archivos, tienen propietarios, y debes ser el propietario de un proceso (o el superusuario) para enviarle señales con **kill**.

Además de la lista de señales tratadas hasta ahora, que son las que se utilizan con más frecuencia con **kill**, existen otras señales utilizadas con frecuencia por el sistema, como las que figuran en la Tabla 10-5.

**Tabla 10-5:** Otras Señales Comunes

| **Número** | **Nombre** | **Significado** |
| --- | --- | --- |
| 3 | QUIT | *Quit* (salir). |
| 11 | SEGV | *Segmentation violation* (violación de segmentación). Esta señal se envía si un programa hace un uso ilegal de la memoria; es decir, si intentó escribir en algún lugar donde no le estaba permitido escribir. |
| 28 | WINCH | *Window change* (cambio de ventana). Esta es la señal enviada por el sistema cuando una ventana cambia de tamaño. Algunos programas, como **top** y **less**, responderán a esta señal redibujándose para ajustarse a las nuevas dimensiones de la ventana. |

Para los curiosos, puedes mostrar una lista completa de señales con el siguiente comando:

```bash
[me@linuxbox ~]$ kill -l
```

#### **_Enviando Señales a Múltiples Procesos con killall_**

También es posible enviar señales a múltiples procesos que coincidan con un programa o nombre de usuario especificado utilizando el comando **killall**. Aquí está la sintaxis:

`killall [-u usuario] [-señal] nombre...`

Para demostrarlo, iniciaremos un par de instancias del programa **xlogo** y luego las terminaremos.

```bash
[me@linuxbox ~]$ xlogo &  
[1] 18801  
[me@linuxbox ~]$ xlogo &  
[2] 18802  
[me@linuxbox ~]$ killall xlogo  
[1]-  Terminated              xlogo  
[2]+  Terminated              xlogo
```

Recuerda que, al igual que con **kill**, debes tener privilegios de superusuario para enviar señales a procesos que no te pertenecen.

### **Apagando el Sistema**

El proceso de apagado del sistema implica la terminación ordenada de todos los procesos del sistema, así como la realización de algunas tareas vitales de mantenimiento (como la sincronización de todos los sistemas de archivos montados) antes de que el sistema se apague. Cuatro comandos pueden realizar esta función:

- **halt**
- **poweroff**
- **reboot**
- **shutdown**

Los tres primeros se explican por sí mismos y se suelen utilizar sin ninguna opción de línea de comandos. He aquí un ejemplo:

```bash
[me@linuxbox ~]$ sudo reboot
```

El comando **shutdown** es un poco más interesante. Con él, podemos especificar cuál de las acciones realizar (detener, apagar o reiniciar) y proporcionar un retraso de tiempo para el evento de apagado. Lo más frecuente es que se utilice así para detener el sistema:

```bash
[me@linuxbox ~]$ sudo shutdown -h now
```

o así para reiniciar el sistema:

```bash
[me@linuxbox ~]$ sudo shutdown -r now
```

El retraso puede especificarse de varias maneras. Consulta la página man de **shutdown** para más detalles. Una vez que se ejecuta el comando **shutdown**, se "transmite" un mensaje a todos los usuarios conectados advirtiéndoles del inminente evento.

### **Resumiendo**

La mayoría de los sistemas modernos cuentan con un mecanismo para gestionar múltiples procesos. Linux proporciona un rico conjunto de herramientas para este propósito. Dado que Linux es el sistema operativo para servidores más desplegado del mundo, esto tiene mucho sentido. A diferencia de otros sistemas, sin embargo, Linux se basa principalmente en herramientas de línea de comandos para la gestión de procesos. Aunque existen herramientas gráficas de procesos para Linux, las herramientas de línea de comandos son preferibles debido a su velocidad y ligereza. Aunque las herramientas de la interfaz gráfica de usuario (GUI) puedan parecer bonitas, a menudo crean mucha carga en el sistema por sí mismas, lo que en cierto modo derrota el propósito.
