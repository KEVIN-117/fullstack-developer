Ahora que sabemos cómo movernos por el sistema de archivos, es hora de hacer una visita guiada a nuestro sistema Linux. Sin embargo, antes de empezar, vamos a aprender algunos comandos más que serán útiles en el camino.

**ls** - Lista el contenido de un directorio.

**file** - Determina el tipo de archivo.

**less** - Visualiza el contenido de un archivo.

### **Más diversión con ls**

El comando **ls** es probablemente el más usado, y con razón. Con él, podemos ver el contenido de los directorios y determinar una variedad de atributos importantes de archivos y directorios. Como hemos visto, podemos simplemente introducir **ls** para obtener una lista de archivos y subdirectorios contenidos en el directorio de trabajo actual.

```bash
[me@linuxbox ~]$ ls  
Desktop Documents Music Pictures Public Templates Videos
```

Además del directorio de trabajo actual, podemos especificar el directorio a listar, así:

```bash
[me@linuxbox ~]$ ls /usr  
bin  games  include  lib  local  sbin  share  src
```

Incluso podemos especificar varios directorios. En el siguiente ejemplo, listamos tanto el directorio personal del usuario (simbolizado por el carácter `~`) como el directorio `/usr`:

```bash
[me@linuxbox ~]$ ls ~ /usr  
/home/me:  
Desktop Documents Music Pictures Public Templates Videos  
/usr:  
bin games incluyen lib local sbin share src
```

También podemos cambiar el formato de la salida para revelar más detalles.

```bash
[me@linuxbox ~]$ ls -l  
total 56  
drwxrwxr-x 2 me me 4096 2017-10-26 17:00 Desktop  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Documents  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Music  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Pictures  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Public  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Templates  
drwxrwxr-x 2 me me 4096 2017-10-26 17:20 Videos
```

Al añadir `-l` al comando, cambiamos la salida al formato largo.

#### **_Opciones y argumentos_**

Esto nos lleva a un punto muy importante sobre cómo funcionan la mayoría de los comandos. A menudo, los comandos van seguidos de una o más *opciones* que modifican su comportamiento y, además, de uno o más *argumentos*, los elementos sobre los que actúa el comando. Así que, la mayoría de los comandos se ven más o menos así:

`comando [opciones] [argumentos]`

La mayoría de los comandos usan opciones, que consisten en un solo carácter precedido por un guion, por ejemplo, `-l`. Sin embargo, muchos comandos, incluidos los del Proyecto GNU, también admiten *opciones largas*, que consisten en una palabra precedida de dos guiones. Además, muchos comandos permiten encadenar varias opciones cortas. En el siguiente ejemplo, el comando **ls** tiene dos opciones: la opción `l` para producir una salida de formato largo y la opción `t` para ordenar el resultado por el tiempo de modificación del archivo.

```bash
[me@linuxbox ~]$ ls -lt
```

Añadiremos la opción larga `--reverse` para invertir el orden de la clasificación.

```bash
[me@linuxbox ~]$ ls -lt --reverse
```

> [!NOTE]
> _Las opciones de comandos, como los nombres de archivo en Linux, son sensibles a mayúsculas y minúsculas._

El comando **ls** tiene un gran número de opciones posibles, las más comunes se enumeran en la Tabla 3-1.

### **Determinación del tipo de archivo con file**

A medida que exploramos el sistema, será útil saber qué contienen los archivos. Para ello, usaremos el comando **file** para determinar el tipo de archivo. Como comentamos antes, los nombres de archivo en Linux no están obligados a reflejar el contenido de un archivo. Aunque normalmente se esperaría que un nombre de archivo como *picture.jpg* contenga una imagen comprimida en JPEG, en Linux no es obligatorio. Podemos invocar el comando **file** de esta manera:

```bash
file nombre_archivo
```

Cuando se invoca, el comando **file** imprimirá una breve descripción del contenido del archivo. Por ejemplo:

```bash
[me@linuxbox ~]$ file picture.jpg  
picture.jpg: JPEG image data, JFIF standard 1.01
```

Hay muchos tipos de archivos. De hecho, una de las ideas comunes en sistemas operativos tipo Unix como Linux es que "todo es un archivo". A medida que avancemos con nuestras lecciones, veremos cuán cierta es esa afirmación.

Aunque muchos de los archivos de nuestro sistema son familiares, por ejemplo, MP3 y JPEG, hay muchos que son un poco menos evidentes y algunos que resultan bastante extraños.

### **Visualización del contenido de archivos con less**

El comando **less** es un programa para ver archivos de texto. En todo nuestro sistema Linux, hay muchos archivos que contienen texto legible para humanos. El programa **less** ofrece una forma cómoda de examinarlos.

¿Por qué querríamos examinar archivos de texto? Porque muchos de los archivos que contienen la configuración del sistema (llamados *archivos de configuración*) se almacenan en este formato, y poder leerlos nos da una idea de cómo funciona el sistema. Además, algunos de los programas reales que utiliza el sistema (llamados *scripts*) se almacenan en este formato. En capítulos posteriores, aprenderemos a editar archivos de texto para modificar la configuración del sistema y escribir nuestros propios scripts, pero por ahora solo miraremos su contenido.

El comando **less** se usa así:

```bash
less nombre_archivo
```

**¿QUÉ ES "TEXTO"?**

Hay muchas formas de representar información en un ordenador. Todos los métodos implican definir una relación entre la información y algunos números que se usarán para representarla. Los ordenadores, al fin y al cabo, solo entienden números, y todos los datos se convierten en representación numérica.

Algunos de estos sistemas de representación son muy complejos (como los archivos de vídeo comprimidos), mientras que otros son bastante simples. Uno de los más antiguos y sencillos se llama texto ASCII. ASCII (pronunciado "as-ki") es la abreviatura de *American Standard Code for Information Interchange*. Este es un esquema de codificación sencillo que se utilizó por primera vez en máquinas de Teletipo para mapear caracteres de teclado a números.

El texto es una simple asignación uno a uno de caracteres a números. Es muy compacto. Cincuenta caracteres de texto se traducen en cincuenta bytes de datos. Es importante entender que el texto solo contiene una simple asignación de caracteres a números. No es lo mismo que un documento de procesador de textos, como uno creado por Microsoft Word o LibreOffice Writer. Estos archivos, a diferencia del texto ASCII simple, contienen muchos elementos no textuales que se utilizan para describir su estructura y formato. Los archivos de texto ASCII simples contienen solo los caracteres y algunos códigos de control rudimentarios como tabulaciones, retornos de carro y saltos de línea.

En todo un sistema Linux, muchos archivos se almacenan en formato de texto, y existen muchas herramientas Linux que funcionan con archivos de texto. Incluso Windows reconoce la importancia de este formato. El conocido programa NOTEPAD.EXE es un editor para archivos de texto ASCII simples.

Una vez iniciado, el programa **less** nos permite desplazarnos hacia adelante y hacia atrás por un archivo de texto. Por ejemplo, para examinar el archivo que define todas las cuentas de usuario del sistema, introduce el siguiente comando:

```bash
[me@linuxbox ~]$ less /etc/passwd
```

Una vez que empieza el programa **less**, podemos ver el contenido del archivo. Si el archivo es más largo de una página, podemos desplazarnos hacia arriba y hacia abajo. Para salir de **less**, pulsa `q`.

La Tabla 3-3 enumera los comandos de teclado más comunes usados por **less**.

**Tabla 3-3:** Comandos de less

| **Mando** | **Acción** |
| --- | --- |
| `AV PÁG` o `espacio` | Desplázate una página hacia adelante |
| `RE PÁG` o `b` | Retrocede una página |
| `Flecha abajo` | Desplázate una línea hacia abajo |
| `Flecha arriba` | Desplázate una línea hacia arriba |
| `G` | Ir al final del archivo de texto |
| `1G` o `g` | Ir al inicio del archivo de texto |

| `q` | Salir de less |

**LESS ES MORE**

El programa **less** fue diseñado como un reemplazo mejorado de un programa Unix anterior llamado *more*. El nombre *less* (menos) es un juego de palabras con la expresión "less is more" (menos es más), un lema de arquitectos y diseñadores modernistas.

**less** pertenece a la clase de programas llamados *buscapersonas* (pagers), programas que permiten la visualización fácil de documentos de texto largos página por página. Mientras que el programa **more** solo podía avanzar, el programa **less** permite paginar tanto hacia adelante como hacia atrás y tiene muchas otras funciones también.

La disposición del sistema de archivos en un sistema Linux es muy similar a la que se encuentra en otros sistemas tipo Unix. No todas las distribuciones de Linux cumplen exactamente con el estándar, pero la mayoría se acercan bastante.

Esto nos dará la oportunidad de practicar nuestras habilidades de navegación. ### **Enlaces simbólicos**

Al mirar alrededor, es probable que veamos un listado de directorio (por ejemplo, `/lib`) con una entrada como esta:

```bash
lrwxrwxrwx 1 root root 11 2018-08-11 07:34 libc.so.6 -> libc-2.6.so
```

¿Te has fijado en cómo la primera letra del listado es `l` y la entrada parece tener dos nombres de archivo? Este es un tipo especial de archivo llamado *enlace simbólico* (también conocido como *enlace blando* o *symlink*). En la mayoría de los sistemas tipo Unix, es posible que un archivo sea referenciado por varios nombres. Aunque el valor de esto no sea evidente, es realmente una función útil.

Imagina este escenario: un programa requiere el uso de algún recurso compartido contenido en un archivo llamado "foo", pero "foo" cambia de versión con frecuencia. Sería bueno incluir el número de versión en el nombre del archivo para que el administrador u otra persona interesada pueda ver qué versión de "foo" está instalada. Esto presenta un problema. Si cambiamos el nombre del recurso compartido, tenemos que localizar todos los programas que puedan usarlo y cambiarlos para buscar un nuevo nombre de recurso cada vez que se instala una nueva versión del recurso. Eso no suena nada divertido.

Aquí es donde los enlaces simbólicos salvan el día. Supongamos que instalamos la versión 2.6 de "foo", que tiene el nombre de archivo "foo-2.6", y luego creamos un enlace simbólico llamado simplemente "foo" que apunta a "foo-2.6". Esto significa que cuando un programa abre el archivo "foo", en realidad está abriendo el archivo "foo-2.6". Ahora todos están contentos. Los programas que dependen de "foo" pueden encontrarlo, y aún así podemos ver qué versión real está instalada. Cuando llega el momento de actualizar a "foo-2.7", simplemente añadimos el archivo a nuestro sistema, eliminamos el enlace simbólico "foo" y creamos uno nuevo que apunte a la nueva versión. Esto no solo resuelve el problema de la actualización de versión, sino que también nos permite mantener ambas versiones en nuestra máquina. Imagina que "foo-2.7" tiene un error (¡malditos desarrolladores!), y tenemos que volver a la versión antigua. De nuevo, simplemente eliminamos el enlace simbólico que apunta a la nueva versión y creamos un nuevo enlace simbólico que apunta a la versión antigua.

El listado de directorios al principio de esta sección (del directorio `/lib` de un sistema Fedora) muestra un enlace simbólico llamado `libc.so.6` que apunta a un archivo de biblioteca compartida llamado *libc-2.6.so*. Esto significa que los programas que buscan *libc.so.6* realmente recibirán el archivo *libc-2.6.so*. Aprenderemos a crear enlaces simbólicos en el próximo capítulo.

### **Enlaces Duros**

Ya que hablamos de enlaces, debemos mencionar que existe un segundo tipo de enlace llamado *enlaces duros*. Los enlaces duros también permiten que los archivos tengan varios nombres, pero lo hacen de forma diferente. Hablaremos más sobre las diferencias entre los enlaces simbólicos y los duros en el próximo capítulo.
