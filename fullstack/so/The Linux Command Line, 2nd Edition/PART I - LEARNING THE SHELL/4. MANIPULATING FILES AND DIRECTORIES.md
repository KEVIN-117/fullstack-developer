¡A estas alturas, estamos listos para un trabajo de verdad! Este capítulo presentará cinco de los comandos de Linux más utilizados con frecuencia. Los siguientes comandos se utilizan para manipular tanto archivos como directorios:

**cp** - Copia archivos y directorios.

**mv** - Mueve o renombra archivos y directorios.

**mkdir** - Crea directorios.

**rm** - Elimina archivos y directorios.

**ln** - Crea enlaces duros y simbólicos.

Ahora bien, para ser franco, algunas de las tareas realizadas por estos comandos se pueden hacer más fácilmente con un gestor gráfico de archivos. Con un gestor de archivos, podemos arrastrar y soltar un archivo de un directorio a otro, cortar y pegar archivos, eliminar archivos, y así sucesivamente. ¿Entonces por qué usar estos antiguos programas de línea de comandos?

La respuesta es poder y flexibilidad. Aunque es fácil realizar manipulaciones sencillas de archivos con un gestor gráfico, las tareas complicadas pueden ser más sencillas con los programas de línea de comandos. Por ejemplo, ¿cómo podríamos copiar todos los archivos HTML de un directorio a otro pero copiar solo los archivos que no existen en el directorio de destino o que son más recientes que las versiones del directorio de destino? Es bastante difícil con un gestor de archivos, pero bastante fácil con la línea de comandos.

```bash
cp -u *.html destino
```

### **Comodines**

Antes de empezar a usar nuestros comandos, necesitamos hablar de una función del shell que hace que estos comandos sean tan potentes. Como el shell utiliza tanto los nombres de archivo, proporciona caracteres especiales para ayudarte a especificar rápidamente grupos de nombres de archivo. Estos caracteres especiales se llaman *comodines* (wildcards). Usar comodines (también conocido como *globbing*) te permite seleccionar nombres de archivos basándote en patrones de caracteres. La Tabla 4-1 enumera los comodines y lo que seleccionan.

**Tabla 4-1:** Comodines

| **Comodín** | **Significado** |
| --- | --- |
| `*` | Coincide con cualquier carácter. |
| `?` | Coincide con cualquier carácter individual. |
| `[caracteres]` | Coincide con cualquier carácter que sea miembro del conjunto *caracteres*. |
| `[!caracteres]` | Coincide con cualquier carácter que NO sea miembro del conjunto *caracteres*. |
| `[[:clase:]]` | Coincide con cualquier carácter que pertenezca a la *clase* especificada. |

La Tabla 4-2 enumera las clases de caracteres más usadas.

**Tabla 4-2:** Clases de caracteres comúnmente utilizadas

| **Clase de carácter** | **Significado** |
| --- | --- |
| `[:alnum:]` | Coincide con cualquier carácter alfanumérico. |
| `[:alpha:]` | Coincide con cualquier carácter alfabético. |
| `[:digit:]` | Coincide con cualquier dígito (número). |
| `[:lower:]` | Coincide con cualquier letra minúscula. |
| `[:upper:]` | Coincide con cualquier letra mayúscula. |

El uso de comodines permite construir criterios de selección sofisticados para los nombres de archivos. La Tabla 4-3 ofrece algunos ejemplos de patrones y con qué coinciden.

**Tabla 4-3:** Ejemplos de comodines

| **Patrón** | **Coincidencias** |
| --- | --- |
| `*` | Todos los archivos. |
| `g*` | Cualquier archivo que empiece por *g*. |
| `b*.txt` | Cualquier archivo que empiece por *b* seguido de cualquier carácter y termine con *.txt*. |
| `Data???` | Cualquier archivo que comience con *Data* seguido exactamente de tres caracteres. |
| `[abc]*` | Cualquier archivo que comience por una *a*, una *b* o una *c*. |
| `BACKUP.[0-9][0-9][0-9]` | Cualquier archivo que comience con *BACKUP.* seguido exactamente de tres números. |
| `[[:upper:]]*` | Cualquier archivo que comience con una letra mayúscula. |
| `[![:digit:]]*` | Cualquier archivo que no empiece por un número. |
| `*[[:lower:]123]` | Cualquier archivo que termine en una letra minúscula o en los números 1, 2 o 3. |

**LOS COMODINES TAMBIÉN FUNCIONAN EN LA INTERFAZ GRÁFICA**

Los comodines son especialmente valiosos no solo porque se usan con mucha frecuencia en la línea de comandos, sino porque también están soportados por algunos gestores gráficos de archivos.

- En Nautilus (el gestor de archivos de GNOME), puedes seleccionar archivos pulsando `CTRL-S` e introduciendo un patrón de selección de archivos con comodines, y los archivos del directorio que se muestra actualmente serán seleccionados.
- En algunas versiones de Dolphin y Konqueror (los gestores de archivos de KDE), puedes introducir comodines directamente en la barra de ubicación. Por ejemplo, si quieres ver todos los archivos que empiezan por una *u* minúscula en el directorio */usr/bin*, introduce `/usr/bin/u*` en la barra de ubicación y mostrará el resultado.

Muchas ideas originales que se encontraban en la interfaz de línea de comandos también se integran en la interfaz gráfica. Es una de las muchas cosas que hacen que el escritorio Linux sea tan potente.

Los comodines pueden usarse con cualquier comando que acepte nombres de archivo como argumentos, pero hablaremos más de eso en el Capítulo 7.

### **mkdir — Crear directorios**

El comando **mkdir** se utiliza para crear directorios. Funciona así:

```bash
mkdir directorio...
```

Nótese que cuando tres puntos siguen a un argumento en la descripción de un comando (como en el ejemplo anterior), significa que el argumento puede repetirse. Así, la siguiente orden:

```bash
mkdir dir1
```

crearía un único directorio llamado *dir1*. Esta orden:

```bash
mkdir dir1 dir2 dir3
```

crearía tres directorios llamados *dir1*, *dir2* y *dir3*.

### **cp — Copiar archivos y directorios**

El comando **cp** copia archivos o directorios. Se puede usar de dos maneras diferentes. Lo siguiente:

```bash
cp elemento1 elemento2
```

copia el único archivo o directorio *elemento1* al archivo o directorio *elemento2*. Esta orden:

```bash
cp elemento... directorio
```

copia varios elementos (ya sean archivos o directorios) en un *directorio*.

#### **_Opciones útiles y ejemplos_**

La Tabla 4-4 describe algunas de las opciones más usadas (la opción corta y la opción larga equivalente) para **cp**.

**Tabla 4-4:** Opciones de cp

| **Opción** | **Significado** |
| --- | --- |
| `-a`, `--archive` | Copia los archivos y directorios y todos sus atributos, incluyendo la propiedad y los permisos. Normalmente, las copias adoptan los atributos predeterminados del usuario que realiza la copia. Echaremos un vistazo a los permisos de archivo en el Capítulo 9. |
| `-i`, `--interactive` | Antes de sobrescribir un archivo existente, solicita al usuario que confirme. **Si esta opción no está especificada, cp sobrescribirá silenciosamente (es decir, sin aviso) los archivos.** |
| `-r`, `--recursive` | Copia recursivamente directorios y su contenido. Esta opción (o la opción `-a`) es necesaria al copiar directorios. |
| `-u`, `--update` | Al copiar archivos de un directorio a otro, solo copia los archivos que no existan o sean más recientes que los archivos existentes en el directorio de destino. Esto es útil al copiar grandes cantidades de archivos, ya que se saltan archivos que no necesitan ser copiados. |
| `-v`, `--verbose` | Muestra mensajes informativos a medida que se realiza la copia. |

La Tabla 4-5 ofrece algunos ejemplos de estas opciones comúnmente utilizadas.

**Tabla 4-5:** Ejemplos de cp

| **Comando** | **Resultados** |
| --- | --- |
| `cp file1 file2` | Copia *file1* a *file2*. Si existe *file2*, se sobrescribe con el contenido de *file1*. Si *file2* no existe, se crea. |
| `cp -i file1 file2` | Igual que el comando anterior, excepto que si existe *file2*, se le solicita al usuario confirmación antes de que se sobrescriba. |
| `cp file1 file2 dir1` | Copia *file1* y *file2* en el directorio *dir1*. El directorio *dir1* debe existir previamente. |
| `cp dir1/* dir2` | Usando un comodín, copia todos los archivos de *dir1* en *dir2*. El directorio *dir2* debe existir previamente. |
| `cp -r dir1 dir2` | Copia el contenido del directorio *dir1* al directorio *dir2*. Si el directorio *dir2* no existe, se crea y, tras la copia, contendrá el mismo contenido que el directorio *dir1*. Si el directorio *dir2* existe, entonces el directorio *dir1* (y su contenido) se copiará dentro de *dir2*. |

### **mv — Mover y renombrar archivos**

El comando **mv** realiza tanto el movimiento como el renombramiento de archivos, dependiendo de cómo se utilice. En cualquier caso, el nombre original del archivo ya no existe tras la operación. **mv** se usa de manera muy similar a **cp**, como se muestra aquí:

```bash
mv elemento1 elemento2
```

mueve o renombra el archivo o directorio *elemento1* a *elemento2*. También se utiliza de la siguiente manera:

```bash
mv elemento... directorio
```

para mover uno o más elementos de un directorio a otro.

#### **_Opciones útiles y ejemplos_**

**mv** comparte muchas de las mismas opciones que **cp**, como se describe en la Tabla 4-6.

**Tabla 4-6:** Opciones de mv

| **Opción** | **Significado** |
| --- | --- |
| `-i`, `--interactive` | Antes de sobrescribir un archivo existente, solicita al usuario que confirme. **Si no se especifica esta opción, mv sobrescribirá archivos en silencio.** |
| `-u`, `--update` | Al mover archivos de un directorio a otro, solo mueve los que no existan o sean más recientes que los archivos existentes correspondientes en el directorio de destino. |
| `-v`, `--verbose` | Muestra mensajes informativos a medida que se realiza el movimiento. |

La Tabla 4-7 ofrece algunos ejemplos de cómo usar el comando **mv**.

**Tabla 4-7:** Ejemplos de mv

| **Comando** | **Resultados** |
| --- | --- |
| `mv file1 file2` | Mueve *file1* a *file2*. Si existe *file2*, se sobrescribe con el contenido de *file1*. Si *file2* no existe, se crea. En cualquier caso, *file1* deja de existir. |
| `mv -i file1 file2` | Igual que el comando anterior, salvo que si existe *file2*, se le solicita al usuario confirmación antes de que se sobrescriba. |
| `mv file1 file2 dir1` | Mueve *file1* y *file2* al directorio *dir1*. El directorio *dir1* debe existir previamente. |
| `mv dir1 dir2` | Si el directorio *dir2* no existe, crea el directorio *dir2*, mueve el contenido del directorio *dir1* a *dir2* y elimina el directorio *dir1*. Si existe el directorio *dir2*, mueve el directorio *dir1* (y su contenido) dentro del directorio *dir2*. |

### **rm — Eliminar archivos y directorios**

El comando **rm** se utiliza para eliminar (borrar) archivos y directorios, como se muestra aquí:

```bash
rm elemento...
```
donde *elemento* es uno o más archivos o directorios.

#### **_Opciones útiles y ejemplos_**

La Tabla 4-8 describe algunas de las opciones comunes para **rm**.

**Tabla 4-8:** Opciones de rm

| **Opción** | **Significado** |
| --- | --- |
| `-i`, `--interactive` | Antes de eliminar un archivo existente, solicita al usuario que confirme. **Si esta opción no está especificada, rm eliminará archivos en silencio.** |
| `-r`, `--recursive` | Elimina directorios recursivamente. Esto significa que si un directorio que se elimina tiene subdirectorios, también los eliminará. Para eliminar un directorio, esta opción debe especificarse. |
| `-f`, `--force` | Ignora archivos inexistentes y no pregunta. Esto anula la opción `--interactive`. |
| `-v`, `--verbose` | Muestra mensajes informativos a medida que se realiza la eliminación. |

**¡TEN CUIDADO CON RM!**

Los sistemas operativos tipo Unix como Linux no tienen un comando para "desborrar". Una vez que borras algo con **rm**, desaparece. Linux asume que eres listo y sabes lo que haces.

Ten especial cuidado con los comodines. Considera este ejemplo clásico. Supongamos que solo quieres eliminar los archivos HTML de un directorio. Para ello, escribes lo siguiente:

```bash
rm *.html
```

Esto es correcto, pero si accidentalmente colocas un espacio entre el `*` y el `.html` así:

```bash
rm * .html
```

El comando **rm** eliminará todos los archivos del directorio y luego se quejará de que no hay ningún archivo llamado `.html`.

Aquí tienes un consejo útil: siempre que uses comodines con **rm** (además de revisar bien tu escritura), prueba primero el comodín con **ls**. Esto te permitirá ver los archivos que se eliminarán. Luego pulsa la flecha hacia arriba para recuperar el comando y reemplaza **ls** por **rm**.

La Tabla 4-9 ofrece algunos ejemplos de uso del comando **rm**.

**Tabla 4-9:** Ejemplos de rm

| **Comando** | **Resultados** |
| --- | --- |
| `rm file1` | Elimina *file1* en silencio. |
| `rm -i file1` | Igual que el comando anterior, excepto que se solicita al usuario la confirmación antes de que se realice la eliminación. |
| `rm -r file1 dir1` | Elimina *file1* y *dir1* y su contenido. |
| `rm -rf file1 dir1` | Igual que el comando anterior, excepto que si no existe ni *file1* ni *dir1*, **rm** continuará en silencio. |

### **ln — Crear enlaces**

El comando **ln** se utiliza para crear enlaces duros o simbólicos. Se utiliza de dos maneras. Lo siguiente crea un enlace duro:

```bash
ln archivo enlace
```

Lo siguiente crea un enlace simbólico:

```bash
ln -s elemento enlace
```

donde *elemento* es un archivo o un directorio.

#### **_Enlaces Duros_**

Los enlaces duros son la forma original de crear enlaces en Unix, en comparación con los enlaces simbólicos, que son más modernos. Por defecto, cada archivo tiene un único enlace duro que le da nombre al archivo. Cuando creamos un enlace duro, generamos una entrada adicional en el directorio para un archivo. Los enlaces duros tienen dos limitaciones importantes:

- Un enlace duro no puede referenciar un archivo fuera de su propio sistema de archivos. Esto significa que un enlace no puede referenciar un archivo que no esté en la misma partición de disco que el propio enlace.
- Un enlace duro no puede hacer referencia a un directorio.

Un enlace duro es indistinguible del propio archivo. A diferencia de un enlace simbólico, cuando listas un directorio que contiene un enlace duro, no verás ninguna indicación especial del enlace. Cuando se elimina un enlace duro, se elimina la entrada, pero el contenido del propio archivo sigue existiendo (es decir, su espacio no se desasigna) hasta que todos los enlaces al archivo se eliminan.

Es importante conocer los enlaces duros porque podrías encontrarlos de vez en cuando, pero la práctica moderna prefiere los enlaces simbólicos, que abordaremos a continuación.

#### **_Enlaces Simbólicos_**

Se crearon enlaces simbólicos para superar las limitaciones de los enlaces duros. Funcionan creando un tipo especial de archivo que contiene un puntero de texto al archivo o directorio referenciado. En este sentido, funcionan de forma muy similar a un acceso directo de Windows, aunque, por supuesto, son muchos años anteriores a esa función de Windows.

Un archivo al que apunta un enlace simbólico y el propio enlace simbólico son en gran medida indistinguibles entre sí. Por ejemplo, si escribes algo en el enlace simbólico, se escribe en el archivo referenciado. Sin embargo, cuando eliminas un enlace simbólico, solo se elimina el *enlace*, no el *archivo* en sí. Si el archivo se elimina antes del enlace simbólico, el enlace seguirá existiendo pero no apuntará a nada. En este caso, se dice que el enlace está *roto*. En muchas implementaciones, el comando **ls** mostrará enlaces rotos en un color distintivo, como el rojo, para revelar su presencia.

El concepto de enlaces puede parecer confuso, pero aguanta. Vamos a probar todo esto y, idealmente, se aclarará.

### **Construyendo un patio de juegos**

Como vamos a hacer manipulación de archivos de verdad, vamos a construir un lugar seguro para "jugar" con nuestros comandos. Primero necesitamos un directorio para trabajar. Crearemos uno en nuestro directorio personal y lo llamaremos *playground*.

#### **_Creación de Directorios_**

El comando **mkdir** se utiliza para crear un directorio. Para crear nuestro directorio *playground*, primero nos aseguraremos de estar en nuestro directorio personal y luego crearemos el nuevo directorio.

```bash
[me@linuxbox ~]$ cd  
[me@linuxbox ~]$ mkdir playground
```

Para hacer nuestro patio de juegos un poco más interesante, creemos un par de directorios dentro llamados *dir1* y *dir2*. Para ello, cambiaremos nuestro directorio de trabajo actual a *playground* y ejecutaremos otro **mkdir**.

```bash
[me@linuxbox ~]$ cd playground  
[me@linuxbox playground]$ mkdir dir1 dir2
```

Fíjate que el comando **mkdir** acepta múltiples argumentos, permitiéndonos crear ambos directorios con un solo comando.

#### **_Copiar archivos_**

Ahora, vamos a meter algunos datos en nuestro patio de juegos. Lo haremos copiando un archivo. Usando el comando **cp**, copiaremos el archivo *passwd* del directorio */etc* al directorio de trabajo actual.

```bash
[me@linuxbox playground]$ cp /etc/passwd .
```

Fíjate cómo usamos la abreviatura para el directorio de trabajo actual, el punto final. Así que ahora, si hacemos un **ls**, veremos nuestro archivo.

```bash
[me@linuxbox playground]$ ls -l  
total 12  
drwxrwxr-x 2 me me 4096 2018-01-10 16:40 dir1  
drwxrwxr-x 2 me me 4096 2018-01-10 16:40 dir2  
-rw-r--r-- 1 me me 1650 2018-01-10 16:07 passwd
```

Ahora, solo por diversión, vamos a repetir la copia usando la opción `-v` (*verbose*) para ver qué hace.

```bash
[me@linuxbox playground]$ cp -v /etc/passwd .  
`/etc/passwd' -> `./passwd'
```

El comando **cp** realizó la copia de nuevo, pero esta vez mostró un mensaje conciso indicando qué operación estaba realizando. Fíjate que **cp** sobrescribió la primera copia sin previo aviso. De nuevo, esto es un caso de **cp** asumiendo que sabemos lo que hacemos. Para recibir una advertencia, incluiremos la opción `-i` (interactiva).

```bash
[me@linuxbox playground]$ cp -i /etc/passwd .  
cp: overwrite `./passwd'?
```

Responder al prompt introduciendo una `y` hará que el archivo se sobrescriba; cualquier otro carácter hará que **cp** deje el archivo intacto.

#### **_Moviendo y renombrando archivos_**

Ahora, el nombre *passwd* no parece muy juguetón y esto es un patio de juegos, así que vamos a cambiarlo por otra cosa.

```bash
[me@linuxbox playground]$ mv passwd fun
```

Vamos a repartir un poco la diversión moviendo nuestro archivo renombrado a cada uno de los directorios y de vuelta. Lo siguiente lo mueve primero al directorio *dir1*:

```bash
[me@linuxbox playground]$ mv fun dir1
```

A continuación, se mueve de *dir1* a *dir2*:

```bash
[me@linuxbox playground]$ mv dir1/fun dir2
```

Finalmente, este comando lo devuelve al directorio de trabajo actual:

```bash
[me@linuxbox playground]$ mv dir2/fun .
```

A continuación, veamos el efecto de **mv** en los directorios. Primero moveremos nuestro archivo de datos a *dir1* de nuevo, así:

```bash
[me@linuxbox playground]$ mv fun dir1
```

Luego movemos *dir1* a *dir2* y lo confirmamos con **ls**.

```bash
[me@linuxbox playground]$ mv dir1 dir2  
[me@linuxbox playground]$ ls -l dir2  
total 4  
drwxrwxr-x 2 me me 4096 2018-01-11 06:06 dir1  
[me@linuxbox playground]$ ls -l dir2/dir1  
total 4  
-rw-r--r-- 1 me me 1650 2018-01-10 16:33 fun
```

Ten en cuenta que, como *dir2* ya existía, **mv** movió *dir1* dentro de *dir2*. Si el *dir2* no hubiera existido, **mv** habría renombrado el *dir1* como *dir2*. Por último, vamos a volver a poner todo en su sitio.

```bash
[me@linuxbox playground]$ mv dir2/dir1 .  
[me@linuxbox playground]$ mv dir1/fun .
```

#### **_Creación de enlaces duros_**

Ahora probaremos algunos enlaces. Primero crearemos algunos enlaces duros a nuestro archivo de datos, así:

```bash
[me@linuxbox playground]$ ln fun fun-hard  
[me@linuxbox playground]$ ln fun dir1/fun-hard  
[me@linuxbox playground]$ ln fun dir2/fun-hard
```

Así que ahora tenemos cuatro instancias del archivo *fun*. Echemos un vistazo a nuestro directorio *playground*.

```bash
[me@linuxbox playground]$ ls -l  
total 16  
drwxrwxr-x 2 me me 4096 2018-01-14 16:17 dir1  
drwxrwxr-x 2 me me 4096 2018-01-14 16:17 dir2  
-rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun  
-rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun-hard
```

Una cosa que notamos es que los segundos campos en los listados para *fun* y para *fun-hard* contienen un 4, que es el número de enlaces duros que ahora existen para el archivo. Recuerda que un archivo siempre tendrá al menos un enlace porque el nombre del archivo se crea mediante un enlace. Entonces, ¿cómo sabemos que *fun* y *fun-hard* son, en realidad, el mismo archivo? En este caso, **ls** no es muy útil. Aunque podemos ver que *fun* y *fun-hard* tienen el mismo tamaño (campo 5), nuestra lista no ofrece forma de asegurarlo. Para resolver este problema, tendremos que profundizar un poco más.

Cuando piensas en enlaces duros, es útil imaginar que los archivos están compuestos por dos partes:

- La parte de datos que contiene el contenido del archivo.
- La parte del nombre que contiene el nombre del archivo.

Cuando creamos enlaces duros, en realidad estamos creando partes adicionales de nombre que se refieren todas a la misma parte de datos. El sistema asigna una cadena de bloques de disco a lo que se llama un *inodo*, que luego se asocia con la parte del nombre. Por tanto, cada enlace duro se refiere a un inodo específico que contiene el contenido del archivo.

El comando **ls** tiene una forma de revelar esta información. Se invoca con la opción `-i`.

```bash
[me@linuxbox playground]$ ls -li  
total 16  
12353539 drwxrwxr-x 2 me me 4096 2018-01-14 16:17 dir1  
12353540 drwxrwxr-x 2 me me 4096 2018-01-14 16:17 dir2  
12353538 -rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun  
12353538 -rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun-hard
```

En esta versión del listado, el primer campo es el número de inodo y, como podemos ver, tanto *fun* como *fun-hard* comparten el mismo número de inodo, lo que confirma que son el mismo archivo.

#### **_Creación de Enlaces Simbólicos_**

Se crearon enlaces simbólicos para superar las dos desventajas de los enlaces duros:

- Los enlaces duros no pueden abarcar dispositivos físicos.
- Los enlaces duros no pueden referenciar directorios, solo archivos.

Los enlaces simbólicos son un tipo especial de archivo que contiene un puntero de texto al archivo o directorio de destino.
Crear enlaces simbólicos es similar a crear enlaces duros.

```bash
[me@linuxbox playground]$ ln -s fun fun-sym  
[me@linuxbox playground]$ ln -s ../fun dir1/fun-sym  
[me@linuxbox playground]$ ln -s ../fun dir2/fun-sym
```

El primer ejemplo es bastante sencillo; simplemente añadimos la opción `-s` para crear un enlace simbólico en lugar de un enlace duro. ¿Pero qué pasa con los dos siguientes? Recuerda que cuando creamos un enlace simbólico, estamos creando una descripción en texto de dónde está el archivo destino respecto al enlace simbólico. Es más fácil de ver si miramos la salida de **ls**, que se muestra aquí:

```bash
[me@linuxbox playground]$ ls -l dir1  
total 4  
-rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun-hard  
lrwxrwxrwx 1 me me    6 2018-01-15 15:17 fun-sym -> ../fun
```

La inclusión de *fun-sym* en *dir1* muestra que es un enlace simbólico por la `l` inicial en el primer campo y que apunta a `../fun`, lo cual es correcto. En relación con la ubicación de *fun-sym*, *fun* está en el directorio que está arriba. Fíjate también que la longitud del archivo de enlace simbólico es 6, el número de caracteres en la cadena `../fun`, en vez de la longitud del archivo al que apunta.

Al crear enlaces simbólicos, puedes usar nombres de ruta absolutos, como se muestra aquí:

```bash
[me@linuxbox playground]$ ln -s /home/me/playground/fun dir1/fun-sym
```

o nombres de ruta relativos, como hicimos en nuestro ejemplo anterior. En la mayoría de los casos, usar nombres de ruta relativos es más deseable porque permite que un árbol de directorios que contiene enlaces simbólicos y sus archivos referenciados sea renombrado y/o movido sin romper los enlaces.

Además de los archivos normales, los enlaces simbólicos también pueden referenciar directorios.

```bash
[me@linuxbox playground]$ ln -s dir1 dir1-sym  
[me@linuxbox playground]$ ls -l  
total 16  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir1  
lrwxrwxrwx 1 me me    4 2018-01-16 14:45 dir1-sym -> dir1  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir2  
-rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun  
-rw-r--r-- 4 me me 1650 2018-01-10 16:33 fun-hard  
lrwxrwxrwx 1 me me    3 2018-01-15 15:15 fun-sym -> fun
```

#### **_Eliminación de archivos y directorios_**

Como mencionamos antes, el comando **rm** se usa para eliminar archivos y directorios. Vamos a usarlo para limpiar un poco nuestro patio de juegos. Primero, borremos uno de nuestros enlaces duros.

```bash
[me@linuxbox playground]$ rm fun-hard  
[me@linuxbox playground]$ ls -l  
total 12  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir1  
lrwxrwxrwx 1 me me    4 2018-01-16 14:45 dir1-sym -> dir1  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir2  
-rw-r--r-- 3 me me 1650 2018-01-10 16:33 fun  
lrwxrwxrwx 1 me me    3 2018-01-15 15:15 fun-sym -> fun
```

Funcionó como esperaba. El archivo *fun-hard* ha desaparecido, y el recuento de enlaces mostrado para *fun* se reduce de cuatro a tres, como indica el segundo campo del listado del directorio. A continuación, borraremos el archivo *fun* y, solo para disfrutar, incluiremos la opción `-i` para mostrar qué hace.

```bash
[me@linuxbox playground]$ rm -i fun  
rm: remove regular file `fun'?
```

Introduce `y` en el aviso y el archivo se elimina. Pero veamos ahora la salida de **ls**. ¿Has notado lo que pasó con *fun-sym*? Como es un enlace simbólico que apunta a un archivo que ya no existe, el enlace está roto.

```bash
[me@linuxbox playground]$ ls -l  
total 8  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir1  
lrwxrwxrwx 1 me me    4 2018-01-16 14:45 dir1-sym -> dir1  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir2  
lrwxrwxrwx 1 me me    3 2018-01-15 15:15 fun-sym -> fun
```

La mayoría de las distribuciones de Linux configuran **ls** para mostrar enlaces rotos. La presencia de un enlace roto no es peligrosa en sí misma, pero sí es bastante desordenada. Si intentamos usar un enlace roto, veremos esto:

```bash
[me@linuxbox playground]$ less fun-sym  
fun-sym: No such file or directory
```

Vamos a limpiar un poco. Aquí eliminaremos los enlaces simbólicos:

```bash
[me@linuxbox playground]$ rm fun-sym dir1-sym  
[me@linuxbox playground]$ ls -l  
total 8  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir1  
drwxrwxr-x 2 me me 4096 2018-01-15 15:17 dir2
```

Una cosa a recordar sobre los enlaces simbólicos es que la mayoría de las operaciones de archivo se realizan en el destino del enlace, no en el enlace en sí. **rm** es una excepción. Cuando eliminas un enlace, es el enlace el que se elimina, no el objetivo.

Por último, quitaremos nuestro patio de juegos. Para ello, volveremos a nuestro directorio personal y usaremos **rm** con la opción recursiva (`-r`) para eliminar *playground* y todo su contenido, incluidos sus subdirectorios.

```bash
[me@linuxbox playground]$ cd  
[me@linuxbox ~]$ rm -r playground
```

**CREACIÓN DE ENLACES SIMBÓLICOS CON LA INTERFAZ GRÁFICA**

Los gestores de archivos tanto en GNOME como en KDE proporcionan un método sencillo y automático para crear enlaces simbólicos. Con GNOME, mantener pulsadas las teclas `CTRL-SHIFT` mientras arrastras un archivo creará un enlace en lugar de copiar (o mover) el archivo. En KDE, aparece un pequeño menú cada vez que se deja caer un archivo, ofreciendo la opción de copiar, mover o enlazar el archivo.
