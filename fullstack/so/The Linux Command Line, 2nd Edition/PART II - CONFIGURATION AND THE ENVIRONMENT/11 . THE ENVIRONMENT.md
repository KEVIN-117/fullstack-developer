Como hemos discutido anteriormente, el shell mantiene un cuerpo de información durante nuestra sesión de shell llamado *entorno* (*environment*). Los programas utilizan los datos almacenados en el entorno para determinar datos sobre la configuración del sistema. Si bien la mayoría de los programas utilizan *archivos de configuración* para almacenar la configuración de los programas, algunos programas también buscan valores almacenados en el entorno para ajustar su comportamiento. Sabiendo esto, podemos utilizar el entorno para personalizar nuestra experiencia con el shell.

En este capítulo, trabajaremos con los siguientes comandos:

**printenv** - Imprime parte o todo el entorno.

**set** - Establece las opciones del shell.

**export** - Exporta el entorno a programas ejecutados posteriormente.

**alias** - Crea un alias para un comando.

### **¿Qué se almacena en el entorno?**

El shell almacena dos tipos básicos de datos en el entorno; aunque, con **bash**, los tipos son en gran medida indistinguibles. Son las *variables de entorno* (*environment variables*) y las *variables de shell* (*shell variables*). Las variables de shell son trozos de datos colocados allí por **bash**, y las variables de entorno son todo lo demás. Además de las variables, el shell almacena algunos datos programáticos, a saber, los *alias* y las *funciones del shell*. Cubrimos los alias en el Capítulo 5 y cubriremos las funciones del shell (que están relacionadas con el scripting del shell) en la Parte IV de este libro.

#### **_Examinando el Entorno_**

Para ver lo que se almacena en el entorno, podemos utilizar el comando interno **set** de **bash** o el programa **printenv**. El comando **set** mostrará tanto las variables de shell como las de entorno, mientras que **printenv** solo mostrará estas últimas. Dado que la lista de contenidos del entorno será bastante larga, es mejor canalizar la salida de cualquiera de los dos comandos a **less**.

```bash
[me@linuxbox ~]$ printenv | less
```

Lo que vemos es una lista de variables de entorno y sus valores. Por ejemplo, vemos una variable llamada **USER**, que contiene el valor `me`. El comando **printenv** también puede listar el valor de una variable específica.

```bash
[me@linuxbox ~]$ printenv USER  
me
```

El comando **set**, cuando se utiliza sin opciones ni argumentos, mostrará tanto las variables de shell como las de entorno, así como cualquier función de shell definida. A diferencia de **printenv**, su salida está cortésmente ordenada en orden alfabético.

```bash
[me@linuxbox ~]$ set | less
```

También es posible ver el contenido de una variable utilizando el comando **echo**, de esta manera:

```bash
[me@linuxbox ~]$ echo $HOME  
/home/me
```

Un elemento del entorno que ni **set** ni **printenv** muestran son los alias. Para verlos, introduce el comando **alias** sin argumentos.

```bash
[me@linuxbox ~]$ alias  
alias l.=’ls -d .* --color=tty’  
alias ll=’ls -l --color=tty’  
alias ls=’ls --color=tty’  
alias vi=’vim’  
alias which=’alias | /usr/bin/which --tty-only --read-alias --show-dot --show-tilde’
```

### **¿Cómo se establece el entorno?**

Cuando iniciamos sesión en el sistema, el programa **bash** se inicia y lee una serie de scripts de configuración llamados *archivos de inicio* (*startup files*), que definen el entorno por defecto compartido por todos los usuarios. A esto le siguen más archivos de inicio en nuestro directorio personal que definen nuestro entorno personal. La secuencia exacta depende del tipo de sesión de shell que se esté iniciando. Hay dos tipos:

**Una sesión de shell de inicio de sesión** (*login shell session*): Es aquella en la que se nos pide nuestro nombre de usuario y contraseña. Esto sucede cuando iniciamos una sesión de consola virtual, por ejemplo.

**Una sesión de shell que no es de inicio de sesión** (*non-login shell session*): Normalmente ocurre cuando lanzamos una sesión de terminal en la interfaz gráfica (GUI).

Los shells de inicio de sesión leen uno o más archivos de inicio, como se muestra en la Tabla 11-2.

**Tabla 11-2:** Archivos de Inicio para Sesiones de Shell de Inicio de Sesión

| **Archivo** | **Contenido** |
| --- | --- |
| */etc/profile* | Un script de configuración global que se aplica a todos los usuarios. |
| *~/.bash_profile* | El archivo de inicio personal de un usuario. Puede utilizarse para ampliar o anular la configuración del script de configuración global. |
| *~/.bash_login* | Si no se encuentra *~/.bash_profile*, **bash** intenta leer este script. |
| *~/.profile* | Si no se encuentra ni *~/.bash_profile* ni *~/.bash_login*, **bash** intenta leer este archivo. Este es el valor por defecto en las distribuciones basadas en Debian, como Ubuntu. |

Las sesiones de shell que no son de inicio de sesión leen los archivos de inicio listados en la Tabla 11-3.

**Tabla 11-3:** Archivos de Inicio para Sesiones de Shell que No Son de Inicio de Sesión

| **Archivo** | **Contenido** |
| --- | --- |
| */etc/bash.bashrc* | Un script de configuración global que se aplica a todos los usuarios. |
| *~/.bashrc* | El archivo de inicio personal de un usuario. Puede utilizarse para ampliar o anular la configuración del script de configuración global. |

Además de leer los archivos de inicio listados en la Tabla 11-3, los shells que no son de inicio de sesión heredan el entorno de su proceso padre, normalmente un shell de inicio de sesión.

Echa un vistazo y comprueba cuáles de estos archivos de inicio están instalados. Recuerda que, como la mayoría de los nombres de archivo listados empiezan por un punto (lo que significa que están ocultos), tendrás que utilizar la opción `-a` al usar **ls**.

El archivo *~/.bashrc* es probablemente el archivo de inicio más importante desde el punto de vista del usuario ordinario, porque casi siempre se lee. Los shells que no son de inicio de sesión lo leen por defecto, y la mayoría de los archivos de inicio para los shells de inicio de sesión están escritos de tal manera que también leen el archivo *~/.bashrc*.

#### **_¿Qué hay en un archivo de inicio?_**

Si echamos un vistazo al interior de un *.bash_profile* típico (tomado de un sistema CentOS 6), se ve algo como esto:

```bash
# .bash_profile  
  
# Get the aliases and functions  
if [ -f ~/.bashrc ]; then  
        . ~/.bashrc  
fi  
  
# User specific environment and startup programs  
  
PATH=$PATH:$HOME/bin  
export PATH
```

Las líneas que empiezan por `#` son *comentarios* y no son leídas por el shell. Están ahí para la legibilidad humana. Lo primero interesante ocurre en la cuarta línea, con el siguiente código:

```bash
if [ -f ~/.bashrc ]; then  
        . ~/.bashrc  
fi
```

Este es un *comando compuesto* `if`, que cubriremos completamente cuando lleguemos al scripting del shell en la Parte IV, pero por ahora, aquí hay una traducción:

*Si el archivo "~/.bashrc" existe, entonces lee el archivo "~/.bashrc".*

Podemos ver que este trozo de código es la forma en que un shell de inicio de sesión obtiene el contenido de *.bashrc*. Lo siguiente en nuestro archivo de inicio tiene que ver con la variable **PATH**.

¿Alguna vez te has preguntado cómo sabe el shell dónde encontrar los comandos cuando los introducimos en la línea de comandos? Por ejemplo, cuando introducimos **ls**, el shell no busca en todo el ordenador para encontrar */bin/ls* (el nombre de ruta completo del comando **ls**); más bien, busca en una lista de directorios que están contenidos en la variable **PATH**.

La variable **PATH** suele ser establecida (pero no siempre, dependiendo de la distribución) por el archivo de inicio */etc/profile* con este código:

`PATH=$PATH:$HOME/bin`

**PATH** se modifica para añadir el directorio *$HOME/bin* al final de la lista. Este es un ejemplo de *expansión de parámetros*, que tocamos en el Capítulo 7. Para demostrar cómo funciona, intenta lo siguiente:

```bash
[me@linuxbox ~]$ foo="This is some "  
[me@linuxbox ~]$ echo $foo  
This is some  
[me@linuxbox ~]$ foo=$foo"text."  
[me@linuxbox ~]$ echo $foo  
This is some text.
```

Utilizando esta técnica, podemos añadir texto al final del contenido de una variable.

Al añadir la cadena `$HOME/bin` al final del contenido de la variable **PATH**, el directorio *$HOME/bin* se añade a la lista de directorios buscados cuando se introduce un comando. Esto significa que cuando queramos crear un directorio dentro de nuestro directorio personal para almacenar nuestros propios programas privados, el shell está listo para complacernos. Todo lo que tenemos que hacer es llamarlo *bin*, y ya estamos listos para empezar.

**NOTA**

_Muchas distribuciones proporcionan esta configuración de **PATH** por defecto. Las distribuciones basadas en Debian, como Ubuntu, comprueban la existencia del directorio `~/bin` al iniciar la sesión y lo añaden dinámicamente a la variable **PATH** si se encuentra el directorio._

Por último, tenemos esto:

`export PATH`

El comando **export** le dice al shell que ponga el contenido de **PATH** a disposición de los procesos hijo de este shell.

### **Modificando el Entorno**

Dado que sabemos dónde están los archivos de inicio y qué contienen, podemos modificarlos para personalizar nuestro entorno.

#### **_¿Qué Archivos Deberíamos Modificar?_**

Como regla general, para añadir directorios a tu **PATH** o definir variables de entorno adicionales, coloca esos cambios en *.bash_profile* (o el equivalente, según tu distribución; por ejemplo, Ubuntu utiliza *.profile*). Para todo lo demás, coloca los cambios en *.bashrc*.

**NOTA**

_A menos que seas el administrador del sistema y necesites cambiar los valores por defecto para todos los usuarios del sistema, restringe tus modificaciones a los archivos de tu directorio personal. Ciertamente es posible cambiar los archivos en `/etc` como `profile`, y en muchos casos sería sensato hacerlo, pero por ahora, vamos a ir a lo seguro._

#### **_Editores de Texto_**

Para editar (es decir, modificar) los archivos de inicio del shell, así como la mayoría de los demás archivos de configuración del sistema, utilizamos un programa llamado *editor de texto*. Un editor de texto es un programa que es, en algunos aspectos, como un procesador de textos en el sentido de que nos permite editar las palabras en la pantalla con un cursor móvil. Se diferencia de un procesador de textos en que solo admite texto puro y a menudo contiene características diseñadas para escribir programas. Los editores de texto son la herramienta central utilizada por los desarrolladores de software para escribir código y por los administradores de sistemas para gestionar los archivos de configuración que controlan el sistema.

Existen muchos editores de texto diferentes para Linux; la mayoría de los sistemas tienen varios instalados. ¿Por qué tantos diferentes? Porque a los programadores les gusta escribirlos y porque los programadores los utilizan extensamente, escriben editores para expresar sus propios deseos sobre cómo deberían funcionar.

Los editores de texto se dividen en dos categorías básicas: gráficos y basados en texto. GNOME y KDE incluyen algunos editores gráficos populares. GNOME viene con un editor llamado **gedit**, que suele llamarse "Editor de texto" en el menú de GNOME. KDE suele venir con tres, que son (en orden de complejidad creciente) **kedit**, **kwrite** y **kate**.

Existen muchos editores basados en texto. Los más populares que encontraremos son **nano**, **vi** y **emacs**. El editor **nano** es un editor sencillo y fácil de usar diseñado como sustituto del editor **pico** suministrado con la suite de correo electrónico PINE. El editor **vi** (que en la mayoría de los sistemas Linux ha sido sustituido por un programa llamado **vim**, que es la abreviatura de "vi improved") es el editor tradicional para sistemas tipo Unix. Será el tema del Capítulo 12. El editor **emacs** fue escrito originalmente por Richard Stallman. Es un entorno de programación gigantesco, de propósito general y que lo hace todo. Aunque está disponible, rara vez se instala en la mayoría de los sistemas Linux por defecto.

#### **_Utilizando un Editor de Texto_**

Los editores de texto pueden invocarse desde la línea de comandos escribiendo el nombre del editor seguido del nombre del archivo que quieres editar. Si el archivo no existe todavía, el editor asumirá que queremos crear un nuevo archivo. He aquí un ejemplo utilizando **gedit**:

```bash
[me@linuxbox ~]$ gedit algun_archivo
```

Este comando iniciará el editor de texto **gedit** y cargará el archivo llamado *algun_archivo*, si existe.

Los editores de texto gráficos se explican por sí mismos, por lo que no los cubriremos aquí. En su lugar, nos concentraremos en nuestro primer editor de texto basado en texto, **nano**. Vamos a poner en marcha **nano** y a editar el archivo *.bashrc*. Pero antes de hacerlo, vamos a practicar algo de "informática segura". Siempre que editemos un archivo de configuración importante, siempre es una buena idea crear primero una copia de seguridad del archivo. Esto nos protege en caso de que estropeemos el archivo mientras lo editamos. Para crear una copia de seguridad del archivo *.bashrc*, haz esto:

```bash
[me@linuxbox ~]$ cp .bashrc .bashrc.bak
```

No importa cómo llamemos al archivo de copia de seguridad; simplemente elige un nombre comprensible. Las extensiones *.bak*, *.sav*, *.old* y *.orig* son todas formas populares de indicar un archivo de copia de seguridad. Ah, y recuerda que **cp** sobrescribirá los archivos existentes en silencio.

Ahora que tenemos un archivo de copia de seguridad, iniciaremos el editor.

```bash
[me@linuxbox ~]$ nano .bashrc
```

Una vez **nano** se inicia, obtendremos una pantalla como esta:

```text
  GNU nano 2.0.3           File: .bashrc  
  
# .bashrc  
  
# Source global definitions  
if [ -f /etc/bashrc ]; then  
        . /etc/bashrc  
fi  
  
# User specific aliases and functions  
  
                          [ Read 8 lines ]  
^G Get Help^O WriteOut^R Read Fil^Y Prev Pag^K Cut Text^C Cur Pos  
^X Exit    ^J Justify ^W Where Is^V Next Pag^U UnCut Te^T To Spell
```

**NOTA**

_Si tu sistema no tiene **nano** instalado, puedes utilizar un editor gráfico en su lugar._

La pantalla consta de un encabezado en la parte superior, el texto del archivo que se está editando en el medio y un menú de comandos en la parte inferior. Debido a que **nano** fue diseñado para reemplazar al editor de texto suministrado con un cliente de correo electrónico, es bastante escaso en funciones de edición.

El primer comando que debes aprender en cualquier editor de texto es cómo salir del programa. En el caso de **nano**, presionas **CTRL-X** para salir. Esto se indica en el menú de la parte inferior de la pantalla. La notación `^X` significa **CTRL-X**. Esta es una notación común para los caracteres de control utilizada por muchos programas.

El segundo comando que necesitamos saber es cómo guardar nuestro trabajo. Con **nano** es **CTRL-O**. Con este conocimiento, estamos listos para hacer algo de edición. Utilizando la tecla de flecha abajo y/o la tecla **AV PÁG**, mueve el cursor hasta el final del archivo y luego añade las siguientes líneas al archivo *.bashrc*:

```text
umask 0002  
export HISTCONTROL=ignoredups  
export HISTSIZE=1000  
alias l.='ls -d .* --color=auto'  
alias ll='ls -l --color=auto'
```

**NOTA**

_Es posible que tu distribución ya incluya algunas de estas, pero los duplicados no harán daño a nada._

La Tabla 11-4 detalla el significado de nuestras adiciones.

**Tabla 11-4:** Adiciones a Nuestro *.bashrc*

| **Línea** | **Significado** |
| --- | --- |
| `umask 0002` | Establece la **umask** para resolver el problema de los directorios compartidos que discutimos en el Capítulo 9. |
| `export HISTCONTROL=ignoredups` | Hace que la función de registro del historial del shell ignore un comando si el mismo comando acaba de ser registrado. |
| `export HISTSIZE=1000` | Aumenta el tamaño del historial de comandos del valor por defecto habitual de 500 líneas a 1.000 líneas. |
| `alias l.=’ls -d .* --color=auto’` | Crea un nuevo comando llamado **l.**, que muestra todas las entradas del directorio que empiezan por un punto. |
| `alias ll=’ls -l --color=auto’` | Crea un nuevo comando llamado **ll**, que muestra un listado del directorio en formato largo. |

Como podemos ver, muchas de nuestras adiciones no son intuitivamente obvias, por lo que sería una buena idea añadir algunos comentarios a nuestro archivo *.bashrc* para ayudar a explicar las cosas a los humanos. Utilizando el editor, cambia nuestras adiciones para que se vean así:

```bash
# Cambiar umask para facilitar el intercambio de directorios  
umask 0002  
  
# Ignorar duplicados en el historial de comandos y aumentar  
# el tamaño del historial a 1000 líneas  
export HISTCONTROL=ignoredups  
export HISTSIZE=1000  
  
# Añadir algunos alias útiles  
alias l.='ls -d .* --color=auto'  
alias ll='ls -l --color=auto'
```

¡Ah, mucho mejor! Con nuestros cambios completados, presiona **CTRL-O** para guardar nuestro archivo *.bashrc* modificado y presiona **CTRL-X** para salir de **nano**.

**POR QUÉ LOS COMENTARIOS SON IMPORTANTES**

Siempre que modifiques archivos de configuración, es una buena idea añadir algunos comentarios para documentar tus cambios. Claro que probablemente recordarás lo que cambiaste mañana, pero ¿qué tal dentro de seis meses? Hazte un favor y añade algunos comentarios. Ya que estás en ello, no es mala idea llevar un registro de los cambios que haces.

Los scripts de shell y los archivos de inicio de **bash** utilizan el símbolo `#` para empezar un comentario. Otros archivos de configuración pueden utilizar otros símbolos. La mayoría de los archivos de configuración tendrán comentarios. Utilízalos como guía.

A menudo verás líneas en los archivos de configuración que están *comentadas* para evitar que sean utilizadas por el programa afectado. Esto se hace para dar al lector sugerencias sobre posibles opciones de configuración o ejemplos de sintaxis de configuración correcta. Por ejemplo, el archivo *.bashrc* de Ubuntu 18.04 contiene estas líneas:

```bash
# some more ls aliases  
#alias ll=’ls -l’  
#alias la=’ls -A’  
#alias l=’ls -CF’
```

Las tres últimas líneas son definiciones de alias válidas que han sido comentadas. Si eliminas los símbolos `#` iniciales de estas tres líneas, una técnica llamada *descomentado* (*uncommenting*), activarás los alias. Por el contrario, si añades un símbolo `#` al principio de una línea, puedes desactivar una línea de configuración conservando la información que contiene.

#### **_Activando Nuestros Cambios_**

Los cambios que hemos hecho en nuestro *.bashrc* no entrarán en vigor hasta que cerremos nuestra sesión de terminal e iniciemos una nueva, porque el archivo *.bashrc* solo se lee al principio de una sesión. Sin embargo, podemos obligar a **bash** a volver a leer el archivo *.bashrc* modificado con el siguiente comando:

```bash
[me@linuxbox ~]$ source ~/.bashrc
```

Después de hacer esto, deberíamos poder ver el efecto de nuestros cambios. Prueba uno de los nuevos alias.

```bash
[me@linuxbox ~]$ ll
```
