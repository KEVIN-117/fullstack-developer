Una de las tareas principales de un administrador de sistemas es mantener seguros los datos del sistema. Una de las formas de hacerlo es asegurándose de que se realicen *copias de seguridad* (*backups*) puntuales de los archivos del sistema. Incluso si no eres el administrador de un sistema multiusuario, a menudo es útil hacer copias de archivos o mover grandes colecciones de archivos de un sistema a otro.

En este capítulo, veremos varios programas que se utilizan para gestionar colecciones de archivos. Son los programas de compresión de archivos:

**gzip** - Comprime o expande archivos.

**bzip2** - Un compresor de archivos por bloques.

**zip** - Empaqueta y comprime archivos.

Y los programas de archivado:

**tar** - Utilidad de archivado de cintas.

**cpio** - Copia archivos hacia y desde archivos de archivos.

Y, por último, el programa de sincronización de archivos:

**rsync** - Sincronización remota de archivos y directorios.

### **Compresión de Archivos**

A lo largo de la historia de la informática, siempre ha habido una lucha entre el tamaño de los datos y el coste y la velocidad de los medios de almacenamiento y transmisión. Por ello, se ha dedicado mucha investigación a la *compresión de datos* (*data compression*), el proceso de eliminar la redundancia de los datos para hacerlos más pequeños.

La compresión de datos es un tema de estudio profundo y complejo, pero para nuestros propósitos aquí, podemos decir que hay dos tipos básicos: *con pérdida* (*lossy*) y *sin pérdida* (*lossless*). La compresión con pérdida elimina datos para lograr mayores niveles de compresión, basándose en el hecho de que el ojo o el oído humano no pueden detectar pequeñas diferencias en los datos. Esto se utiliza habitualmente en formatos de medios como JPEG (imágenes), MP3 (audio) y MPEG (vídeo).

La compresión sin pérdida, por otro lado, conserva todos los datos originales. Esto es vital para cosas como programas, bases de datos y archivos de configuración. Los algoritmos de compresión sin pérdida funcionan buscando patrones repetidos de datos y sustituyéndolos por códigos más cortos.

#### **_gzip_**

El programa **gzip** se utiliza para comprimir uno o más archivos. Cuando se ejecuta, sustituye el archivo original por una versión comprimida del mismo. El programa correspondiente **gunzip** se utiliza para restaurar los archivos comprimidos a su forma original. He aquí un ejemplo:

```bash
[me@linuxbox ~]$ ls -l /etc > foo.txt  
[me@linuxbox ~]$ ls -l foo.txt  
-rw-r--r-- 1 me   me   64738 2018-04-12 14:14 foo.txt  
[me@linuxbox ~]$ gzip foo.txt  
[me@linuxbox ~]$ ls -l foo.txt.gz  
-rw-rw-r-- 1 me   me   6508 2018-04-12 14:15 foo.txt.gz  
[me@linuxbox ~]$ gunzip foo.txt.gz
```

En este ejemplo, creamos un archivo de texto llamado *foo.txt* a partir de un listado de directorios. A continuación, ejecutamos **gzip**, que sustituyó el archivo original por una versión comprimida llamada *foo.txt.gz*. En el listado del directorio de *foo.txt.gz*, vemos que el archivo comprimido tiene aproximadamente una décima parte del tamaño del original. Dado que el archivo comprimido es solo una lista de directorios, contiene mucho texto repetido, por lo que la compresión funciona muy bien.

**gzip** tiene muchas opciones. La Tabla 18-1 enumera algunas de ellas.

**Tabla 18-1:** Opciones de **gzip**

| **Opción** | **Descripción** |
| --- | --- |
| `-c` | Escribe la salida en la salida estándar y conserva los archivos originales. También puede utilizarse el operador de redirección para dirigir la salida a un archivo. |
| `-d` | Descomprimir. Esto hace que **gzip** actúe como **gunzip**. |
| `-f` | Fuerza la compresión incluso si ya existe una versión comprimida del archivo. |
| `-h` | Muestra la ayuda de uso. |
| `-l` | Lista estadísticas de compresión para cada archivo comprimido. |
| `-r` | Comprime de forma recursiva los directorios. |
| `-t` | Prueba la integridad de un archivo comprimido. |
| `-v` | Muestra mensajes detallados que indican el porcentaje de compresión realizado. |
| `-`*número* | Establece la cantidad de compresión de 1 (más rápido, menos compresión) a 9 (más lento, más compresión). El valor por defecto es 6. |

Volviendo a nuestro ejemplo:

```bash
[me@linuxbox ~]$ gzip -dv foo.txt.gz  
foo.txt.gz:      90.2% -- replaced with foo.txt
```

Aquí sustituimos el archivo comprimido por la versión original y vimos un mensaje que indicaba el porcentaje de compresión.

También existen versiones de muchos programas ordinarios que pueden leer archivos comprimidos con **gzip**. El programa **zcat**, por ejemplo, es como **cat** pero para archivos comprimidos con **gzip**.

```bash
[me@linuxbox ~]$ gzip foo.txt  
[me@linuxbox ~]$ zcat foo.txt.gz | less
```

De forma similar, existe **zless**, que realiza la misma función que el comando canalizado anterior. También existe **zgrep** para buscar patrones en archivos comprimidos.

#### **_bzip2_**

El programa **bzip2** de Julian Seward es similar a **gzip** pero utiliza un algoritmo de compresión diferente que logra mayores niveles de compresión a costa de una menor velocidad. En la mayoría de los aspectos, funciona de la misma manera que **gzip**. Un archivo comprimido con **bzip2** termina con la extensión *.bz2*.

```bash
[me@linuxbox ~]$ ls -l /etc > foo.txt  
[me@linuxbox ~]$ bzip2 foo.txt  
[me@linuxbox ~]$ ls -l foo.txt.bz2  
-rw-rw-r-- 1 me   me   5304 2018-04-12 15:02 foo.txt.bz2  
[me@linuxbox ~]$ bunzip2 foo.txt.bz2
```

Al igual que con **gzip**, podemos utilizar el programa **bunzip2** para descomprimir archivos, o `bzip2 -d`. **bzip2** también admite la mayoría de las mismas opciones que **gzip**. Los programas **bzcat**, **bzless** y **bzgrep** se proporcionan para trabajar con archivos comprimidos con **bzip2**.

**NOTA**

_A medida que pase el tiempo, es probable que veas nuevos programas de compresión como **xz**, que utiliza el algoritmo de compresión LZMA2 y ofrece niveles de compresión aún mejores. **xz** funciona de la misma manera que **bzip2** y **gzip**._

### **Archivando Archivos**

Una tarea común que se realiza junto con la compresión es el *archivado* (*archiving*). El archivado es el proceso de reunir muchos archivos y empaquetarlos en un único archivo de gran tamaño. Esta tarea se realiza a menudo como parte de las copias de seguridad del sistema y también cuando el software se empaqueta para su distribución.

#### **_tar_**

En el mundo de los sistemas tipo Unix, el programa **tar** es la herramienta clásica para la gestión de archivos de almacenamiento. Sus siglas proceden de *tape archive* (archivador de cintas), lo que revela su origen como herramienta para realizar copias de seguridad en cinta. Aunque todavía se utiliza para ese fin, **tar** es igualmente capaz de trabajar con archivos de disco ordinarios.

Los archivos **tar** pueden constar de muchos archivos e incluso de jerarquías de directorios enteras. **tar** utiliza la siguiente sintaxis:

`tar modo[opciones] archivo...`

donde *modo* es uno de los modos de funcionamiento enumerados en la Tabla 18-2.

**Tabla 18-2:** Modos de Funcionamiento de **tar**

| **Modo** | **Descripción** |
| --- | --- |
| `c` | Crear un archivo a partir de una lista de archivos o directorios. |
| `x` | Extraer archivos de un archivo. |
| `t` | Listar el contenido de un archivo. |
| `r` | Añadir archivos al final de un archivo existente. |
| `u` | Actualizar un archivo. Añadir archivos al final de un archivo existente si son más recientes que la copia en el archivo. |
| `A` | Concatenar archivos. Añadir archivos **tar** al final de otro archivo **tar**. |

La mayoría de los usuarios de Linux utilizan el modo `c` para crear archivos y el modo `x` para extraerlos. **tar** también admite un gran conjunto de opciones, como se describe en la Tabla 18-3.

**Tabla 18-3:** Opciones Comunes de **tar**

| **Opción** | **Descripción** |
| --- | --- |
| `-f archivo` | Utiliza *archivo* como nombre del archivo de archivado. |
| `-v` | Salida detallada. Muestra los nombres de los archivos a medida que se procesan. |
| `-z` | Utiliza **gzip** para comprimir/descomprimir el archivo automáticamente. |
| `-j` | Utiliza **bzip2** para comprimir/descomprimir el archivo automáticamente. |
| `-p` | Conserva los permisos de los archivos originales. |
| `-C directorio` | Cambia al directorio especificado antes de realizar la operación. Esto es útil al extraer archivos en una ubicación diferente de la actual. |

Veamos **tar** en acción. Primero, recrearemos el entorno que usamos en el Capítulo 4:

```bash
[me@linuxbox ~]$ mkdir -p playground/dir-{001..100}  
[me@linuxbox ~]$ touch playground/dir-{001..100}/file-{A..Z}
```

A continuación, crearemos un archivo **tar** de todo el directorio *playground*:

```bash
[me@linuxbox ~]$ tar cf playground.tar playground
```

Este comando crea un archivo llamado *playground.tar* que contiene la jerarquía de directorios completa de *playground*. Podemos ver que el archivo se ha creado:

```bash
[me@linuxbox ~]$ ls -l playground.tar  
-rw-rw-r-- 1 me   me   1233920 2018-04-12 15:45 playground.tar
```

Ahora, listemos el contenido del archivo:

```bash
[me@linuxbox ~]$ tar tf playground.tar | less
```

Para ver un listado más detallado, podemos añadir la opción `v`:

```bash
[me@linuxbox ~]$ tar tvf playground.tar | less
```

Ahora, vamos a extraer el archivo *playground* en una nueva ubicación. Crearemos un nuevo directorio llamado *foo*, cambiaremos a él y extraeremos el archivo:

```bash
[me@linuxbox ~]$ mkdir foo  
[me@linuxbox ~]$ cd foo  
[me@linuxbox foo]$ tar xf ../playground.tar  
[me@linuxbox foo]$ ls  
playground
```

Observa que **tar** extrae los archivos utilizando nombres de ruta relativos a menos que se le indique lo contrario. Esto significa que los archivos se extraerán en el directorio actual. Por esta razón, suele ser una buena idea crear un directorio para la extracción antes de ejecutar el comando **tar**.

Veamos un uso más práctico de **tar**. Supongamos que queremos hacer una copia de seguridad de nuestro directorio personal y de todos sus archivos. Podríamos crear un archivo comprimido llamado *home.tar.gz* con el siguiente comando:

```bash
[me@linuxbox ~]$ tar czf home.tar.gz ~
```

Utilizando la opción `z`, **tar** invoca automáticamente a **gzip** para comprimir el archivo a medida que se crea. Para un sistema con un directorio personal de tamaño medio, el archivo resultante será considerablemente más pequeño que los datos originales. Del mismo modo, podríamos haber utilizado **bzip2** añadiendo la opción `j`:

```bash
[me@linuxbox ~]$ tar cjf home.tar.bz2 ~
```

Por último, miremos un truco genial utilizando **tar**. Recuerda que **tar** puede escribir su salida en *stdout* o leer su entrada desde *stdin*. Podemos aprovechar esto para copiar directorios de un lugar a otro.

```bash
[me@linuxbox ~]$ mkdir foo  
[me@linuxbox ~]$ cd playground  
[me@linuxbox playground]$ tar cf - . | (cd ../foo; tar xf -)
```

En este ejemplo, utilizamos **tar** para crear un archivo de todo el contenido del directorio actual (`.`) y enviarlo a *stdout* (`-`). A continuación, canalizamos la salida a un subshell que cambia al directorio de destino (`../foo`) y ejecuta **tar** para extraer el archivo desde *stdin* (`-`). El resultado es una copia exacta del directorio *playground* en el directorio *foo*. Esta técnica es especialmente útil cuando se copian directorios que contienen enlaces simbólicos, dispositivos y otros archivos especiales que el comando **cp** podría no manejar correctamente.

#### **_zip_**

El programa **zip** es a la vez una herramienta de compresión y de archivado. El formato de archivo utilizado por el programa es muy familiar para los usuarios de Windows, ya que es el formato de compresión estándar en esa plataforma. En Linux, el programa **gzip** es la herramienta de compresión predominante y **tar** es la herramienta de archivado predominante, pero **zip** se utiliza a menudo para intercambiar archivos con sistemas Windows.

En su uso más simple, **zip** se invoca de esta manera:

```bash
[me@linuxbox ~]$ zip -r playground.zip playground
```

A diferencia de **tar**, **zip** requiere la opción `-r` para incluir directorios de forma recursiva. Si no se especifica `-r`, solo se incluirá el directorio *playground* (vacío) en el archivo. El programa correspondiente **unzip** se utiliza para extraer archivos de un archivo zip.

```bash
[me@linuxbox ~]$ unzip playground.zip
```

Una característica interesante de **zip** (frente a **tar**) es que permite añadir o actualizar archivos en un archivo existente de forma muy eficiente. Consulta la página man de **zip** para ver los detalles.

### **Sincronización de Archivos y Directorios**

Mantener una copia exacta de un directorio en otro sistema es una tarea común para los administradores de sistemas. Por ejemplo, un servidor web puede tener una copia local de su contenido que se sincroniza periódicamente con un servidor maestro.

#### **_rsync_**

El programa **rsync** es la herramienta definitiva para la sincronización de archivos y directorios. Su gran ventaja es que utiliza un algoritmo especial que minimiza la cantidad de datos transferidos al copiar solo las partes de los archivos que han cambiado. **rsync** puede utilizarse para copiar archivos localmente o a través de una red utilizando **ssh**.

Para demostrar **rsync**, primero limpiaremos nuestros directorios de prueba:

```bash
[me@linuxbox ~]$ rm -rf foo/*
```

A continuación, sincronizaremos el directorio *playground* con el directorio *foo*:

```bash
[me@linuxbox ~]$ rsync -av playground foo
```

La opción `-a` (*archive*) es una opción combinada que activa la recursividad y conserva casi todos los atributos de los archivos (permisos, propietarios, tiempos, etc.). La opción `-v` activa la salida detallada. Observa que el comando anterior creó un directorio llamado *playground* dentro de *foo*. Si hubiéramos querido sincronizar el *contenido* de *playground* con *foo*, habríamos añadido una barra inclinada final al nombre del directorio de origen:

```bash
[me@linuxbox ~]$ rsync -av playground/ foo
```

Esta sutil diferencia es importante. Sin la barra final, **rsync** copia el directorio en sí; con la barra final, **rsync** copia el contenido del directorio.

**rsync** también tiene una opción muy útil, `--delete`, que elimina los archivos del directorio de destino que ya no existen en el directorio de origen. Esto garantiza que el destino sea una copia exacta del origen.

```bash
[me@linuxbox ~]$ rsync -av --delete playground/ foo
```

**rsync** brilla realmente cuando se utiliza a través de una red. Supongamos que queremos sincronizar nuestro directorio *playground* con un sistema remoto llamado *remote-sys*. Utilizaríamos una sintaxis similar a la de **scp**:

```bash
[me@linuxbox ~]$ rsync -av --delete playground/ remote-sys:backup/playground
```

Al igual que con **ssh** y **scp**, **rsync** utilizará **ssh** por defecto para la transferencia de datos encriptada. **rsync** es una herramienta muy potente con muchísimas opciones. Te recomiendo encarecidamente que leas su página man para conocer todas sus capacidades.

### **Resumiendo**

En este capítulo, hemos cubierto las herramientas básicas para el archivado, la compresión y la sincronización de archivos. Estas herramientas forman la base de cualquier estrategia de copia de seguridad sólida. Tanto si estás realizando copias de seguridad de tus propios archivos personales como si estás gestionando un servidor corporativo, el conocimiento de estos programas te resultará indispensable.
