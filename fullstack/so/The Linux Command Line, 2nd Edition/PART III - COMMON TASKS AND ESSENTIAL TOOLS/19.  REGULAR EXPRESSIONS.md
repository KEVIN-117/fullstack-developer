En los capítulos anteriores, hemos utilizado programas que buscaban patrones de texto, como **grep** y el comando de búsqueda de **vi**. Sin embargo, los patrones que utilizamos eran simples cadenas de texto. En este capítulo, veremos un método mucho más potente para describir patrones de texto, llamado *expresiones regulares* (*regular expressions*).

Como hemos visto al utilizar la línea de comandos, se utilizan patrones para muchas cosas. Vimos los comodines de expansión de nombres de ruta (como `*`) y cómo el shell los expande. Las expresiones regulares son similares a los comodines, pero son mucho más potentes y se utilizan para la búsqueda de texto en lugar de la expansión de nombres de archivos.

Muchos programas de línea de comandos y lenguajes de programación utilizan expresiones regulares. En este capítulo, nos centraremos en el uso de expresiones regulares con **grep**.

### **¿Qué son las Expresiones Regulares?**

Dicho de forma sencilla, una expresión regular es un método para describir patrones en los datos de texto. Pueden utilizarse para buscar patrones específicos (como una dirección de correo electrónico o un número de teléfono) dentro de una gran cantidad de texto. Las expresiones regulares se componen de caracteres ordinarios y caracteres especiales llamados *metacaracteres* (*metacharacters*).

### **grep**

El programa **grep** (*global regular expression print*) es la herramienta fundamental para trabajar con expresiones regulares en la línea de comandos. **grep** busca en los archivos líneas que coincidan con una expresión regular específica y las imprime en la salida estándar.

La sintaxis de **grep** es la siguiente:

`grep [opciones] expresión [archivo...]`

En el Capítulo 6, vimos algunas de las opciones de **grep**. Vamos a repasarlas y a introducir un par de ellas más en la Tabla 19-1.

**Tabla 19-1:** Opciones de **grep**

| **Opción** | **Descripción** |
| --- | --- |
| `-i` | Ignora las mayúsculas y minúsculas. |
| `-v` | Invierte la coincidencia. Imprime las líneas que NO coinciden. |
| `-c` | Imprime el recuento de líneas coincidentes en lugar de las líneas mismas. |
| `-l` | Imprime solo los nombres de los archivos que contienen coincidencias. |
| `-L` | Imprime solo los nombres de los archivos que NO contienen coincidencias. |
| `-n` | Precede cada línea de salida con su número de línea en el archivo. |
| `-h` | Suprime el prefijo del nombre del archivo en la salida (cuando se busca en varios archivos). |

Para nuestros experimentos, utilizaremos una lista de archivos que crearemos a partir de un listado de directorios:

```bash
[me@linuxbox ~]$ ls /usr/bin > dirlist.txt
```

Ahora, busquemos todas las líneas que contengan la cadena "bzip":

```bash
[me@linuxbox ~]$ grep bzip dirlist.txt  
bzip2  
bzip2recover
```

En este ejemplo, la expresión regular es la cadena simple `bzip`.

### **Metacaracteres y Caracteres Ordinarios**

En las expresiones regulares, la mayoría de los caracteres coinciden con ellos mismos. Por ejemplo, la expresión regular "a" coincide con el carácter "a". Sin embargo, hay algunos caracteres que tienen un significado especial y se denominan metacaracteres. Los metacaracteres básicos se enumeran en la Tabla 19-2.

**Tabla 19-2:** Metacaracteres de Expresiones Regulares

| **Metacarácter** | **Descripción** |
| --- | --- |
| `.` | Coincide con cualquier carácter individual. |
| `^` | Coincide con el principio de una línea. |
| `$` | Coincide con el final de una línea. |
| `[ ]` | Coincide con cualquier carácter del conjunto especificado. |
| `[^ ]` | Coincide con cualquier carácter NO incluido en el conjunto especificado. |
| `*` | Coincide con cero o más repeticiones del elemento anterior. |

#### **_El Carácter Punto_**

El carácter punto (`.`) coincide con cualquier carácter individual. Por ejemplo:

```bash
[me@linuxbox ~]$ grep '.zip' dirlist.txt  
bunzip2  
bzip2  
bzip2recover  
gunzip  
gzip
```

Aquí buscamos cualquier línea que contenga la cadena `.zip`, donde el punto puede ser cualquier carácter. Observa que esto incluyó `bunzip2` pero no `zip`, porque `zip` no tiene un carácter antes de la "z".

#### **_Anclajes_**

Los caracteres `^` y `$` se denominan *anclajes*. El signo de intercalación (`^`) indica que la coincidencia debe producirse al principio de la línea, y el signo de dólar (`$`) indica que debe producirse al final de la línea.

```bash
[me@linuxbox ~]$ grep '^zip' dirlist.txt  
zip  
zipcloak  
zipgrep  
zipinfo  
zipnote  
zipsplit
```

```bash
[me@linuxbox ~]$ grep 'zip$' dirlist.txt  
gunzip  
gzip  
unzip  
zip
```

```bash
[me@linuxbox ~]$ grep '^zip$' dirlist.txt  
zip
```

#### **_Expresiones de Corchetes y Clases de Caracteres_**

Los corchetes (`[ ]`) permiten especificar un conjunto de caracteres para que coincidan en una única posición. Por ejemplo, para encontrar líneas que contengan "bzip" o "gzip":

```bash
[me@linuxbox ~]$ grep '[bg]zip' dirlist.txt  
bunzip2  
bzip2  
bzip2recover  
gzip
```

También podemos especificar rangos de caracteres utilizando un guion. Para encontrar líneas que contengan un dígito:

```bash
[me@linuxbox ~]$ grep '[0-9]' dirlist.txt
```

Podemos especificar múltiples rangos, como `[A-Za-z0-9]`.

Si el primer carácter dentro de los corchetes es un signo de intercalación (`^`), el conjunto de caracteres se niega. Esto significa que coincidirá con cualquier carácter que NO esté en el conjunto.

```bash
[me@linuxbox ~]$ grep '[^0-9]' dirlist.txt
```

Este comando encontrará todas las líneas que contengan al menos un carácter que no sea un dígito.

#### **_Clases de Caracteres POSIX_**

Debido a que los rangos de caracteres como `[A-Z]` pueden comportarse de forma diferente dependiendo de la configuración del idioma (*localización*), POSIX define un conjunto de clases de caracteres que son más portátiles. Algunas de ellas se enumeran en la Tabla 19-3.

**Tabla 19-3:** Clases de Caracteres POSIX

| **Clase** | **Descripción** |
| --- | --- |
| `[:alnum:]` | Caracteres alfanuméricos. |
| `[:alpha:]` | Caracteres alfabéticos. |
| `[:digit:]` | Dígitos. |
| `[:lower:]` | Letras minúsculas. |
| `[:upper:]` | Letras mayúsculas. |

Para utilizar una clase de caracteres, se encierra entre corchetes adicionales. Por ejemplo:

```bash
[me@linuxbox ~]$ grep '[[:upper:]]' dirlist.txt
```

### **Expresiones Regulares Básicas frente a Extendidas**

Existen dos estándares principales para las expresiones regulares: las *Expresiones Regulares Básicas* (BRE) y las *Expresiones Regulares Extendidas* (ERE). La mayoría de los programas de Linux (incluido **grep**) utilizan BRE por defecto, pero pueden utilizar ERE si se especifica una opción (en **grep**, es `-E`).

La principal diferencia es que en ERE, algunos metacaracteres adicionales están disponibles sin necesidad de escaparlos con una barra invertida. La Tabla 19-4 enumera los metacaracteres adicionales de ERE.

**Tabla 19-4:** Metacaracteres de Expresiones Regulares Extendidas

| **Metacarácter** | **Descripción** |
| --- | --- |
| `( )` | Agrupación de expresiones. |
| `|` | Alternancia (OR lógico). |
| `?` | Coincide con cero o una instancia del elemento anterior. |
| `+` | Coincide con una o más instancias del elemento anterior. |
| `{ }` | Especifica un número exacto o un rango de repeticiones. |

#### **_Alternancia_**

El metacarácter de alternancia (`|`) permite que la coincidencia se produzca con cualquiera de un conjunto de expresiones.

```bash
[me@linuxbox ~]$ echo "AAA" | grep -E 'AAA|BBB'  
AAA  
[me@linuxbox ~]$ echo "BBB" | grep -E 'AAA|BBB'  
BBB
```

#### **_Cuantificadores_**

Los cuantificadores permiten especificar cuántas veces debe aparecer un elemento.

- `?`: Cero o una vez.
- `*`: Cero o más veces (disponible tanto en BRE como en ERE).
- `+`: Una o más veces.
- `{n}`: Exactamente *n* veces.
- `{n,m}`: Entre *n* y *m* veces.
- `{n,}`: *n* o más veces.

Ejemplos:

```bash
[me@linuxbox ~]$ echo "12345" | grep -E '[0-9]{3}'  
123  
[me@linuxbox ~]$ echo "abbbc" | grep -E 'ab{2,3}c'  
abbbc
```

### **Poniendo las Expresiones Regulares a Trabajar**

Vamos a realizar un ejercicio práctico. Supongamos que queremos validar una lista de números de teléfono en un archivo llamado *phones.txt*. Los números válidos deben tener el formato (nnn) nnn-nnnn o nnn-nnn-nnnn.

Una expresión regular para esto sería (utilizando ERE):

`^\(? [0-9]{3} \)? [ -]? [0-9]{3} [ -] [0-9]{4}$`

Desglose:

- `^`: Inicio de línea.
- `\(?`: Un paréntesis de apertura opcional (escapado porque en BRE el paréntesis tiene significado especial, pero aquí usamos `-E`).
- `[0-9]{3}`: Tres dígitos.
- `\)?`: Un paréntesis de cierre opcional.
- `[ -]?`: Un espacio o un guion opcional.
- `[0-9]{3}`: Tres dígitos.
- `[ -]`: Un espacio o un guion obligatorio.
- `[0-9]{4}`: Cuatro dígitos.
- `$`: Fin de línea.

Podemos probarlo así:

```bash
[me@linuxbox ~]$ grep -E '^\(?[0-9]{3}\)? [ -]?[0-9]{3}[ -][0-9]{4}$' phones.txt
```
