En los capítulos anteriores, vimos cómo manipular los datos a nivel de archivo. En este capítulo, consideraremos los datos a nivel de dispositivo. Sin embargo, como este no es un libro sobre administración de sistemas, no intentaremos cubrir todo este tema en profundidad. Lo que intentaremos hacer es presentar algunos de los conceptos y comandos clave que se utilizan para gestionar los dispositivos de almacenamiento.

Veremos los siguientes comandos:

**mount** - Montar un sistema de archivos.

**umount** - Desmontar un sistema de archivos.

**fsck** - Comprobar y reparar un sistema de archivos.

**fdisk** - Manipular la tabla de particiones del disco.

**mkfs** - Crear un sistema de archivos.

**dd** - Convertir y copiar un archivo.

**genisoimage (mkisofs)** - Crear un archivo de imagen ISO 9660.

**md5sum** - Calcular una suma de comprobación MD5.

### **Montaje y Desmontaje de Dispositivos de Almacenamiento**

Los recientes avances en el escritorio de Linux han hecho que la gestión de los dispositivos de almacenamiento sea extremadamente fácil para los usuarios de escritorio. En su mayor parte, conectamos un dispositivo a nuestro sistema y "simplemente funciona". En los viejos tiempos (digamos, 2004), esto tenía que hacerse manualmente. En los sistemas que no son de escritorio (es decir, los servidores), sigue siendo un procedimiento mayoritariamente manual, ya que los servidores suelen tener necesidades de almacenamiento extremas y requisitos de configuración complejos.

El primer paso en la gestión de un dispositivo de almacenamiento es adjuntar el dispositivo al árbol del sistema de archivos. Este proceso, llamado *montaje* (*mounting*), permite al dispositivo interactuar con el sistema operativo. Como recordamos del Capítulo 2, los sistemas operativos tipo Unix (como Linux) mantienen un único árbol de sistemas de archivos con los dispositivos conectados en varios puntos. Esto contrasta con otros sistemas operativos como Windows que mantienen árboles de sistemas de archivos separados para cada dispositivo (por ejemplo, `C:\`, `D:\`, etc.).

Un archivo llamado */etc/fstab* (abreviatura de "file system table") enumera los dispositivos (normalmente particiones de disco duro) que se van a montar en el momento del arranque. He aquí un ejemplo de archivo */etc/fstab* de un sistema Fedora antiguo:

```text
LABEL=/12         /                       ext4    defaults        1 1  
LABEL=/home       /home                   ext4    defaults        1 2  
LABEL=/boot       /boot                   ext4    defaults        1 2  
tmpfs             /dev/shm                tmpfs   defaults        0 0  
devpts            /dev/pts                devpts  gid=5,mode=620  0 0  
sysfs             /sys                    sysfs   defaults        0 0  
proc              /proc                   proc    defaults        0 0  
LABEL=SWAP-sda3   swap                    swap    defaults        0 0
```

La mayoría de los sistemas de archivos enumerados en este archivo de ejemplo son virtuales y no son aplicables a nuestra discusión. Para nuestros propósitos, los interesantes son los tres primeros:

```text
LABEL=/12         /                       ext4    defaults        1 1  
LABEL=/home       /home                   ext4    defaults        1 2  
LABEL=/boot       /boot                   ext4    defaults        1 2
```

Estas son las particiones del disco duro. Cada línea del archivo consta de seis campos, como se describe en la Tabla 15-1.

**Tabla 15-1:** Campos de */etc/fstab*

| **Campo** | **Contenido** | **Descripción** |
| --- | --- | --- |
| 1 | Dispositivo | Tradicionalmente, este campo contiene el nombre real de un archivo de dispositivo asociado al dispositivo físico, como */dev/sda1* (la primera partición del primer disco duro detectado). Pero con los ordenadores actuales, que tienen muchos dispositivos que se pueden conectar en caliente (como las unidades USB), muchas distribuciones modernas de Linux asocian un dispositivo con una etiqueta de texto en su lugar. Esta etiqueta (que se añade al soporte de almacenamiento cuando se formatea) puede ser una etiqueta de texto simple o un UUID (*Universally Unique Identifier*) generado aleatoriamente. Esta etiqueta es leída por el sistema operativo cuando el dispositivo se conecta al sistema. De este modo, no importa qué archivo de dispositivo se asigne al dispositivo físico real, siempre podrá ser identificado correctamente. |
| 2 | Punto de montaje | El directorio donde el dispositivo se adjunta al árbol del sistema de archivos. |
| 3 | Tipo de sistema de archivos | Linux permite montar muchos tipos de sistemas de archivos. La mayoría de los sistemas de archivos nativos de Linux son *Fourth Extended File System* (ext4), pero se admiten muchos otros, como FAT16 (*msdos*), FAT32 (*vfat*), NTFS (*ntfs*), CD-ROM (*iso9660*), etc. |
| 4 | Opciones | Los sistemas de archivos pueden montarse con varias opciones. Es posible, por ejemplo, montar los sistemas de archivos como de solo lectura o impedir que se ejecute cualquier programa desde ellos (una función de seguridad útil para soportes extraíbles). |
| 5 | Frecuencia | Un único número que especifica si el sistema de archivos debe ser respaldado con el comando **dump** y cuándo. |
| 6 | Orden | Un único número que especifica en qué orden deben ser comprobados los sistemas de archivos con el comando **fsck**. |

El formato del listado es el siguiente: `dispositivo on punto_montaje type tipo_sistema_archivos (opciones)`. Este listado es de un sistema CentOS, que utiliza LVM (*Logical Volume Manager*) para crear su sistema de archivos raíz. Como muchas distribuciones modernas de Linux, este sistema intentará montar automáticamente el CD-ROM tras su inserción. Después de insertar el disco, vemos lo siguiente:

Después de insertar el disco, vemos el mismo listado de antes con una entrada adicional. **ADVERTENCIA**

_En los ejemplos que siguen, es vital que prestes mucha atención a los nombres de los dispositivos reales en uso en tu sistema y **¡no utilices los nombres utilizados en este texto!** Ten en cuenta también que los CDs de audio no son lo mismo que los CD-ROMs. Los CDs de audio no contienen sistemas de archivos y, por lo tanto, no pueden montarse en el sentido habitual._

Ahora que tenemos el nombre del dispositivo de la unidad de CD-ROM, vamos a desmontar el disco y volver a montarlo en otra ubicación del árbol del sistema de archivos. Para ello, nos convertimos en superusuario (utilizando el comando adecuado para nuestro sistema) y desmontamos el disco con el comando **umount** (fíjate en la ortografía).

```bash
[me@linuxbox ~]$ su -  
Password:  
[root@linuxbox ~]# umount /dev/sdc
```

El siguiente paso es crear un nuevo *punto de montaje* para el disco. Un punto de montaje es simplemente un directorio en algún lugar del árbol del sistema de archivos. No tiene nada de especial. Ni siquiera tiene que ser un directorio vacío, aunque si montas un dispositivo en un directorio que no esté vacío, no podrás ver el contenido anterior del directorio hasta que desmontes el dispositivo. Para nuestros propósitos, crearemos un nuevo directorio.

```bash
[root@linuxbox ~]# mkdir /mnt/cdrom
```

Finalmente, montamos el CD-ROM en el nuevo punto de montaje. La opción `-t` se utiliza para especificar el tipo de sistema de archivos.

```bash
[root@linuxbox ~]# mount -t iso9660 /dev/sdc /mnt/cdrom
```

A continuación, podemos examinar el contenido del CD-ROM a través del nuevo punto de montaje.

```bash
[root@linuxbox ~]# cd /mnt/cdrom  
[root@linuxbox cdrom]# ls
```

Observa qué sucede cuando intentamos desmontar el CD-ROM.

```bash
[root@linuxbox cdrom]# umount /dev/sdc  
umount: /mnt/cdrom: device is busy
```

¿Por qué sucede esto? El motivo es que no podemos desmontar un dispositivo si este está siendo utilizado por alguien o por algún proceso. En este caso, cambiamos nuestro directorio de trabajo al punto de montaje del CD-ROM, lo que hace que el dispositivo esté ocupado. Podemos remediar fácilmente el problema cambiando el directorio de trabajo a algo distinto del punto de montaje.

```bash
[root@linuxbox cdrom]# cd  
[root@linuxbox ~]# umount /dev/sdc
```

Ahora el dispositivo se desmonta con éxito.

**POR QUÉ ES IMPORTANTE DESMONTAR**

Si miras la salida del comando **free**, que muestra estadísticas sobre el uso de la memoria, verás una estadística llamada *buffers*. Los sistemas informáticos están diseñados para ir lo más rápido posible. Uno de los impedimentos para la velocidad del sistema son los dispositivos lentos. Las impresoras son un buen ejemplo. Incluso la impresora más rápida es extremadamente lenta según los estándares informáticos. Un ordenador sería muy lento si tuviera que detenerse y esperar a que una impresora terminara de imprimir una página. En los primeros tiempos de los PC (antes de la multitarea), esto era un verdadero problema. Si estabas trabajando con una hoja de cálculo o un documento de texto, el ordenador se detenía y dejaba de estar disponible cada vez que imprimías. El ordenador enviaba los datos a la impresora tan rápido como esta podía aceptarlos, pero era muy lento porque las impresoras no imprimen muy rápido. Este problema se solucionó con la llegada del *búfer de impresora*, un dispositivo que contenía algo de memoria RAM y que se situaba entre el ordenador y la impresora. Con el búfer de impresora instalado, el ordenador enviaba la salida de la impresora al búfer, y ésta se almacenaba rápidamente en la memoria RAM rápida, para que el ordenador pudiera volver al trabajo sin esperas. Mientras tanto, el búfer de la impresora enviaba lentamente los datos a la impresora desde la memoria del búfer a la velocidad que la impresora podía aceptar.

Esta idea de almacenamiento en búfer se utiliza ampliamente en los ordenadores para hacerlos más rápidos. No dejes que la necesidad de leer o escribir ocasionalmente datos en dispositivos lentos impida la velocidad del sistema. Los sistemas operativos almacenan en memoria los datos que se han leído y que se van a escribir en los dispositivos de almacenamiento durante el mayor tiempo posible antes de tener que interactuar realmente con el dispositivo más lento. En un sistema Linux, por ejemplo, notarás que el sistema parece llenar la memoria cuanto más tiempo se utiliza. Esto no significa que Linux esté "usando" toda la memoria; significa que Linux está aprovechando toda la memoria disponible para hacer todo el almacenamiento en búfer que pueda.

Este almacenamiento en búfer permite que la escritura en los dispositivos de almacenamiento se realice muy rápidamente porque la escritura en el dispositivo físico se pospone para un momento futuro. Mientras tanto, los datos destinados al dispositivo se amontonan en la memoria. De vez en cuando, el sistema operativo escribirá estos datos en el dispositivo físico.

Desmontar un dispositivo implica escribir todos los datos restantes en el dispositivo para que pueda ser retirado con seguridad. Si el dispositivo se retira sin desmontarlo primero, existe la posibilidad de que no se hayan transferido todos los datos destinados al dispositivo. En algunos casos, estos datos pueden incluir actualizaciones vitales del directorio, lo que provocará la *corrupción del sistema de archivos*, una de las peores cosas que pueden ocurrir en un ordenador.

#### **_Determinando los Nombres de los Dispositivos_**

A veces es difícil determinar el nombre de un dispositivo. Antiguamente, no era muy difícil. Un dispositivo estaba siempre en el mismo sitio y no cambiaba. A los sistemas tipo Unix les gusta que sea así. Cuando se desarrolló Unix, "cambiar una unidad de disco" implicaba el uso de una carretilla elevadora para retirar de la sala de ordenadores un dispositivo del tamaño de una lavadora. En los últimos años, la configuración típica del hardware de escritorio se ha vuelto bastante dinámica, y Linux ha evolucionado para ser más flexible que sus antepasados.

En los ejemplos de la sección anterior, aprovechamos la capacidad del escritorio moderno de Linux para montar "mágicamente" el dispositivo y determinar el nombre después del hecho. Pero, ¿y si estamos gestionando un servidor o algún otro entorno donde esto no ocurre? ¿Cómo podemos averiguarlo?

En primer lugar, veamos cómo nombra el sistema los dispositivos. Si listamos el contenido del directorio */dev* (donde viven todos los dispositivos), podemos ver que hay muchísimos dispositivos.

```bash
[me@linuxbox ~]$ ls /dev
```

El contenido de este listado revela algunos patrones de denominación de dispositivos. La Tabla 15-2 resume algunos de estos patrones.

**Tabla 15-2:** Nombres de Dispositivos de Almacenamiento en Linux

| **Patrón** | **Dispositivo** |
| --- | --- |
| */dev/fd** | Unidades de disquete. |
| */dev/hd** | Discos IDE (PATA) en sistemas antiguos. Las placas base típicas contienen dos conectores o canales IDE, cada uno con un cable con dos puntos de conexión para las unidades. La primera unidad del cable se llama dispositivo *maestro* (*master*), y la segunda se llama dispositivo *esclavo* (*slave*). Los nombres de los dispositivos están ordenados de tal manera que */dev/hda* se refiere al dispositivo maestro del primer canal, */dev/hdb* es el dispositivo esclavo del primer canal; */dev/hdc* es el dispositivo maestro del segundo canal, y así sucesivamente. Un dígito al final indica el número de partición en el dispositivo. Por ejemplo, */dev/hda1* se refiere a la primera partición del primer disco duro del sistema, mientras que */dev/hda* se refiere a toda la unidad. |
| */dev/lp** | Impresoras. |
| */dev/sd** | Discos SCSI. En los sistemas Linux modernos, el núcleo trata todos los dispositivos de tipo disco (incluidos los discos duros PATA/SATA, las unidades flash y los dispositivos de almacenamiento masivo USB, como los reproductores de música portátiles y las cámaras digitales) como discos SCSI. El resto del sistema de denominación es similar al esquema de denominación */dev/hd** descrito anteriormente. |
| */dev/sr** | Unidades ópticas (lectores y grabadores de CD/DVD). |

Además, a menudo vemos enlaces simbólicos como */dev/cdrom*, */dev/dvd* y */dev/floppy*, que apuntan a los archivos de dispositivo reales, proporcionados para mayor comodidad.

Si estás trabajando en un sistema que no monta automáticamente los dispositivos extraíbles, puedes utilizar la siguiente técnica para determinar cómo se denomina el dispositivo extraíble cuando se conecta. #### **_Manipulación de Particiones con fdisk_**

**fdisk** es uno de los muchos programas disponibles (tanto de línea de comandos como gráficos) que nos permiten interactuar directamente con dispositivos de tipo disco (como discos duros y unidades flash) a un nivel muy bajo. Con esta herramienta podemos editar, borrar y crear particiones en el dispositivo. Para trabajar con nuestra unidad flash, primero debemos desmontarla (si es necesario) y luego invocar el programa **fdisk** de la siguiente manera:

```bash
[me@linuxbox ~]$ sudo umount /dev/sdb1  
[me@linuxbox ~]$ sudo fdisk /dev/sdb
```

Observa que debemos especificar el dispositivo en términos de todo el dispositivo, no por número de partición. Tras el inicio del programa, veremos el siguiente prompt:

`Command (m for help):`

Introducir una `m` mostrará el menú del programa.

```text
Command action  
   a   toggle a bootable flag  
   b   edit bsd disklabel  
   c   toggle the dos compatibility flag  
   d   delete a partition  
   l   list known partition types  
   m   print this menu  
   n   add a new partition  
   o   create a new empty DOS partition table  
   p   print the partition table  
   q   quit without saving changes  
   s   create a new empty Sun disklabel  
   t   change a partition's system id  
   u   change display/entry units  
   v   verify the partition table  
   w   write table to disk and exit  
   x   extra functionality (experts only)  
  
  
Command (m for help):
```

Lo primero que queremos hacer es examinar la distribución de particiones existente. Lo hacemos introduciendo `p` para imprimir la tabla de particiones del dispositivo.

```text
Command (m for help): p  
  
Disk /dev/sdb: 16 MB, 16006656 bytes  
1 heads, 31 sectors/track, 1008 cylinders

   Device Boot      Start         End      Blocks   Id  System

```

En este ejemplo, vemos un dispositivo de 16 MB con una sola partición (1) que utiliza 1.006 de los 1.008 cilindros disponibles en el dispositivo. La partición se identifica como una partición de Windows 95 FAT32. Algunos programas utilizarán este identificador para limitar los tipos de operaciones que se pueden realizar en el disco, pero la mayoría de las veces no es crítico cambiarlo. Sin embargo, para esta demostración, lo cambiaremos para indicar una partición de Linux. Para ello, primero debemos averiguar qué ID se utiliza para identificar una partición Linux. En el listado anterior, vemos que se utiliza el ID `b` para especificar la partición existente. Para ver una lista de los tipos de particiones disponibles, consultamos el menú del programa. Allí podemos ver la siguiente opción:

`   l   list known partition types`

Si introducimos `l` en el prompt, se muestra una gran lista de tipos posibles. Entre ellos vemos `b` para nuestro tipo de partición existente y `83` para Linux.

Volviendo al menú, vemos esta opción para cambiar un ID de partición:

`   t   change a partition's system id`

Introducimos `t` en el prompt e introducimos el nuevo ID.


Esto completa todos los cambios que necesitamos hacer. Hasta este punto, el dispositivo ha permanecido intacto (todos los cambios se han almacenado en la memoria, no en el dispositivo físico), por lo que escribiremos la tabla de particiones modificada en el dispositivo y saldremos. Para ello, introducimos `w` en el prompt.


Si hubiéramos decidido dejar el dispositivo inalterado, podríamos haber introducido `q` en el prompt, lo que habría hecho salir del programa sin escribir los cambios. Podemos ignorar con seguridad el mensaje de advertencia de sonido ominoso.

#### **_Creación de un Nuevo Sistema de Archivos con mkfs_**

Con la edición de las particiones terminada (aunque haya sido ligera), es hora de crear un nuevo sistema de archivos en nuestra unidad flash. Para ello, utilizaremos **mkfs** (abreviatura de "make file system"), que puede crear sistemas de archivos en diversos formatos. Para crear un sistema de archivos ext4 en el dispositivo, utilizamos la opción `-t` para especificar el tipo de sistema "ext4", seguido del nombre del dispositivo que contiene la partición que queremos formatear.

### **Prueba y Reparación de Sistemas de Archivos**

En nuestra discusión anterior sobre el archivo */etc/fstab*, vimos algunos dígitos misteriosos al final de cada línea. Cada vez que el sistema arranca, comprueba rutinariamente la integridad de los sistemas de archivos antes de montarlos. Esto lo hace el programa **fsck** (abreviatura de "file system check"). El último número de cada entrada de fstab especifica el orden en que se deben comprobar los dispositivos. En nuestro ejemplo anterior, vemos que el sistema de archivos raíz se comprueba primero, seguido de los sistemas de archivos *home* y *boot*. Los dispositivos con un cero como último dígito no se comprueban rutinariamente.

Además de comprobar la integridad de los sistemas de archivos, **fsck** también puede reparar sistemas de archivos corruptos con diversos grados de éxito, dependiendo de la magnitud del daño. En los sistemas de archivos tipo Unix, las porciones de archivos recuperadas se colocan en el directorio *lost+found*, situado en la raíz de cada sistema de archivos.

Para comprobar nuestra unidad flash (que debería estar desmontada primero), podríamos hacer lo siguiente:

```bash
[me@linuxbox ~]$ sudo fsck /dev/sdb1  
fsck 1.40.8 (13-Mar-2016)  
e2fsck 1.40.8 (13-Mar-2016)  
/dev/sdb1: clean, 11/3904 files, 1661/15608 blocks
```

Hoy en día, la corrupción del sistema de archivos es bastante rara a menos que haya un problema de hardware, como un fallo en la unidad de disco. En la mayoría de los sistemas, la corrupción del sistema de archivos detectada en el momento del arranque hará que el sistema se detenga y te indique que ejecutes **fsck** antes de continuar.

**¿QUÉ DIANTRES ES FSCK?**

En la cultura Unix, la palabra *fsck* se utiliza a menudo en lugar de una palabra popular con la que comparte tres letras. Esto es especialmente apropiado, dado que probablemente estarás pronunciando la palabra mencionada si te encuentras en una situación en la que te ves obligado a ejecutar **fsck**.

### **Moviendo Datos Directamente hacia y desde los Dispositivos**

Aunque solemos pensar en los datos de nuestros ordenadores como organizados en archivos, también es posible pensar en los datos en forma "bruta". Si miramos una unidad de disco, por ejemplo, vemos que consiste en un gran número de "bloques" de datos que el sistema operativo ve como directorios y archivos. Sin embargo, si pudiéramos tratar una unidad de disco como una simple colección de bloques de datos, podríamos realizar tareas útiles, como la clonación de dispositivos.

El programa **dd** realiza esta tarea. Copia bloques de datos de un lugar a otro. Utiliza una sintaxis única (por razones históricas) y se suele utilizar de esta manera:

`dd if=archivo_entrada of=archivo_salida [bs=tamaño_bloque [count=bloques]]`

**ADVERTENCIA**

_El comando **dd** es muy potente. Aunque su nombre deriva de "data definition" (definición de datos), a veces se le llama "destroy disk" (destruir disco) porque los usuarios suelen escribir mal la especificación de `if` o `of`. **¡Comprueba siempre las especificaciones de entrada y salida antes de pulsar ENTER!**_

Digamos que tenemos dos unidades flash USB del mismo tamaño y que queremos copiar exactamente la primera unidad en la segunda. Si conectamos ambas unidades al ordenador y se asignan a los dispositivos */dev/sdb* y */dev/sdc*, respectivamente, podríamos copiar todo lo de la primera unidad a la segunda con lo siguiente:

`dd if=/dev/sdb of=/dev/sdc`

Alternativamente, si solo el primer dispositivo estuviera conectado al ordenador, podríamos copiar su contenido a un archivo ordinario para su posterior restauración o copia.

`dd if=/dev/sdb of=flash_drive.img`

#### **_Creación de Imágenes de CD-ROM_**

La escritura de un CD-ROM grabable (ya sea un CD-R o un CD-RW) consta de dos pasos:

1. Construir un *archivo de imagen ISO* que sea la imagen exacta del sistema de archivos del CD-ROM.
2. Escribir el archivo de imagen en el soporte CD-ROM.

#### **_Creación de una Copia de Imagen de un CD-ROM_**

Si queremos hacer una imagen ISO de un CD-ROM existente, podemos utilizar **dd** para leer todos los bloques de datos del CD-ROM y copiarlos a un archivo local. Supongamos que tenemos un CD de Ubuntu y queremos hacer un archivo ISO que podamos utilizar más tarde para hacer más copias. Después de insertar el CD y determinar el nombre de su dispositivo (asumiremos */dev/cdrom*), podemos hacer el archivo ISO así:

`dd if=/dev/cdrom of=ubuntu.iso`

Esta técnica funciona también para los DVDs de datos, pero no funcionará para los CDs de audio, ya que no utilizan un sistema de archivos para el almacenamiento. Para los CDs de audio, mira el comando **cdrdao**.

#### **_Creación de una Imagen a partir de una Colección de Archivos_**

Para crear un archivo de imagen ISO que contenga el contenido de un directorio, utilizamos el programa **genisoimage**. Para ello, primero creamos un directorio que contenga todos los archivos que queramos incluir en la imagen y luego ejecutamos el comando **genisoimage** para crear el archivo de imagen. Por ejemplo, si hubiéramos creado un directorio llamado *~/cd-rom-files* y lo hubiéramos llenado de archivos para nuestro CD-ROM, podríamos crear un archivo de imagen llamado *cd-rom.iso* con el siguiente comando:

`genisoimage -o cd-rom.iso -R -J ~/cd-rom-files`

La opción `-R` añade metadatos para las *extensiones Rock Ridge*, que permite el uso de nombres de archivo largos y permisos de archivo al estilo POSIX. Del mismo modo, la opción `-J` activa las *extensiones Joliet*, que permiten nombres de archivo largos para Windows.

**UN PROGRAMA CON CUALQUIER OTRO NOMBRE . . .**

Si buscas tutoriales en línea para crear y grabar soportes ópticos como CD-ROMs y DVDs, te encontrarás frecuentemente con dos programas llamados **mkisofs** y **cdrecord**. Estos programas formaban parte de un popular paquete llamado **cdrtools** de Jörg Schilling. En el verano de 2006, el Sr. Schilling hizo un cambio de licencia en una parte del paquete **cdrtools**, lo que, en opinión de muchos en la comunidad Linux, creó una incompatibilidad de licencia con la GPL de GNU. Como resultado, se inició un *fork* del proyecto **cdrtools** que ahora incluye programas de reemplazo para **cdrecord** y **mkisofs** llamados **wodim** y **genisoimage**, respectivamente.

### **Escritura de Imágenes de CD-ROM**

Una vez que tenemos un archivo de imagen, podemos grabarlo en nuestro soporte óptico. La mayoría de los comandos que discutiremos en las secciones siguientes pueden aplicarse tanto a los soportes CD-ROM como a los DVD grabables.

#### **_Montaje Directo de una Imagen ISO_**

Hay un truco que podemos utilizar para montar una imagen ISO mientras está todavía en nuestro disco duro y tratarla como si ya estuviera en un soporte óptico. Añadiendo la opción `-o loop` a **mount** (junto con el tipo de sistema de archivos `iso9660` requerido), podemos montar el archivo de imagen como si fuera un dispositivo y adjuntarlo al árbol del sistema de archivos.

```bash
mkdir /mnt/iso_image  
mount -t iso9660 -o loop imagen.iso /mnt/iso_image
```

En este ejemplo, creamos un punto de montaje llamado */mnt/iso_image* y luego montamos el archivo de imagen *imagen.iso* en ese punto de montaje. Una vez montada la imagen, ésta puede tratarse exactamente como si fuera un CD-ROM o un DVD real. *Recuerda desmontar la imagen cuando ya no sea necesaria*.

#### **_Borrando un CD-ROM Regrabable_**

Los soportes CD-RW regrabables deben borrarse (*blanked*) antes de poder volver a utilizarse. Para ello, podemos utilizar **wodim**, especificando el nombre del dispositivo para el grabador de CD y el tipo de borrado que se va a realizar. El programa **wodim** ofrece varios tipos. El más mínimo (y rápido) es el tipo "fast".

`wodim dev=/dev/cdrw blank=fast`

#### **_Escribiendo una Imagen_**

Para escribir una imagen, utilizamos de nuevo **wodim**, especificando el nombre del dispositivo grabador de soportes ópticos y el nombre del archivo de imagen.

`wodim dev=/dev/cdrw imagen.iso`

Además del nombre del dispositivo y del archivo de imagen, **wodim** admite un gran conjunto de opciones. Dos de las más comunes son `-v` para la salida detallada, y `-dao`, que escribe el disco en modo *disc-at-once*. Este modo debe utilizarse si estás preparando un disco para su reproducción comercial. El modo por defecto para **wodim** es *track-at-once*, que es útil para grabar pistas de música.

### **Resumiendo**

En este capítulo, hemos visto las tareas básicas de gestión del almacenamiento. Hay, por supuesto, muchas más. Linux admite una amplia gama de dispositivos de almacenamiento y esquemas de sistemas de archivos. También ofrece muchas características para la interoperabilidad con otros sistemas.

### **Crédito Extra**

A menudo es útil verificar la integridad de una imagen ISO que hemos descargado. En la mayoría de los casos, el distribuidor de una imagen ISO suministrará también un *archivo de suma de comprobación* (*checksum*). Una suma de comprobación es el resultado de un cálculo matemático exótico que da como resultado un número que representa el contenido del archivo de destino. Si el contenido del archivo cambia aunque sea un solo bit, la suma de comprobación resultante será muy diferente. El método más común de generación de sumas de comprobación utiliza el programa **md5sum**. Cuando utilizas **md5sum**, éste produce un número hexadecimal único.

```text
md5sum imagen.iso  
34e354760f9bb7fbf85c96f6a3f94ece  imagen.iso
```

Después de descargar una imagen, debes ejecutar **md5sum** contra ella y comparar los resultados con el valor **md5sum** suministrado por el editor.

Además de comprobar la integridad de un archivo descargado, podemos utilizar **md5sum** para verificar soportes ópticos recién grabados. Para ello, calculamos primero la suma de comprobación del archivo de imagen y luego calculamos la suma de comprobación del soporte. El truco para verificar el soporte es limitar el cálculo a la parte del soporte óptico que contiene la imagen. Para ello, determinamos el número de bloques de 2.048 bytes que contiene la imagen (los soportes ópticos siempre se escriben en bloques de 2.048 bytes) y leemos ese número de bloques del soporte. En algunos tipos de soportes, esto no es necesario. Los discos CD-R y CD-RW grabados en modo *disc-at-once* pueden comprobarse de esta manera:

```text
md5sum /dev/cdrom  
34e354760f9bb7fbf85c96f6a3f94ece  /dev/cdrom
```

Muchos tipos de soportes, como los DVD, requieren un cálculo preciso del número de bloques. En el siguiente ejemplo, comprobamos la integridad del archivo de imagen *dvd-image.iso* y del disco en el lector de DVD */dev/dvd*. ¿Eres capaz de averiguar cómo funciona esto?

`md5sum dvd-image.iso; dd if=/dev/dvd bs=2048 count=$(( $(stat -c "%s" dvd-image.iso) / 2048 )) | md5sum`
