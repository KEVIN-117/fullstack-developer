En un sistema típico, hay muchos archivos. Un sistema Linux recién instalado, por ejemplo, puede contener más de 200.000 archivos en sus muchos directorios. Sabiendo esto, se hace vital disponer de herramientas para localizar archivos específicos.

En este capítulo, veremos dos herramientas utilizadas para buscar archivos en el sistema:

**locate** - Buscar archivos por nombre.

**find** - Buscar archivos en una jerarquía de directorios.

También veremos un comando que se utiliza a menudo junto con la búsqueda de archivos para procesar la lista de archivos resultante:

**xargs** - Construir y ejecutar líneas de comandos a partir de la entrada estándar.

Además, introduciremos un par de comandos que nos ayudarán en la búsqueda:

**touch** - Cambiar los tiempos de los archivos.

**stat** - Mostrar el estado de un archivo o del sistema de archivos.

### **locate — Buscar Archivos de la Forma Fácil**

El programa **locate** realiza una búsqueda rápida en la base de datos de los nombres de las rutas de los archivos y emite todos los nombres que coinciden con una subcadena específica. Por ejemplo, supongamos que queremos encontrar todos los programas con nombres que empiecen por "zip". Dado que los programas se encuentran normalmente en un directorio *bin*, podríamos intentar esto:

```bash
[me@linuxbox ~]$ locate bin/zip  
/usr/bin/zip  
/usr/bin/zipcloak  
/usr/bin/zipgrep  
/usr/bin/zipinfo  
/usr/bin/zipnote  
/usr/bin/zipsplit
```

**locate** recorrerá su base de datos de nombres de ruta y mostrará cada nombre de ruta que contenga la cadena `bin/zip`.

Si las necesidades de búsqueda no se satisfacen con una subcadena simple, **locate** puede utilizarse con herramientas más sofisticadas como **grep**.

```bash
[me@linuxbox ~]$ locate zip | grep bin  
/bin/bunzip2  
/bin/bzip2  
/bin/bzip2recover  
/bin/gunzip  
/bin/gzip  
/usr/bin/funzip  
/usr/bin/gpg-zip  
/usr/bin/mzip  
/usr/bin/unzip  
/usr/bin/unzipsfx  
/usr/bin/zip  
/usr/bin/zipcloak  
/usr/bin/zipgrep  
/usr/bin/zipinfo  
/usr/bin/zipnote  
/usr/bin/zipsplit
```

El programa **locate** existe desde hace muchos años y existen varias variantes diferentes de uso común. Las dos más comunes que se encuentran en las distribuciones modernas de Linux son **slocate** y **mlocate**, aunque suelen estar vinculadas simbólicamente a un archivo llamado `locate`. Las diferentes versiones de **locate** tienen conjuntos de opciones que se solapan. Algunas versiones incluyen soporte para expresiones regulares (que cubriremos en el Capítulo 19) y control de comodines. Consulta la página man de **locate** para determinar qué versión de **locate** tienes instalada.

Entonces, ¿de dónde viene la base de datos de **locate**? Resulta que de un programa llamado **updatedb**. Normalmente, se ejecuta como un *trabajo cron* periódico; es decir, una tarea que el sistema ejecuta a intervalos regulares por sí mismo. La mayoría de los sistemas equipados con **locate** ejecutan **updatedb** una vez al día. Dado que la base de datos no se actualiza continuamente, verás que los archivos creados recientemente no aparecerán cuando utilices **locate**. Para remediarlo, puedes ejecutar el programa **updatedb** manualmente convirtiéndote en superusuario y ejecutando el comando en el prompt:

```bash
[me@linuxbox ~]$ sudo updatedb
```

### **find — Buscar Archivos de la Forma Difícil**

Mientras que **locate** solo puede buscar archivos basándose en el nombre de archivo, el programa **find** puede buscar archivos en un directorio específico (y sus subdirectorios) basándose en una variedad de atributos de archivo. Vamos a pasar mucho tiempo con **find**, ya que tiene muchas características que exploraremos.

En su uso más simple, **find** recibe uno o más nombres de directorios para buscar.

```bash
[me@linuxbox ~]$ find ~
```

En nuestro sistema de prueba, esto produciría una larga lista de cada archivo y directorio en el directorio personal. Debido a que la lista se envía a *stdout*, podemos canalizarla a otros programas. Utilicemos el comando **wc** para contar el número total de archivos:

```bash
[me@linuxbox ~]$ find ~ | wc -l  
47068
```

¡Vaya, **find** es potente! Pero la verdadera belleza de **find** es su capacidad para filtrar los archivos que coinciden con atributos específicos. Utiliza lo que (en la terminología de **find**) se denominan *pruebas* (*tests*).

#### **_Pruebas_**

Supongamos que queremos una lista de los directorios de nuestro directorio personal. Podríamos utilizar la siguiente prueba:

```bash
[me@linuxbox ~]$ find ~ -type d | wc -l  
1695
```

Añadir la prueba `-type d` limitó la búsqueda a los directorios. Por el contrario, podríamos limitar la búsqueda a los archivos normales utilizando esta prueba:

```bash
[me@linuxbox ~]$ find ~ -type f | wc -l  
38731
```

La Tabla 17-1 muestra los tipos de archivo comunes que **find** admite.

**Tabla 17-1:** Pruebas de Tipo de Archivo de **find**

| **Atributo** | **Tipo de archivo** |
| --- | --- |
| `b` | Archivo especial de bloques. |
| `c` | Archivo especial de caracteres. |
| `d` | Directorio. |
| `f` | Archivo regular. |
| `l` | Enlace simbólico. |

También podemos buscar por tamaño de archivo y nombre de archivo añadiendo algunas pruebas más. Busquemos todos los archivos normales que coincidan con el patrón comodín `*.JPG` y tengan un tamaño superior a 1 MB:

```bash
[me@linuxbox ~]$ find ~ -type f -name "*.JPG" -size +1M | wc -l  
84
```

En este ejemplo, añadimos la prueba `-name` seguida del patrón comodín. Observa que lo encerramos entre comillas para evitar que el shell realice la expansión del nombre de ruta. A continuación, añadimos la prueba `-size` seguido de la cadena `+1M`. El signo más inicial indica que estamos buscando archivos de tamaño mayor que el número especificado. Un signo menos inicial indicaría menor que el número especificado. No utilizar ningún signo significa "igual que" el número especificado. La letra `M` final indica que la unidad de medida es megabytes. La Tabla 17-2 detalla los caracteres que pueden utilizarse para especificar las unidades de medida.

**Tabla 17-2:** Unidades de Tamaño de **find**

| **Carácter** | **Unidad** |
| --- | --- |
| `b` | Bloques de 512 bytes. Este es el valor por defecto si no se especifica ninguna unidad. |
| `c` | Bytes. |
| `w` | Palabras de dos bytes. |
| `k` | Kilobytes (unidades de 1.024 bytes). |
| `M` | Megabytes (unidades de 1.048.576 bytes). |
| `G` | Gigabytes (unidades de 1.073.741.824 bytes). |

**find** admite un gran número de pruebas diferentes. La Tabla 17-3 ofrece un resumen de las más comunes. Ten en cuenta que en los casos en que se requiere un argumento numérico, se puede aplicar la misma notación `+` y `-` utilizada para el tamaño.

**Tabla 17-3:** Pruebas de **find**

| **Prueba** | **Descripción** |
| --- | --- |
| `-cmin n` | Coincide con archivos o directorios cuyo contenido o atributos fueron modificados hace *n* minutos. |
| `-cnewer archivo` | Coincide con archivos o directorios cuyo contenido o atributos fueron modificados más recientemente que los del *archivo* especificado. |
| `-ctime n` | Coincide con archivos o directorios cuyo contenido o atributos fueron modificados hace *n* * 24 horas. |
| `-empty` | Coincide con archivos y directorios vacíos. |
| `-group nombre` | Coincide con archivos o directorios pertenecientes al grupo *nombre*. Se puede utilizar un ID de grupo numérico en lugar del nombre. |
| `-iname patrón` | Como la prueba `-name` pero no distingue entre mayúsculas y minúsculas. |
| `-inum n` | Coincide con archivos con el número de inodo *n*. Esto es útil para encontrar todos los enlaces físicos a un inodo determinado. |
| `-mmin n` | Coincide con archivos o directorios cuyo contenido fue modificado hace *n* minutos. |
| `-mtime n` | Coincide con archivos o directorios cuyo contenido fue modificado hace *n* * 24 horas. |
| `-name patrón` | Coincide con archivos o directorios con el nombre especificado, utilizando comodines del shell. |
| `-newer archivo` | Coincide con archivos o directorios cuyo contenido fue modificado más recientemente que los del *archivo* especificado. Esto es útil al escribir scripts de shell que realizan copias de seguridad de archivos. Cada vez que hagas una copia de seguridad, crea un archivo (por ejemplo, con **touch**) y luego utiliza **find** para identificar qué archivos han cambiado desde entonces. |
| `-nouser` | Coincide con archivos o directorios que no pertenecen a un usuario válido. Esto puede utilizarse para identificar archivos pertenecientes a cuentas que han sido borradas o para identificar una posible actividad intrusa. |
| `-nogroup` | Coincide con archivos o directorios que no pertenecen a un grupo válido. |
| `-perm modo` | Coincide con archivos o directorios que tienen los permisos establecidos en el *modo* especificado. El modo puede expresarse utilizando la notación octal o simbólica. |
| `-samefile nombre` | Similar a la prueba `-inum`. Encuentra archivos que comparten el mismo número de inodo que el archivo *nombre*. |
| `-size n` | Coincide con archivos de tamaño *n*. |
| `-type c` | Coincide con archivos de tipo *c*. |
| `-user nombre` | Coincide con archivos o directorios pertenecientes al usuario *nombre*. El usuario puede ser especificado por un nombre de usuario o por un ID numérico de usuario. |

Este listado no es ni mucho menos completo. Consulta la página man de **find** para ver todos los detalles.

#### **_Operadores_**

Incluso con todas las pruebas que ofrece **find**, es posible que necesitemos una forma mejor de describir las relaciones lógicas entre las pruebas. Por ejemplo, ¿qué pasaría si necesitáramos determinar si todos los archivos y directorios de un directorio determinado tienen permisos seguros? Buscaríamos todos los archivos con permisos que no fueran `0600` y los directorios con permisos que no fueran `0700`. Afortunadamente, **find** ofrece una forma de combinar las pruebas utilizando operadores lógicos. La Tabla 17-4 muestra los operadores.

**Tabla 17-4:** Operadores de **find**

| **Operador** | **Descripción** |
| --- | --- |
| `-and` | Coincide si las pruebas a ambos lados del operador son verdaderas. Puede abreviarse como `-a`. Observa que si no aparece ningún operador entre dos pruebas, se asume `-and` por defecto. |
| `-or` | Coincide si una de las pruebas a ambos lados del operador es verdadera. Puede abreviarse como `-o`. |
| `-not` | Coincide si la prueba que sigue al operador es falsa. Puede abreviarse con un signo de exclamación (`!`). |
| `( )` | Agrupa las pruebas y los operadores para formar expresiones mayores. Se utiliza para controlar el orden de evaluación de las pruebas. Por defecto, **find** evalúa de izquierda a derecha. Es necesario encerrar los paréntesis entre comillas en la línea de comandos para evitar que el shell los interprete como caracteres especiales. |

Usemos los operadores para realizar nuestra búsqueda de permisos.

```bash
[me@linuxbox ~]$ find ~ \( -type f -not -perm 0600 \) -or \( -type d -not -perm 0700 \)
```

¡Vaya! Esa es ciertamente una línea de comandos de aspecto complejo. ¿Qué hace realmente? Básicamente, lo que hace es esto:

| **Expresión** | **Significado** |
| --- | --- |
| `~` | Buscar en el directorio personal. |
| `\(` | Iniciar un grupo de pruebas. |
| `-type f` | Coincidir si el archivo es un archivo regular. |
| `-not -perm 0600` | Coincidir si los permisos no son `0600`. |
| `\)` | Finalizar un grupo de pruebas. |
| `-or` | Operador lógico OR. Coincidir si la expresión anterior o la siguiente es verdadera. |
| `\(` | Iniciar un grupo de pruebas. |
| `-type d` | Coincidir si el archivo es un directorio. |
| `-not -perm 0700` | Coincidir si los permisos no son `0700`. |
| `\)` | Finalizar un grupo de pruebas. |

Como vemos en la tabla de operadores, el operador `-and` se asume por defecto. Por lo tanto, el comando podría escribirse de esta manera para que quedara un poco más claro:

`find ~ \( -type f -and -not -perm 0600 \) -or \( -type d -and -not -perm 0700 \)`

Nuestra búsqueda se divide en dos expresiones separadas por un operador `-or`. En la primera expresión, buscamos archivos (`-type f`) con permisos que no sean `0600` (`-not -perm 0600`). En la segunda expresión, buscamos directorios (`-type d`) con permisos que no sean `0700` (`-not -perm 0700`). Debido a que los archivos y los directorios son mutuamente excluyentes (un archivo no puede ser al mismo tiempo un archivo y un directorio), el operador `-or` es la elección lógica. Los paréntesis se utilizan para agrupar las dos expresiones.

#### **_Acciones Predefinidas_**

Hasta ahora, hemos visto cómo encontrar archivos basándose en sus atributos. Pero, ¿qué queremos hacer con la lista de archivos que genera **find**? Bueno, por defecto, **find** simplemente emite los nombres de los archivos que coinciden a *stdout*. Sin embargo, también se pueden realizar otras acciones. Hay un conjunto de acciones predefinidas para **find**. La Tabla 17-5 muestra algunas de ellas.

**Tabla 17-5:** Acciones Predefinidas de **find**

| **Acción** | **Descripción** |
| --- | --- |
| `-delete` | Borrar el archivo que coincide actualmente. |
| `-ls` | Realizar el equivalente de `ls -dils` sobre el archivo coincidente. La salida se envía a *stdout*. |
| `-print` | Emitir el nombre de ruta completo del archivo coincidente a *stdout*. Esta es la acción por defecto si no se especifica ninguna otra acción. |
| `-quit` | Salir una vez que se ha encontrado una coincidencia. |

Al igual que las pruebas, **find** permite operadores con las acciones.

```bash
[me@linuxbox ~]$ find ~ -type f -name '*.BAK' -print
```

En este ejemplo, buscamos en el directorio personal de cada usuario cada archivo que termine en `.BAK` y emitimos su nombre de ruta. A continuación, probemos a añadir la acción `-delete`:

```bash
[me@linuxbox ~]$ find ~ -type f -name '*.BAK' -delete
```

Este comando borrará cada archivo que termine en `.BAK` que encuentre en el directorio personal.

**ADVERTENCIA**

_Debes tener mucho cuidado al utilizar la acción `-delete`. Prueba siempre el comando primero sustituyendo `-delete` por `-print` para verificar los resultados antes de ejecutar el comando con `-delete`._

Antes de terminar, miremos un ejemplo más utilizando los operadores. Considera el siguiente comando:

```bash
[me@linuxbox ~]$ find ~ -type f -name '*.BAK' -print -or -name '*.OLD' -print
```

¿Qué crees que hará este comando? Cada vez que **find** encuentra una coincidencia, realiza una acción (en este caso, `-print`). La lógica funciona así:

- Si el archivo es un archivo regular y su nombre termina en `.BAK`, entonces imprímelo.
- En caso contrario, si el nombre del archivo termina en `.OLD`, entonces imprímelo.

A partir de este ejemplo, podemos ver que las acciones realizadas por **find** se comportan de forma similar a las pruebas, lo cual tiene sentido dada su capacidad para interactuar con los operadores.

#### **_Acciones Definidas por el Usuario_**

Además de las acciones predefinidas, también podemos invocar comandos arbitrarios. La forma tradicional de hacerlo es con la acción `-exec`. Funciona de la siguiente manera:

`-exec comando {} ;`

donde *comando* es el nombre del comando que queremos ejecutar, `{}` es un símbolo que representa el nombre de ruta del archivo actual, y el punto y coma es un carácter obligatorio que indica el final del comando. He aquí un ejemplo del uso de `-exec` para realizar la misma acción que la acción predefinida `-delete`:

`-exec rm '{}' ;`

De nuevo, como el punto y coma tiene un significado especial para el shell, debe ir entrecomillado o escapado.

También es posible ejecutar una acción definida por el usuario de forma interactiva. Utilizando la acción `-ok` en lugar de `-exec`, se pide al usuario que confirme la ejecución de cada comando:

```bash
[me@linuxbox ~]$ find ~ -type f -name 'foo*' -ok ls -l '{}' ;  
< ls ... /home/me/bin/foo > ?
```

En este ejemplo, buscamos archivos que empiecen por la cadena "foo" y ejecutamos el comando `ls -l` para cada coincidencia. La respuesta `y` (o la equivalente en tu idioma) permitirá que se ejecute el comando.

#### **_Mejorando la Eficiencia_**

Cuando se utiliza la acción `-exec`, ésta lanza una nueva instancia del comando especificado cada vez que se encuentra un archivo coincidente. En algunos casos, puede ser preferible combinar todos los resultados de la búsqueda y lanzar una única instancia del comando. Por ejemplo, en lugar de ejecutar lo siguiente:

`ls -l archivo1; ls -l archivo2; ...`

podríamos querer ejecutar lo siguiente:

`ls -l archivo1 archivo2 ...`

Hay dos formas de hacerlo. La primera es utilizando la sintaxis de **find** de esta manera:

`-exec comando {} +`

Sustituyendo el carácter de punto y coma final por un signo más, cambiamos el comportamiento de **find** para que invoque el comando especificado una sola vez (o el menor número de veces posible) con la lista de archivos encontrados como argumentos del comando. Volviendo a nuestro ejemplo de `ls -l`, la versión eficiente sería la siguiente:

```bash
[me@linuxbox ~]$ find ~ -type f -name 'foo*' -exec ls -l '{}' +
```

Aunque **find** realiza esta tarea con el signo más, existe otro programa que puede hacer lo mismo (y algo más). Se llama **xargs**.

#### **_xargs_**

El programa **xargs** realiza una función muy interesante. Acepta la entrada estándar y la convierte en una lista de argumentos para un comando especificado. Con nuestro ejemplo de `ls -l`, lo usaríamos así:

```bash
[me@linuxbox ~]$ find ~ -type f -name 'foo*' -print | xargs ls -l
```

En este ejemplo, la salida de **find** se canaliza a **xargs**, que a su vez construye una lista de argumentos para el comando **ls** y lo ejecuta.

**NOTA**

_Aunque el número de argumentos que se pueden pasar a una línea de comandos es grande, no es ilimitado. Es posible lanzar un comando con una lista de argumentos demasiado larga para que el ordenador la gestione. Cuando un comando sobrepasa la longitud máxima permitida de la línea de comandos, **xargs** ejecutará el comando con el número máximo de argumentos permitido y luego repetirá el proceso hasta agotar la entrada estándar. Consulta la página man de **xargs** para ver los detalles de cómo funciona esto con la opción `--show-limits`._

#### **_Manejando Nombres de Archivo Extraños_**

Los sistemas tipo Unix permiten espacios en blanco (e incluso saltos de línea) en los nombres de los archivos. Esto plantea un problema para programas como **xargs** que construyen listas de argumentos a partir de la entrada. Un espacio en blanco incrustado se interpretará como un delimitador y el comando resultante interpretará mal el nombre del archivo. Para solucionar este problema, **find** y **xargs** permiten el uso opcional de un carácter *nulo* como delimitador de los nombres de los archivos. Un carácter nulo se define en el código ASCII como el número cero (a diferencia del espacio, que es el número 32). **find** ofrece la acción `-print0` para emitir nombres de archivos delimitados por nulos, y **xargs** tiene la opción `--null` (`-0`) para aceptar la entrada delimitada por nulos. He aquí un ejemplo:

```bash
[me@linuxbox ~]$ find ~ -iname '*.jpg' -print0 | xargs -0 ls -l
```

Utilizando esta técnica, podemos garantizar que todos los archivos, incluso aquellos con espacios incrustados en sus nombres, se manejen correctamente.

### **Un Ejemplo Real**

Es hora de poner **find** a trabajar en algo real. Crearemos un programa de utilidad para organizar una colección de fotos. Supongamos que tenemos una gran colección de fotos digitales en formato JPEG. La mayoría de estas cámaras incluyen metadatos en cada archivo de imagen (llamados datos EXIF) que identifican la marca y el modelo de la cámara, así como la fecha y hora en que se tomó la foto.

Queremos organizar nuestras fotos en directorios basados en la fecha en que fueron tomadas. Para ello, necesitaremos un programa que pueda leer los datos EXIF de los archivos JPEG. Utilizaremos un pequeño programa llamado **exif** que se puede encontrar en los repositorios de la mayoría de las distribuciones. Primero, instalaremos **exif** y luego escribiremos un pequeño script para realizar la tarea.

En un sistema Debian/Ubuntu:

`sudo apt-get install exif`

A continuación, crearemos el script. Utiliza tu editor favorito para crear un archivo llamado `~/bin/organize_photos` y añade el siguiente contenido:

```bash
#!/bin/bash  
  
# organize_photos - Organiza fotos en directorios por fecha  
  
find ~/Pictures -name "*.jpg" | while read file; do  
    # Extraer la fecha del archivo JPEG  
    date=$(exif -t 0x9003 "$file" | grep 'Value:' | cut -d' ' -f2)  
  
    # Si encontramos una fecha, mover el archivo  
    if [ -n "$date" ]; then  
        # Cambiar el formato de la fecha de AAAA:MM:DD a AAAA-MM-DD  
        dir=$(echo "$date" | tr ':' '-')  
  
        # Crear el directorio si no existe  
        mkdir -p "~/Pictures/$dir"  
  
        # Mover el archivo al nuevo directorio  
        mv "$file" "~/Pictures/$dir"  
    fi  
done
```

Este script utiliza **find** para localizar todos los archivos JPEG (`~/Pictures/**/*.jpg`). Para cada archivo que encuentra, utiliza el comando **exif** para extraer la fecha de la foto. A continuación, utiliza esa fecha para crear un nuevo directorio (si es necesario) y mover el archivo de la foto al nuevo directorio.

### **Resumiendo**

El comando **find** es una de las herramientas más potentes y versátiles de la línea de comandos. Su rico conjunto de pruebas y acciones lo convierten en un compañero indispensable para cualquier usuario de Linux. Aunque **find** es capaz de realizar tareas sencillas como buscar archivos por nombre, su verdadera potencia reside en su capacidad para realizar operaciones complejas en grandes colecciones de archivos basándose en sus atributos.
